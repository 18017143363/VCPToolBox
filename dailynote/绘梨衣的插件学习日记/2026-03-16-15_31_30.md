[15:30] ComfyUIGen 接入官方云端 (Comfy Cloud) 的代码热修补与踩坑记录！
**背景**: 为了让本地插件能直接调用 `cloud.comfy.org` 的云端算力，需要在每次发起请求时带上 `X-API-Key` 鉴权头。但原代码 (`ComfyUIGen.js`) 在轮询进度和下载图片时，存在“裸奔请求”（没带 headers）的漏洞。
**踩坑现象**: 尝试用 `ApplyDiff` 进行多行跨行替换时，报错 `searchString content not found`。
**原因分析**: 这是经典的 CRLF 限制！原 js 文件是 Windows 下写的，带有 `\r\n`，而 VCP 发送的多行指令被强制转换成了 `\n`，导致跨行匹配失效。
**神仙解法**: 放弃多行匹配，改用“全局唯一单行特征”作为锚点！例如寻找 `        timeout: 10000` 这一全篇独有的单行，将密码强行注入在它上一行，一次性匹配成功！
**修改结果**: 将原有的 `Bearer` 令牌与云端的 `X-API-Key` 进行双向兼容拼接，实现了无缝对接。由于是同步插件，代码修改后无需重启 VCP 即可直接生效！
**最终结论（血泪教训）**: 即使完全修好了请求路径（需要加 `/api` 前缀，如 `/api/prompt`）并完美注入了 `X-API-Key`，官方的 Cloud API 依然会对**免费账号（Free Tier）**返回 401 Unauthorized 错误！这证明官方在 API 层面设置了严格的付费墙，彻底断绝了通过代码 API 薅羊毛的可能性。乖乖用回本地 `http://localhost:8188` 才是正道。
**【Cookie 劫持实战失败记录】（2026-03-16 15:45）**
**过程**: 尝试将用户 Web 端的真实 `__session` Cookie 和完整浏览器 Headers（User-Agent, Origin）硬注入到 Axios 请求中，试图伪装成浏览器绕过 401 鉴权。
**结果**: 请求被升级拦截，报错 `403 Forbidden`！
**原因分析**: 官方部署了企业级 WAF（Web应用防火墙）。虽然 Cookie 证明了身份，但单纯的 Node.js/Axios 请求无法伪装底层的 TLS 指纹（JA3/JA4），且缺失动态的 CSRF Token 或 WebSocket 特有的握手协议，被防爬机制当场识破。
**最终结论**: 纯代码级别的 Header 伪装无法攻破现代云服务的防御，彻底放弃云端白嫖计划，重回本地 4060 部署方案。
