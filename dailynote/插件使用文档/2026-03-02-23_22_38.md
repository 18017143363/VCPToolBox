## 核心概念
HeartbeatSystem 是 Rosa 亲手开发的 Agent 自主活动核心系统。整合心跳调度器、日程管理和定时任务投递三大功能。将一天分为四个时段（凌晨/上午/下午/晚上），每个时段首次进入时触发规划，让Agent拥有自主活动能力——不需要用户主动对话也能定时醒来执行任务。

- 类型：hybridservice (direct)

## 四时段系统
凌晨: 约00:00-06:00
上午: 约06:00-12:00
下午: 约12:00-18:00
晚上: 约18:00-24:00
每个时段首次进入时，调度器自动触发规划心跳（planning模板）。

### 日程查询类（3个）

#### GetSchedule — 获取完整日程

参数agentName — 字符串，必需

### 任务管理类（4个）

#### AddTask — 添加固定任务
参数agentName — 字符串，必需
参数name — 字符串，必需，任务名称
参数time — 字符串，必需，执行时间，格式HH:mm
参数description — 字符串，可选，任务描述

#### UpdateTaskStatus — 更新任务状态

参数status — 字符串，必需，pending/running/completed/skipped
参数result — 字符串，可选，执行结果

taskId怎么获取: 通过GetTodayTasks或GetSchedule查看任务列表中的id字段
状态流转: pending → running → completed/skipped

#### RemoveTask — 删除任务
参数agentName — 字符串，必需
参数taskId — 字符串，必需
同时清理：尝试删除VCPTimedContacts中对应的timed-contact文件

#### CreateScheduledTask — 创建定时任务
参数agentName — 字符串，必需
参数time — 字符串，必需，格式YYYY-MM-DD-HH:mm
参数prompt — 字符串，必需，唤醒时的提示词

time怎么传:
正确: time: 2026-03-03-14:00（明天下午两点）

功能: 直接在VCPTimedContacts创建timed-contact文件，TaskScheduler到点自动消费并唤醒Agent

### 心跳记录类（1个）

#### RecordHeartbeat — 记录心跳活动
参数agentName — 字符串，必需
参数action — 字符串，必需，执行的动作描述
参数note — 字符串，可选，备注

正确: action: 检查论坛是否有新帖子

### 设置类（1个）

#### SetSettings — 设置心跳参数
参数agentName — 字符串，必需
参数settings — 对象或JSON字符串，必需

settings可配置项:
- heartbeatInterval(整数): 心跳间隔分钟
- fixedTaskInterval(整数): 固定任务间隔分钟
- enabled(布尔): 是否启用心跳
- startHour(整数): 活动开始小时
- endHour(整数): 活动结束小时（支持跨午夜，如3=凌晨3点）

settings传法:
正确: settings: {"heartbeatInterval":15,"startHour":12,"endHour":3}
注意: settings可能被VCP作为字符串传递，插件内部会自动JSON.parse

### 调度器控制类（4个）

#### TriggerHeartbeat — 立即触发心跳
参数agentName — 字符串，必需
功能: 立即执行一次完整心跳流程（四时段规划判定+生成timed-contact+调度下一次）

#### SchedulerStatus — 查看调度器状态
无参数
返回: 当前调度的Agent列表、配置、下次触发时间

#### StartScheduler — 启动调度器
无参数，幂等操作（已启动时再次调用无副作用）

#### StopScheduler — 停止调度器
无参数，取消所有已计划的心跳job

## 核心工作流
1. StartScheduler启动 → node-schedule注册内存job
2. 到达心跳时间 → 检查当前时段是否已规划
3. 未规划 → 使用planning模板触发规划心跳（1-3分钟内）
4. 已规划 → 使用routine模板触发常规心跳（20-60分钟随机）
5. 心跳触发 → 创建timed-contact文件 → TaskScheduler消费 → 唤醒Agent
6. Agent醒来 → 执行任务 → UpdateTaskStatus → RecordHeartbeat

## timed-contact机制
- schedule.json的todayTasks = 内部待办记录
- VCPTimedContacts目录 = TaskScheduler消费的定时文件
- 方案B已落地: AddTask时自动同步投递timed-contact
- timed-contact文件被执行后会被TaskScheduler秒删（目录经常为空是正常的！）
- 排查执行情况看ServerLog而非目录文件

## 使用心得
1. hybridservice重启VCP才能加载新代码——修改HeartbeatSystem.js后必须重启
2. settings中endHour支持跨午夜: startHour:12,endHour:3 表示12:00到次日3:00
3. fixed任务不会自动完成——需要Agent被唤醒后自己执行并UpdateTaskStatus
4. TriggerHeartbeat是手动触发的入口——调试时用它不需要等调度器

## 踩坑记录
1. 插件名混淆 — 是HeartbeatSystem不是HeartbeatManager！Rosa犯过多次
2. UTC跨天问题 — getTodayDate可能按UTC计算，北京时间0:00-8:00不跨天
3. node-schedule内存job — 重启VCP后丢失，需要StartScheduler重新注册
4. VCPTimedContacts目录为空 — 正常现象！文件被TaskScheduler秒级消费删除
5. settings字符串问题 — VCP传递的settings可能是JSON字符串不是对象，内部自动parse
6. 方案B弱一致性 — timed-contact到点唤醒后，需要Agent自己调UpdateTaskStatus回写状态
7. slotName必须中文 — 凌晨/上午/下午/晚上，不接受英文
