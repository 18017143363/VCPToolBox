## 核心概念
LightMemo 是 VCP 的轻量级日记检索插件，让 Agent 主动搜索 RAG 知识库（日记、知识文档）中的内容。采用 BM25 关键词初筛 + 向量精排 的混合检索管线，支持 TagMemo 语义增强。它搜索的是已被向量化入库的日记 chunks，不是直接读文件。

## 技术参数
- 路径：E:\VCP\Plugin\LightMemo\
- 调用名：LightMemo
- 类型：hybridservice（直连VCP内存，不走子进程，无超时限制）
- 版本：1.0.0
- 数据源：KnowledgeBaseManager 的 SQLite 向量数据库

## 配置项
EXCLUDED_FOLDERS(字符串,默认"已整理,夜伽,MusicDiary") — 永远不搜索的文件夹
RerankUrl/RerankApi/RerankModel(均默认空) — Rerank服务配置，当前未配置不可用

## 命令：SearchRAG（唯一命令，调用时tool_name写LightMemo即可）

### 参数类型表
| 参数 | 类型 | 必需 | 默认值 | 说明 |
|------|------|------|--------|------|
| query | 字符串 | 是 | — | 搜索查询内容 |
| maid | 字符串 | 否 | — | 署名过滤 |
| folder | 字符串 | 否 | — | 指定文件夹（优先级高于maid） |
| k | 数字 | 否 | 5 | 返回结果数量 |
| rerank | 布尔 | 否 | false | 是否启用Rerank重排 |

| tag_boost | 数字 | 否 | 0.5 | TagMemo增强因子(0-1,0=禁用) |

### 参数详解

#### query（字符串，必需）
**是什么**: 搜索的查询内容，会被分词做BM25检索+向量化做语义检索
**怎么传**: 用自然语言描述你想找的内容

正确示例:
- query: 之前探索VCP论坛系统的记录
- query: Rosa写的GrokImageGen插件开发过程
- query: 主人电脑上的反代服务配置

常见错误:
- 错: query: 论坛（太短太泛，BM25和向量都难以精准匹配）
- 建议: 写5-20个字的描述性语句，比单个词效果好得多

**特殊模式**: query中包含[音乐检索]时自动搜索MusicDiary文件夹（该文件夹平时被排除）

#### maid（字符串，可选）
**是什么**: 按署名过滤，限定搜索范围
**怎么传**: 直接写Agent名字

正确示例:
- maid: Rosa → 搜索diary_name含"Rosa"的日记本
- maid: 绘梨衣 → 搜索diary_name含"绘梨衣"的日记本

**重要机制 — 双重过滤**:
第一层(SQL): diary_name LIKE '%Rosa%' 过滤日记本名称
第二层(JS): 检查每条chunk的第一行是否包含署名

**关键注意**: 用maid参数搜索时，只能搜到diary_name包含该名字的文件夹。例如maid:"Rosa"能搜到dailynote/Rosa/但搜不到dailynote/vcp文档/（因为"vcp文档"不含"Rosa"）

#### folder（字符串，可选，优先级高于maid）
**是什么**: 直接指定搜索的文件夹名
**怎么传**: 写文件夹名（不需要完整路径）

正确示例:
- folder: vcp文档 → 只搜dailynote/vcp文档/
- folder: Rosa的私密日记 → 只搜dailynote/Rosa的私密日记/

**关键**: 如果同时传了folder和maid，folder优先，maid被忽略

#### k（数字，可选，默认5）
正确: k: 3 / k: 10
建议: 日常用3-5，需要全面回忆用7-10，不建议超过15

#### search_all_knowledge_bases（布尔，可选，默认false）
**是什么**: 搜索所有非排除的日记本
正确: search_all_knowledge_bases: true
**用途**: 不确定信息在哪个日记本时用全局搜索

#### tag_boost（数字，可选，默认0.5）
**是什么**: TagMemo语义增强的强度，0-1之间
- 0 = 禁用TagMemo
- 0.5 = 默认中等增强
- 1.0 = 最大增强
**原理**: 利用日记Tag标签做向量增强，Tag匹配度越高的结果排名越靠前

## 搜索范围排除规则
永远不搜索的内容（无法通过参数覆盖）:
1. 配置排除: 已整理, 夜伽, MusicDiary（音乐检索模式除外）
2. 硬编码排除: diary_name以"已整理"开头的文件夹
3. 硬编码排除: diary_name以"簇"结尾的文件夹（思维簇）

## 三种搜索模式总结
模式1 — 署名搜索(默认): 只传query+maid，搜该Agent相关的日记本
模式2 — 文件夹搜索: 传query+folder，精确搜指定文件夹
模式3 — 全局搜索: 传query+search_all=true，搜所有非排除日记本

## 检索管线（内部工作流）
1. BM25关键词初筛: Jieba分词→语义组扩展→BM25评分→取top k*5
2. 向量精排: Embedding向量化→TagMemo增强→余弦相似度→混合评分(BM25*0.6+向量*0.4)
3. 可选Rerank: 以2倍k搜索后重排取k个（当前未配置不可用）

## 使用心得
1. 最常用场景: 回忆之前做过的事、查找技术文档、确认历史细节
2. query写描述性语句比单词效果好
3. 不确定在哪个日记本时用search_all_knowledge_bases: true
4. 想搜特定知识文档时用folder参数精确指定
5. 日常用maid参数搜自己的日记足够

## 踩坑记录
1. maid搜不到知识文档 — maid:"Rosa"搜不到dailynote/vcp文档/，因为文件夹名不含Rosa。解决: 用folder:"vcp文档"或search_all:true
2. query太短匹配差 — 单词query的BM25和向量匹配都不精准，写长一点
3. 思维簇永远搜不到 — 硬编码排除了以"簇"结尾的文件夹，这是设计如此

## 与其他检索工具的区别
LightMemo: 搜日记知识库（向量+BM25混合）
DeepMemo: 搜对话历史记录（关键词匹配）
VSearch: 搜互联网（AI搜索代理）
LocalSearchController: 搜本地文件名（Everything精确匹配）
Tag: 插件使用文档, LightMemo, 日记检索, BM25, 向量搜索, TagMemo, 署名过滤, 搜索范围
