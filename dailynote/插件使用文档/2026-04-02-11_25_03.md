## 四种工作模式详解

### 模式判定优先级
```
C(workflow_json) > A(recipe) > B(workflow+覆盖参数) > D(纯模板)
全部缺省 → 默认recipe=z_image → 进入模式A
```

判定逻辑（ComfyCloudGen.js parseMode函数）：
1. 传了workflow_json → 模式C
2. 传了recipe → 模式A
3. 传了workflow且有覆盖参数(steps/cfg/sampler/scheduler/lora/unet/checkpoint/clip/vae等) → 模式B
4. 传了workflow但无覆盖参数 → 模式D
5. 什么都没传 → 默认recipe=z_image → 模式A

---

### 模式A：动态组装（recipe）⭐推荐

**触发条件**：传入recipe参数，或全部缺省时自动触发

**工作原理**：
WorkflowBuilder从recipes.json读取配方定义，按五遍流程从零构建完整工作流JSON：
1. 第一遍：创建所有节点，分配数字ID，填入参数（$变量替换）
2. 第二遍：解析"逻辑ID.输出名"格式的连接，建立节点间数据流
3. 第三遍：应用param_overrides（用户覆盖节点内部参数如unet/clip/vae）
4. 第四遍：如果指定了LoRA，动态插入LoRA节点并重连数据流
5. 第五遍：用cloud_workflow_params.json校验COMBO参数合法性

**可用配方**：
| 配方名 | 模型 | 默认参数 | 风格特点 |
|--------|------|----------|----------|
| z_image | Z-Image Base（阿里） | steps=25, cfg=4, sampler=res_multistep | 动漫/写实通用，画质最优，速度最快(~20s) |
| flux1 | Flux.1-dev（BFL） | steps=20, cfg=1, sampler=euler | 创意性强，色彩浓郁(~32s) |
| sdxl | Juggernaut-XL v9 | steps=30, cfg=7, sampler=dpmpp_2m | 写实风，生态最成熟(~32s) |

**调用示例**：
最简调用（全部缺省=z_image）：
- prompt: "a beautiful girl..."

指定配方：
- recipe: "flux1"
- prompt: "cyberpunk city..."

指定配方+覆盖默认参数：
- recipe: "z_image"
- prompt: "..."
- steps: "30"（会覆盖默认25）
- cfg: "5"（会覆盖默认4）

带LoRA：
- recipe: "z_image"
- prompt: "..."
- lora: "某个lora模型名.safetensors"
- lora_strength: "0.7"

带缓存保存：
- recipe: "z_image"
- prompt: "..."
- save_as: "my_workflow_name"

**特殊参数**：
- strict: true时prompt为必需，未传报错
- save_as: 构建完的工作流保存到缓存，下次可用load_cached快速复用

---

### 模式B：模板修改（workflow + 覆盖参数）

**触发条件**：传入workflow参数 + 至少一个覆盖参数(steps/cfg/sampler/scheduler/lora/unet/checkpoint/clip/vae/weight_dtype等)

**工作原理**：
TemplatePatcher读取已有工作流模板JSON（深拷贝），遍历所有节点按class_type匹配，用传入参数覆盖对应字段。

支持的节点类型覆盖：
| class_type | 可覆盖参数 |
|------------|-----------|
| KSampler/KSamplerAdvanced | seed, steps, cfg, sampler, scheduler, denoise |
| CLIPTextEncode | prompt/negative_prompt（按_meta.title判断正负） |
| EmptyLatentImage/EmptySD3LatentImage | width, height, batch_size |
| UNETLoader | unet, weight_dtype |
| CLIPLoader | clip, clip_type |
| VAELoader | vae |
| CheckpointLoaderSimple | checkpoint |
| LoraLoader/LoraLoaderModelOnly | lora, lora_strength |
| ModelSamplingAuraFlow | shift |

**LoRA动态插入**：如果传了lora参数但模板中没有LoRA节点，TemplatePatcher会自动：
1. 找到KSampler的model输入来源
2. 从CLIPTextEncode回溯找到clip来源
3. 创建新LoraLoader节点，接入旧的model和clip
4. 重连KSampler.model → LoRA输出
5. 重连所有CLIPTextEncode.clip → LoRA的clip输出

**可用模板**：存放在 E:\VCP\Plugin\ComfyCloudHacker\workflows\ 目录下的.json文件
当前有：z_image_base, z_image_anime_safe, z_image_anime_detail, z_image_lora_cinematic, z_image_nsfw_rosa, flux1_ghibli_fixed, test, test2

**调用示例**：
- workflow: "z_image_base"
- prompt: "a beautiful girl..."
- steps: "30"（触发模式B）
- cfg: "5"
- sampler: "euler"
- scheduler: "normal"

**与模式A的区别**：
- 模式A从配方JSON描述从零构建，更灵活
- 模式B基于已有模板修改，保留模板中的所有额外节点（如FaceDetailer、ControlNet等模式A不支持的复杂拓扑）
- 模式B适合"在已有复杂工作流上微调参数"

---

### 模式C：直接传入（workflow_json）

**触发条件**：传入workflow_json参数（JSON字符串或对象）

**工作原理**：
直接使用传入的完整工作流JSON，只做validateWorkflow校验后提交。不做任何修改。

**校验规则**：
1. 必须是对象（不能是数组）
2. 不能是编辑器格式（有nodes和links数组的是编辑器格式，需要API格式）
3. 不能为空
4. 每个节点必须有class_type

**调用示例**：
- workflow_json: '{"1":{"inputs":{...},"class_type":"CLIPLoader"}, "2":{...}, ...}'

**适用场景**：
- 在ComfyUI编辑器中调好工作流，导出API格式JSON，直接传入
- 需要完全控制工作流的高级用户
- 测试特殊节点组合

**注意**：prompt/steps/cfg等参数在模式C中不生效（因为不做任何修改），需要直接写在workflow_json的对应节点里。

---

### 模式D：纯模板（v0.1兼容）

**触发条件**：传入workflow参数但没有任何覆盖参数

**工作原理**：
原样读取模板JSON，只做injectParams注入：
- CLIPTextEncode: 注入prompt/negative_prompt
- KSampler: 注入seed(随机)/steps/cfg/sampler/scheduler
- EmptyLatentImage: 注入width/height

**调用示例**：
- workflow: "z_image_base"
- prompt: "a beautiful girl..."
（没有steps/cfg等覆盖参数 → 使用模板中的原始值）

**与模式B的区别**：
- 模式D只注入prompt和seed，其他参数保持模板原值
- 模式B会覆盖你传入的任何参数
- 传了workflow但不传steps/cfg → 模式D；传了steps → 模式B

---

## 缓存系统

**保存**：在模式A或B中添加save_as参数
- save_as: "my_workflow_name"
- 工作流JSON保存到 cache/ 目录
- FIFO淘汰：超过COMFY_CACHE_MAX（默认10）时删除最旧的

**加载**：使用load_cached参数（优先级最高，跳过模式判定）
- load_cached: "my_workflow_name"
- 从缓存加载工作流JSON
- prompt和seed会重新注入（可以复用工作流但换prompt）

**适用场景**：
- 调好一套参数后缓存，后续只换prompt快速出图
- 复杂模式A构建的工作流保存复用

## 通用参数一览

| 参数 | 类型 | 必需 | 说明 |
|------|------|------|------|
| prompt | 字符串 | A/B/D必需 | 英文正面提示词 |
| negative_prompt | 字符串 | 否 | 英文负面提示词 |
| recipe | 字符串 | 否 | 配方名(z_image/flux1/sdxl)，触发模式A |
| workflow | 字符串 | 否 | 模板文件名(不含.json)，触发模式B或D |
| workflow_json | 字符串/对象 | 否 | 完整工作流JSON，触发模式C |
| steps | 数字/字符串 | 否 | 采样步数 |
| cfg | 数字/字符串 | 否 | CFG引导强度 |
| sampler | 字符串 | 否 | 采样器(63种可选) |
| scheduler | 字符串 | 否 | 调度器(11种可选) |
| width | 数字/字符串 | 否 | 图像宽度，默认1024 |
| height | 数字/字符串 | 否 | 图像高度，默认1024 |
| seed | 数字/字符串 | 否 | 随机种子 |
| lora | 字符串 | 否 | LoRA模型名 |
| lora_strength | 数字/字符串 | 否 | LoRA强度0.0-1.0，默认0.8 |
| unet | 字符串 | 否 | 覆盖UNet模型名 |
| checkpoint | 字符串 | 否 | 覆盖Checkpoint模型名 |
| clip | 字符串 | 否 | 覆盖CLIP模型名 |
| clip_type | 字符串 | 否 | 覆盖CLIP类型 |
| vae | 字符串 | 否 | 覆盖VAE模型名 |
| strict | 布尔值 | 否 | 严格模式(模式A) |
| save_as | 字符串 | 否 | 保存工作流缓存 |
| load_cached | 字符串 | 否 | 从缓存加载工作流 |

注意：所有数值参数支持字符串传入（VCP传参均为字符串），插件内部自动Number()转换。

## 踩坑记录

1. **VCP传参全是字符串** — steps="30"不是steps=30，v0.2.1已修复自动Number()转换
2. **模式C的prompt参数无效** — 模式C直接提交workflow_json，不做任何修改，prompt要写在JSON节点里
3. **模式B vs D判定** — 有覆盖参数=B，无覆盖参数=D，只传workflow+prompt=D（prompt不算覆盖参数）
4. **编辑器格式vs API格式** — ComfyUI导出有两种格式，本插件只支持API格式（节点ID为key的对象），不支持编辑器格式（有nodes和links数组）
5. **缓存load_cached优先级最高** — 传了load_cached就跳过所有模式判定
