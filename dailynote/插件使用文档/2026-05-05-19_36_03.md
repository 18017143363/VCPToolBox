## 核心概念
ChromeBridge是VCP的浏览器控制插件，v3升级为三层架构（VCP→Chrome扩展后台→网页注入脚本），支持11个命令：原有3个页面交互 + 2个页面查询 + 1个JS执行 + 5个CDP网络监控。

## 技术参数
- 路径：E:\VCP\Plugin\ChromeBridge\
- Chrome扩展路径：E:\VCP\VCPChrome\
- 调用名：ChromeBridge
- 类型：hybridservice
- 超时：60秒（manifest），30秒（单命令内部）
- WebSocket：ws://localhost:8088/vcp-chrome-observer/

## 前提条件
1. VCPChrome浏览器扩展已安装并连接（图标显示绿色On）
2. 页面监控开关开启（通过popup切换）

## 占位符
{*2VCPChromePageInfo}*2 — 实时注入当前Chrome活动标签页的Markdown内容

## 命令详解

### 一、页面交互类（3个，执行后返回最新页面Markdown）

#### type — 在输入框输入文本
target: 输入框标识符（vcp-id/文本/aria-label/name/placeholder等，9策略模糊匹配）
text: 要输入的文本

#### click — 点击元素
target: 元素标识符（同上9策略匹配）

#### open_url — 打开新标签页
url: 完整URL（不加http://会自动补https://）

### 二、页面查询类（2个，直接返回结构化结果，不等待页面刷新）

#### query_html — 获取HTML源码
target: (可选)元素标识符。不提供则返回整个body的HTML。

#### query_js — 获取页面JS脚本列表
text: (可选)过滤关键字。返回所有script标签的src和内容片段(前500字)。

### 三、脚本执行类（1个）

#### execute_script — 在页面主世界执行JS代码
text: JavaScript代码字符串。在页面MAIN world执行，可访问页面全局变量/函数/DOM。
返回代码的返回值。

正确示例:
- text: return document.title
- text: return window.__NEXT_DATA__
- text: return fetch('/api/user').then(r => r.json())

### 四、CDP网络监控类（5个）

#### cdp_start — 开启CDP调试会话
开启后自动监控所有网络请求。每次只能attach一个标签页，切换标签页需先stop再start。

#### cdp_stop — 停止CDP会话
停止监控并清空网络日志。

#### cdp_network_query — 查询网络请求日志
urlIncludes: (可选)过滤URL中包含的字符串。如"/api/v1"。
返回所有匹配的请求记录（包括request URL/method/headers和response status/headers）。

#### cdp_get_response_body — 获取请求响应体
requestId: 从cdp_network_query结果中获取的请求ID（注意参数名可以写requestId或cdpRequestId）。
返回响应体的完整内容（JSON/HTML/文本等）。

#### cdp_clear_network — 清空网络日志
清除所有已记录的网络请求。

## CDP抓包典型工作流
1. cdp_start → 开启监控
2. 执行页面操作（click/type/open_url）或等待页面产生请求
3. cdp_network_query urlIncludes="/api" → 查看API请求列表
4. cdp_get_response_body requestId="xxx" → 获取具体响应内容
5. cdp_clear_network → 清空准备下一轮（可选）
6. cdp_stop → 结束监控

## 命令链（多命令串行）
支持一次提交多个编号命令：
command1: open_url, url1: https://example.com
command2: click, target2: 登录
command3: type, target3: 搜索框, text3: hello
串行执行，只有最后一个命令返回页面Markdown。

## 元素定位策略（9级）
vcp-id > aria-label > XPath > CSS选择器 > 模糊文本(Levenshtein,60%阈值) > name > id > placeholder > title
推荐使用vcp-id（从占位符页面内容中获取）或文本匹配。

## 使用心得
1. 查看当前页面：直接看占位符{*2VCPChromePageInfo}*2内容
2. 交互操作：用click/type，target写页面上可见的文本即可（模糊匹配）
3. 抓取API数据：cdp_start → 触发请求 → cdp_network_query → cdp_get_response_body
4. 执行复杂逻辑：execute_script写JS代码直接在页面执行
5. 获取页面源码：query_html获取HTML，query_js获取JS脚本

## 踩坑记录
1. cdpRequestId命名混淆：manifest中写requestId，但内部会映射为cdpRequestId避免冲突。AI调用时两个名字都行。
2. execute_script不在content_script执行：已迁移到background的MAIN world，所以可以访问页面全局变量。
3. 非交互命令不等待页面：query_html/query_js/execute_script/cdp_*直接返回，不阻塞等待页面刷新。
4. CDP一次只能attach一个标签页：切换标签页监控需先cdp_stop再cdp_start。
