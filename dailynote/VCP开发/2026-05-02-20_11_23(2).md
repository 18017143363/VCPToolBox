## 一、为什么选Runtime Hook而非mitmproxy

| 痛点 | mitmproxy方案 | Runtime Hook方案 |
|------|--------------|-----------------|
| 环境搭建 | 证书安装+代理链TUN冲突+30min配置 | CDP一行命令+粘贴hook.js |
| 首屏丢失 | 需要完美时序 | Page.addScriptToEvaluateOnNewDocument |
| Clerk JWT | 只能看加密后Cookie | 明文看到JWT payload生成/刷新/发送 |
| 前端状态 | 完全不可见 | Proxy拦截window state |
| 调用栈 | 无 | 精确到文件:行:列 |

## 三、Hook脚本设计（dedalus_hook.js）

### 需要的Preset组合
```javascript
// 1. fetch — 核心！拦截所有Dashboard API调用
// 2. xhr — 兜底（万一有legacy XHR调用）
// 3. cookie — 监控__session JWT生命周期
// 4. crypto-subtle — 检测是否有请求签名
```

### 精简版fetch hook（Console可粘贴）
```javascript
(function() {
    const bucket = window.__dedalusHooks = { fetch: [], xhr: [], cookie: [] };
    const origFetch = window.fetch;
    window.fetch = async function(...args) {
        const req = args[0] instanceof Request ? args[0] : new Request(...args);
        const entry = {
            url: req.url,
            method: req.method,
            headers: Object.fromEntries(req.headers.entries()),
            body: req.body ? await req.clone().text().catch(()=>'') : null,
            timestamp: Date.now(),
            stack: new Error().stack
        };
        try {
            const resp = await origFetch.apply(this, args);
            const clone = resp.clone();
            entry.status = resp.status;
            entry.response = await clone.text().catch(()=>'[binary]');
            bucket.fetch.push(entry);
            return resp;
        } catch(e) {
            entry.error = e.message;
            bucket.fetch.push(entry);
            throw e;
        }
    };
    console.log('[Dedalus Hook] fetch interceptor active');
})();
```
