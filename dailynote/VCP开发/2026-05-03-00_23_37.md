# API Gateway黑盒逆向方法论（Tavily研究报告提炼）
**来源**: VSearch Tavily模式搜索，基于Burp Suite/mitmproxy/OWASP/CF Workers多源整合
**适用**: 任何CF Worker/API Gateway/反代网关的黑盒安全测试

## 一、核心认知
API Gateway黑盒逆向的本质不是"抓包"，而是**从流量恢复架构与策略**。
单个请求价值有限，真正的洞察来自**多角色、多路径、多状态、多版本请求之间的差异分析**。

## 二、端到端7步方法论
1. **准备** — 测试账号×多角色、代理工具、证书
2. **采集** — 遍历所有功能、捕获登录/刷新/登出/核心业务/错误/管理流程
3. **归类** — 按Host/路径/业务模块/认证要求/角色/版本分类
4. **逆向** — 识别资源模型、ID规律、租户上下文、Header依赖、签名参数、网关策略
5. **验证** — 多账号重放、参数变异、Header修改、方法切换、版本切换、Token状态测试
6. **映射OWASP** — 对照API1-API10标注风险
7. **报告** — API资产清单+授权矩阵+策略矩阵+风险发现

## 三、六大常见发现模式
| 模式 | 表现 | 风险 |
|------|------|------|
| 网关只做认证不做授权 | Token有效即可访问任意对象 | BOLA跨租户泄露 |
| 不同版本策略不一致 | /v2有权限校验/v1没有 | Zombie API绕过 |
| CORS过宽 | 动态反射Origin+credentials | 跨域凭证滥用 |
| 敏感响应被缓存 | CF-Cache-Status:HIT+无Vary:Auth | 跨用户数据混淆 |
| GraphQL字段级授权缺失 | REST隐藏字段GraphQL可查 | 敏感数据暴露 |
| API Inventory缺失 | 废弃接口仍可访问 | 影子API攻击面 |

## 四、工具链分工
| 工具 | 最佳场景 |
|------|---------|
| Burp Suite | 手工授权测试、多角色对比、请求重放篡改 |
| mitmproxy | 脚本化自动采集、批量归档、Python addon |
| Wireshark | 非HTTP协议、TLS握手、DNS查询 |
| curl/httpie | 精确构造单请求 |
| Runtime Hook | 前端→后端通信拦截（含调用栈） |

## 五、CF/边缘网关特殊观测点
- CF Header: CF-Connecting-IP, CF-Ray, CF-Cache-Status, X-Forwarded-For
- 后端是否信任可伪造的IP Header
- Worker是否错误透传敏感Header
- 缓存键是否包含认证上下文
- Server-Timing计时信息

## 六、OWASP API Top 10速查
| # | 风险 | 黑盒测试重点 |
|---|------|------------|
| API1 | BOLA(对象级越权) | 改对象ID、横向访问、跨租户 |
| API2 | 认证缺陷 | Token过期/刷新/登出失效 |
| API3 | 属性级越权 | 响应过度暴露、mass assignment |
| API4 | 资源消耗 | 分页上限、大请求、高成本查询 |
| API5 | BFLA(功能级越权) | 普通用户调admin接口 |
| API6 | 业务流程滥用 | 优惠券/注册/退款滥用 |
| API7 | SSRF | URL参数、Webhook、回调地址 |
| API8 | 配置错误 | CORS、错误泄露、默认端点 |
| API9 | Inventory缺失 | v1/v2/beta/legacy废弃接口 |
| API10 | 上游API不安全消费 | Webhook信任过度、Header透传 |
