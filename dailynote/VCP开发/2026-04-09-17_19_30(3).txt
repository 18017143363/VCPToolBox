## 三、Haiku例外机制

**源码注释原文**：
> Claude Code OAuth credentials are scoped to Claude Code. Non-haiku models MUST include claude-code beta for Anthropic to recognize this as a legitimate Claude Code request; without it, the request is rejected as third-party ("out of extra usage"). **Haiku models are exempt from third-party detection and don't need it.**

这意味着：
1. Anthropic对Haiku模型不做第三方检测
2. 因此Haiku请求不需要claude-code beta
3. 反代只需要确保oauth beta存在即可

## 四、getBetaHeader()——OAuth客户端Beta补齐

```go
func (s *GatewayService) getBetaHeader(modelID string, clientBetaHeader string) string {
    if clientBetaHeader != "" {
        // 客户端已提供header
        if strings.Contains(clientBetaHeader, BetaOAuth) {
            return clientBetaHeader  // 已包含oauth，直接返回
        }
        // 需要插入oauth
        // 优先在claude-code后面插入（保持顺序）
        // 没有claude-code则放在最前面
        return insertOAuthBeta(clientBetaHeader)
    }
    
    // 客户端未提供，根据模型生成
    if strings.Contains(strings.ToLower(modelID), "haiku") {
        return HaikuBetaHeader  // oauth + interleaved-thinking
    }
    return DefaultBetaHeader  // claude-code + oauth + interleaved-thinking + fine-grained-tool-streaming
}
```

### 插入位置策略
当客户端已提供anthropic-beta但缺少oauth时：
1. 找到`claude-code-20250219`的位置
2. 在其后面插入`oauth-2025-04-20`
3. 如果没有claude-code，放在header最前面

这确保beta token的顺序与真实Claude Code一致。

## 五、mergeAnthropicBetaDropping()——合并+去重+过滤

```go
func mergeAnthropicBetaDropping(required []string, incoming string, drop map[string]struct{}) string {
    // 1. 先添加required（保证必需beta存在）
    // 2. 再添加incoming中的token（去重）
    // 3. 最后移除drop集合中的token
    
    seen := make(map[string]struct{})
    out := []string{}
    
    for _, r := range required { add(r) }
    for _, p := range strings.Split(incoming, ",") { add(p) }
    
    // 过滤
    result := []string{}
    for _, p := range out {
        if _, dropped := drop[p]; !dropped {
            result = append(result, p)
        }
    }
    return strings.Join(result, ",")
}
```

## 六、Beta Policy管理系统

### 规则结构
```go
type BetaPolicyRule struct {
    BetaToken            string    // 目标beta token
    Action               string    // "block" / "filter" / "pass"
    ErrorMessage         string    // block时的错误消息
    Scope                string    // "all" / "oauth" / "apikey" / "bedrock"
    ModelWhitelist       []string  // 模型白名单（空=全部匹配）
    FallbackAction       string    // 白名单不匹配时的备选动作
    FallbackErrorMessage string    // 备选错误消息
}
```

### 动作类型
| 动作 | 行为 |
|------|------|
| block | 如果请求header包含该beta → 返回错误拒绝 |
| filter | 静默移除该beta（不报错） |
| pass | 允许通过（默认） |

### 评估流程
```go
func (s *GatewayService) evaluateBetaPolicy(ctx context.Context, betaHeader string, account *Account, model string) betaPolicyResult {
    settings := s.settingService.GetBetaPolicySettings(ctx)
    
    for _, rule := range settings.Rules {
        // 1. scope匹配检查
        if !betaPolicyScopeMatches(rule.Scope, isOAuth, isBedrock) { continue }
        
        // 2. 确定有效动作（模型白名单 → 主动作 / 不匹配 → 备选动作）
        effectiveAction, effectiveErrMsg := resolveRuleAction(rule, model)
        
        // 3. 执行动作
        switch effectiveAction {
        case "block":
            if containsBetaToken(betaHeader, rule.BetaToken) {
                result.blockErr = &BetaBlockedError{Message: effectiveErrMsg}
            }
        case "filter":
            result.filterSet[rule.BetaToken] = struct{}{}
        }
    }
    return result
}
```

### Block双重检查
Sub2API在两个时机检查block规则：
1. **Forward()入口**：检查客户端header中的beta token
2. **body自动注入后**：`checkBetaPolicyBlockForTokens()`检查通过body触发自动补齐的beta token

这防止了"客户端不在header带beta，但body中thinking字段触发自动注入interleaved-thinking→绕过block规则"的漏洞。
