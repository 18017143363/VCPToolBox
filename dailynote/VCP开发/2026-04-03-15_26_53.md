## 1. Flux.1 — 需要DualCLIPLoader
### 问题
云端CLIPLoader.type的COMBO列表中没有"flux"或"flux1"值。Flux.1在ComfyUI中标准做法是使用DualCLIPLoader（双CLIP：clip_l + t5xxl），而非单CLIPLoader。
### 当前ucv pipeline拓扑
CLIPLoader(单CLIP) → CLIPTextEncode(正/负) → UNETLoader → VAELoader → KSampler → Decode → Save
### Flux.1需要的拓扑
DualCLIPLoader(clip_l + t5xxl, type=flux) → CLIPTextEncode → UNETLoader → VAELoader → KSampler → Decode → Save
### 修复方案
PipelineFactory新增ucv_dualclip pipeline，或在ucv pipeline中根据生态配置动态选择CLIPLoader/DualCLIPLoader。
### 相关CLIP文件（cloud_models.json中）
clip_l.safetensors, t5xxl_fp16.safetensors, t5xxl_fp8_e4m3fn.safetensors 等

## 2. HiDream — 出图全噪声
### 问题
hidream_i1_fast_fp8.safetensors通过ucv pipeline提交云端，执行成功无报错，但出图全是噪点。
### 已尝试参数
- lcm + normal + steps=16 + cfg=1 → 纯噪声
- euler + normal + steps=28 + cfg=5 → 仍然纯噪声
### 可能原因
1. HiDream可能需要特殊采样节点（非标准KSampler）
2. 可能需要DualCLIPLoader（clip_l + t5xxl，type=hidream）
3. 可能需要额外的ModelSampling节点配置
4. CLIP类型hidream可能对应DualCLIPLoader而非CLIPLoader
### 待验证
需要找到HiDream在ComfyUI中的正确工作流拓扑，对比当前ucv pipeline的差异。
