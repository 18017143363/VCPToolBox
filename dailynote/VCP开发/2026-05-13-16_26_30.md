[16:25] Dedalus代理 Chat→Responses 多模态格式转换规范
## 核心问题
当BYPASS路径将`/v1/chat/completions`请求转换为`/v1/responses`时，多模态content的type字段必须同步转换，否则上游静默忽略导致空回复。
## 格式映射表
| Chat Completions | Responses API | 说明 |
|---|---|---|
| `{"type": "text", "text": "..."}` | `{"type": "input_text", "text": "..."}` | 文本块 |
| `{"type": "image_url", "image_url": {"url": "...", "detail": "..."}}` | `{"type": "input_image", "image_url": "...", "detail": "..."}` | 图片块，注意url从嵌套对象提升为直接字符串 |
| 纯字符串content | 纯字符串content | 无需转换 |
## 转换函数位置
`dedalus_proxy.py` 中的 `convert_content_for_responses()` 和 `convert_messages_for_responses()`
## 注意事项
1. `image_url`字段在Chat格式中是对象`{"url": "...", "detail": "..."}`，在Responses格式中是直接字符串
2. `detail`字段（low/high/auto）如果存在需要保留
3. 已经是Responses格式的type（`input_text`/`input_image`）直接透传不重复转换
4. 非标准type原样保留，不丢弃
## 信源
- OpenAI官方文档: https://platform.openai.com/docs/api-reference/responses
- 社区踩坑帖确认：传`type: "image_url"`给Responses API会返回`Invalid value`
- Dedalus上游更极端：不报错直接静默忽略
