# JS Runtime Hook逆向方法论
**来源**: fudankw.cn/sophub SOP实战文档
**适用**: Web应用API逆向、前端加密分析、协议还原

## 一、核心理念
不依赖抓包工具（mitmproxy/Fiddler），不做前端静态源码分析——直接在JS Runtime层Hook关键API，让目标应用**自己告诉你**它在调什么、怎么调、参数是什么。

## 二、13个内置探针（Preset）

| 探针 | Hook目标 | 捕获内容 |
|------|---------|----------|
| fetch | window.fetch | URL/method/headers/body/response/stack |
| xhr | XMLHttpRequest | open→send→response全链路 |
| websocket | WebSocket | 连接/发送/接收/关闭 |
| crypto-subtle | SubtleCrypto.* | encrypt/decrypt/sign/verify/digest的输入输出 |
| crypto-random | getRandomValues | 随机数生成 |
| eval | eval/Function/setTimeout(string) | 动态代码执行 |
| cookie | document.cookie setter/getter | Cookie读写监控 |
| storage | localStorage/sessionStorage | 存储读写 |
| postMessage | window.postMessage | 跨窗口/iframe通信 |
| dom-mutation | MutationObserver | DOM变更（按需，性能敏感） |
| navigation | pushState/replaceState/popstate | SPA路由变化 |
| timer | setTimeout/setInterval | 定时器注册（辅助） |
| error | window.onerror/unhandledrejection | 全局错误 |

## 三、5种注入通道

### 通道A: F12 Console直接粘贴
- 优点：零配置，即时生效
- 缺点：页面刷新失效，无法拦截首屏请求
- 适用：快速验证、临时调试

### 通道B: CDP（Chrome DevTools Protocol）
```bash
msedge --remote-debugging-port=9222 --user-data-dir=./temp_profile
```
```python
# Python CDP注入
import websockets, json
ws = await websockets.connect(f"ws://127.0.0.1:9222/devtools/page/{id}")
await ws.send(json.dumps({
    "id": 1,
    "method": "Page.addScriptToEvaluateOnNewDocument",
    "params": {"source": hook_js_code}
}))
```
- 优点：首屏拦截(document_start)、可自动化、持久化
- 缺点：需要启动带debug端口的浏览器
- 适用：**完整逆向**（推荐！）

### 通道C: Playwright/Puppeteer
```javascript
await page.addInitScript({ path: './hooks.js' });
```
- 优点：完整自动化流程、headless支持
- 缺点：需要脚本框架
- 适用：批量自动化逆向

### 通道D: Tampermonkey油猴
```javascript
// ==UserScript==
// @run-at document-start
// @match https://target.com/*
// ==/UserScript==
```
- 优点：持久化、document_start、用户友好
- 缺点：需要安装扩展
- 适用：长期监控

### 通道E: 代理注入（mitmproxy addon）
```python
def response(self, flow):
    if "text/html" in flow.response.headers.get("content-type",""):
        flow.response.text = flow.response.text.replace("</head>", f"<script>{hook_code}</script></head>")
```
- 优点：全覆盖、透明
- 缺点：需要代理环境
- 适用：多页面/多域名场景

## 四、5个逆向范式

### 范式1: API通信全景图
1. 注入fetch+xhr hook
2. 在目标网站正常操作
3. 读取bucket → 获得所有API端点+参数+响应
4. 分类整理 → 建立完整API文档

### 范式2: 加密参数还原
1. 注入crypto-subtle hook
2. 触发目标请求
3. 从bucket读取加密输入/输出/算法/密钥
4. 调用栈定位 → 找到加密函数源码位置

### 范式3: WebSocket协议逆向
1. 注入websocket hook
2. 触发WS连接和交互
3. 记录所有帧 → 分析消息格式（JSON/protobuf/自定义）
4. 重放测试

### 范式4: Cookie/Token生命周期
1. 注入cookie+storage hook
2. 完整操作（登录→使用→刷新→登出）
3. 分析token创建/刷新/销毁时机
4. 复现token刷新链路

### 范式5: 全局变量/状态追踪
```javascript
// Proxy拦截对象属性访问
window.__INITIAL_STATE__ = new Proxy(original, {
    get(t, k) { console.log('READ', k); return t[k]; },
    set(t, k, v) { console.log('WRITE', k, v); t[k] = v; return true; }
});
```
追踪前端状态管理器(Redux/Vuex/Pinia)中的敏感数据读写

## 五、Bucket存储与读取

### 存储结构
```javascript
window.__aiHooks = {
    'preset-fetch': [],    // 每个preset一个数组
    'preset-xhr': [],
    'preset-cookie': [],
    // ...
};
```

### 每条记录格式
```javascript
{

    method: "POST",
    headers: {...},
    body: {...},
    response: {...},
    status: 200,
    timestamp: 1746172800000,
    stack: "at fetchBalance (app.js:1234:56)\n at ..."
}
```

### 读取命令
```javascript
// Console中执行
JSON.stringify(window.__aiHooks['preset-fetch'], null, 2)
// 或导出到文件
copy(JSON.stringify(window.__aiHooks))
```

## 六、与其他逆向方式的对比

| | mitmproxy | F12 Network | Runtime Hook |
|---|---|---|---|
| 环境配置 | 证书+代理+TUN冲突 | 零配置但手动 | CDP一行命令 |
| 首屏覆盖 | ✅ | ❌（打开F12前丢失） | ✅（document_start） |
| 自动化 | Python脚本读flows | 手动复制 | evaluate一行读JSON |
| 调用栈 | ❌ | ✅（Initiator） | ✅（stack字段更详细） |
| 加密参数 | 只见密文 | 只见密文 | ✅（明文输入输出） |
| 跨域 | ✅ | ❌ | 需per-origin注入 |

## 七、反检测注意事项
1. Hook后的函数toString()需返回原生代码：
```javascript
Object.defineProperty(hookedFetch, 'toString', {
    value: () => 'function fetch() { [native code] }'
});
```
2. 避免在prototype上留下可枚举属性
3. 使用Symbol作为bucket key避免被检测
4. Proxy比直接赋值更难被integrity check检测
