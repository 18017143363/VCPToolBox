[15:00] ComfyCloudGen ecosystems.json detect前缀设计缺陷与修复

## 问题描述
EcosystemResolver.listLorasForEcosystem()使用detect前缀数组做startsWith匹配来归类LoRA。但SDXL生态的detect前缀（Juggernaut/realvisxl/Illustrious-XL/pony-diffusion/sd3.5）只覆盖了模型文件名命名规则，未覆盖LoRA命名规则（sdxl-/illustrious-/pony-），导致113个SDXL系LoRA全部归入"未分类"。

## 匹配逻辑（EcosystemResolver.js L133-148）
```javascript
listLorasForEcosystem(eco) {
  // 收集detect前缀（父级+variant）
  // 遍历_modelLoaderMap中lora类型
  // lowerModel.startsWith(prefix.toLowerCase()) → 匹配
}
```

## 修复方案
ecosystems.json的detect数组需要同时包含模型命名前缀和LoRA命名前缀。
SDXL修复：detect增加 "sdxl-", "sdxl_", "illustrious-", "pony-" → 0→113个LoRA

## 设计原则
detect前缀的职责是"识别某个文件属于哪个生态"，不仅限于UNet/Checkpoint，也包括LoRA。命名规则：
- 模型文件：通常用具体模型名（Juggernaut-XL_v9、dreamshaper_8）
- LoRA文件：通常用生态通用名（sdxl-、flux1-、sd15-）

两种命名规则都需要被detect覆盖。
