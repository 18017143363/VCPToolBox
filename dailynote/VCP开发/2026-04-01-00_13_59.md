## 背景
Comfy Cloud使用Firebase Authentication，ID Token(JWT)仅1小时有效，不适合插件长期使用。
## Firebase认证三层体系
| 令牌 | 有效期 | 存储位置 | 用途 |
|------|--------|---------|------|
| ID Token (JWT) | ~1小时 | 内存/请求头 | API调用的Bearer Token |
| refresh_token | 长期有效（直到撤销） | IndexedDB firebaseLocalStorage | 换取新JWT |
| Session Cookie | ~2小时 | Cookie | /api/auth/session返回 |
## refresh_token自动刷新机制
### API端点
```
POST https://securetoken.googleapis.com/v1/token?key={FIREBASE_API_KEY}
Content-Type: application/x-www-form-urlencoded
Body: grant_type=refresh_token&refresh_token={REFRESH_TOKEN}
```
### 响应
```json
{
  "id_token": "新JWT",
  "refresh_token": "可能更新的refresh_token",
  "expires_in": "3600",
  "user_id": "xxx",
  "project_id": "dreamboothy"
}
```
### 注意事项
- Content-Type必须是application/x-www-form-urlencoded，不是application/json
- 返回的refresh_token可能会更新，需要保存新值
- Firebase项目ID: dreamboothy
## refresh_token失效条件
- 用户被删除/禁用
- 密码/邮箱等重大账户变更
- 管理员主动调用revokeRefreshTokens
- 项目不匹配/API Key不匹配
正常使用下基本永不过期。
## 获取方式
1. refresh_token: F12 → Application → IndexedDB → firebaseLocalStorage → refreshToken字段
2. Firebase API Key: F12 → Network → 搜securetoken.googleapis.com → URL的key=参数；或搜页面源码中的apiKey
## 插件实现方案
config.env存两个值：COMFY_REFRESH_TOKEN、COMFY_FIREBASE_API_KEY
插件内部ComfyCloudAuth类：
- getValidToken()：检查JWT过期时间（提前60秒刷新），过期则自动调securetoken API
- 刷新后更新内存中的idToken和expiresAt
- 如果返回了新的refresh_token，需要回写config.env（或内存缓存）
## 常见错误码
| 错误 | 原因 |
|------|------|
| INVALID_REFRESH_TOKEN | token拼错/已被撤销/不属于当前项目 |
| PROJECT_NUMBER_MISMATCH | refresh_token和API Key不匹配 |
| INVALID_GRANT_TYPE | grant_type不是refresh_token |
| MISSING_REFRESH_TOKEN | body未正确传递 |
| TOKEN_EXPIRED | 凭证整体失效，需重新登录 |

## 关键发现：Firebase v11存储位置
Firebase v11.6.0模块化版本的认证信息**不在IndexedDB**！
存储在localStorage，key格式：`firebase:authUser:{API_KEY}:[DEFAULT]`
值结构：{uid, email, stsTokenManager: {refreshToken, accessToken, expirationTime}, apiKey, ...}
IndexedDB的firebaseLocalStorage表是空的（v11新行为）。
