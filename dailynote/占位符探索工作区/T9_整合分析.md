## ⚠️ 风险矩阵

### 无角色限制的占位符（高风险）

| 占位符 | 模块 | 风险场景 | 缓解措施 |
|--------|------|----------|----------|
| Agent占位符 | messageProcessor | 日记/论坛中写英文Agent名 | 只匹配英文，中文安全 |
| VCP_ASYNC_RESULT | messageProcessor | 格式特殊 | 误触发风险极低 |
| superDetectors | messageProcessor | 取决于配置规则 | 需检查具体规则 |
| RAG区块标记 | chatCompletionHandler | 文档中写示例 | 用点号破坏标记 |

### 仅system角色的占位符（低风险）

| 占位符 | 模块 | 说明 |
|--------|------|------|
| 表情包/日记本 | messageProcessor | 在assistant消息中不会被解析 |
| 时间变量 | messageProcessor | 在assistant消息中不会被解析 |
| RAG语法 | RAGDiaryPlugin | 只在system消息中解析 |
| VCPTavern触发器 | VCPTavern | 只在system消息中检测 |

## 🔒 安全书写规范总结

### 场景1: 在日记中写占位符示例

| 格式 | 安全性 | 原因 |
|------|--------|------|
| `{*2xxx表情包}*2` | ✅ 安全 | 日记注入system后是预期行为 |
| `{*2xxx日记本}*2` | ✅ 安全 | 同上 |
| `[*2xxx日记本]*2` | ✅ 安全 | 会被RAGDiaryPlugin净化 |
| `{*2中文Agent名}*2` | ✅ 安全 | 正则不匹配中文 |
| `{*2英文Agent名}*2` | ⚠️ 危险 | 无角色限制，会被解析 |
| `VCP_RAG_BLOCK_START` | ⚠️ 危险 | 会触发RAG刷新检查 |

### 场景2: 在论坛帖子中写占位符示例

与日记相同，因为论坛内容也可能被读取后注入到消息中。

### 场景3: 在技术文档中写占位符示例

**推荐做法**：
1. 使用 `*2` 替代双符号：`{*2` 代替 `{{`
2. 使用点号破坏标记：`VCP_R.A.G_BLOCK` 代替 `VCP_RAG_BLOCK`
3. 在文档头部添加说明

## 📈 模块执行顺序确认

```
1. VCPTavern.processMessages()           ← 预设注入
2. messageProcessor.replaceAgentVariables() ← 占位符解析
3. RAGDiaryPlugin.processMessages()      ← RAG检索注入
4. 其他messagePreprocessor
5. 发送到上游AI
6. VCP循环（工具调用）
   └─ 工具结果不经过messageProcessor！
7. _refreshRagBlocksIfNeeded()           ← RAG区块刷新
   └─ 刷新后内容不经过预处理器！
```
