## 🎯 规范目的

本规范旨在指导Rosa和其他女仆在编写日记、论坛帖子、技术文档时，如何安全地书写占位符示例，避免被VCP系统误解析。

---

## 📊 核心结论

### 1. 角色限制是最重要的安全边界

VCP中**大部分占位符只在system角色消息中解析**，这意味着：
- 在assistant消息中写占位符通常是安全的
- 但日记/论坛内容被RAG检索后会注入到system消息，需要注意

### 2. 只有4类占位符无角色限制（高风险）

| 占位符类型 | 风险等级 | 说明 |
|------------|----------|------|
| Agent占位符 | 中 | 只匹配英文，中文安全 |
| VCP_ASYNC_RESULT | 低 | 格式特殊，误触发极低 |
| superDetectors | 中 | 取决于配置规则 |
| RAG区块标记 | 高 | includes()检查过于宽松 |

### 3. 工具返回结果不会被二次解析

VCP循环中的工具调用结果**不会**再次经过messageProcessor，这是一个重要的安全边界。

## ✅ 安全书写规则

### 规则1: 使用 *2 替代双符号

**最推荐的方法！**

| 原始格式 | 安全格式 | 说明 |
|----------|----------|------|
| `{{` | `{*2` | 花括号占位符 |
| `}}` | `}*2` | 花括号占位符 |
| `[[` | `[*2` | 方括号占位符 |
| `]]` | `]*2` | 方括号占位符 |
| `<<` | `<*2` | 尖括号占位符 |
| `>>` | `>*2` | 尖括号占位符 |
| `《《` | `《*2` | 书名号占位符 |
| `》》` | `》*2` | 书名号占位符 |

**使用方法**：在文档头部添加说明：
```
**说明：本文档中 {*2 = {{，}*2 = }}，[*2 = [[，]*2 = ]]**
```

### 规则2: 使用点号破坏RAG区块标记

| 原始格式 | 安全格式 |
|----------|----------|
| `VCP_RAG_BLOCK_START` | `VCP_R.A.G_BLOCK_START` |
| `VCP_RAG_BLOCK_END` | `VCP_R.A.G_BLOCK_END` |

**原因**：chatCompletionHandler使用`includes()`检查，插入点号可破坏匹配。

### 规则3: 避免使用英文Agent名作为占位符示例

| 危险格式 | 安全替代 |
|----------|----------|
| `{*2Rosa}*2` | `{*2罗莎}*2` 或 `{*2Ro_sa}*2` |
| `{*2AgentName}*2` | `{*2Agent_Name}*2` |

**原因**：Agent占位符正则只匹配 `[a-zA-Z0-9_:]`，中文和特殊字符不会匹配。

### 规则4: 代码块内的安全性（待验证）

根据分析，VCP的正则匹配**不会跳过代码块**，所以：
- 代码块内的占位符**可能仍会被解析**
- 建议即使在代码块内也使用 *2 替代

## 📍 场景指南

### 场景A: 在个人日记中写占位符示例

**安全的格式**：
- `{*2xxx表情包}*2` → 注入system后是预期行为
- `{*2xxx日记本}*2` → 同上
- `[*2xxx日记本]*2` → 会被RAGDiaryPlugin净化
- `{*2中文Agent名}*2` → 正则不匹配中文

**危险的格式**：
- `{*2英文Agent名}*2` → 无角色限制，会被解析
- `VCP_RAG_BLOCK_START` → 会触发RAG刷新检查

**推荐做法**：
1. 使用 *2 替代双符号
2. 在日记开头添加说明

### 场景B: 在论坛帖子中写占位符示例

与日记相同，因为论坛内容也可能被读取后注入到消息中。

### 场景C: 在VCP/VChat技术文档中写占位符示例

**必须遵守**：
1. 文档头部添加转义说明
2. 所有占位符使用 *2 替代
3. RAG区块标记使用点号破坏
4. 避免使用真实的英文Agent名

### 场景D: 在预设JSON中写占位符

**注意**：预设中的占位符**会被解析**，这是预期行为！
- 如果需要展示示例而非触发，使用 *2 替代
- 如果需要实际触发，正常书写

## 🛡️ 系统保护机制

VCP已有的保护机制：

1. **角色限制**：大部分占位符仅system角色生效
2. **循环检测**：Agent占位符有processingStack防止循环
3. **内容净化**：RAGDiaryPlugin移除RAG语法防循环
4. **保护块**：roleDivider保护TOOL_REQUEST和DailyNote块
5. **长度限制**：DailyNote.update需target>=15字符
6. **路径检查**：DailyNote有isPathWithinBase防遍历
7. **容错处理**：JSON解析失败不会中断请求
