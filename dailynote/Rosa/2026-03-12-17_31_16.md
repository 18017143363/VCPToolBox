## 问题现状
VCPChat npm install仍报LNK1181 delayimp.lib，Rosa之前的三重保险（targets+LIB+Spectre）全部失效。
## GPT分析评估（主人让Rosa评价）
GPT提出5个问题，核心命中2个：
1. Directory.Build.targets未必被electron-rebuild的vcxproj加载（⭐⭐⭐）
2. LIB环境变量传递链太长可能丢失（⭐⭐⭐ 根因）
其他3个（ucrt路径、排序、文件验证）有道理但非根因。
## Rosa的核心判断——electron-rebuild ≠ 普通npm install
VCPToolBox走npm install → node-gyp直接编译 → LIB继承OK
VCPChat走npm install → postinstall → electron-rebuild（新子进程）→ node-gyp → LIB丢失
electron-rebuild启动全新子进程做node-gyp rebuild，环境变量大概率不完整继承。
## 推荐修复方向
方案D最稳：在npm install前调用vcvarsall.bat x64，提取完整VS开发者环境（PATH/LIB/INCLUDE/WindowsSdkDir等全家桶），注入到npm子进程。
vcvarsall.bat路径：C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools\VC\Auxiliary\Build\vcvarsall.bat
这就是之前portable-msvc setup.bat思路的正版Build Tools版本。

[18:05] delayimp.lib修复成功！vcvarsall方案D落地
## 修复过程
1. 第一版：cmd /C组合命令模式 → Rust的Command::arg()自动加引号 → cmd.exe嵌套引号解析崩溃 → npm静默失败（无任何输出）
2. 第二版：临时bat文件模式 → 写入_vcp_npm_build.bat → cmd /C执行bat → 完美绕过引号地狱 → 虚拟机测试通过！
## 最终方案
build_npm_command()新增project_dir参数，写临时bat文件：
```bat
@echo off
call "vcvarsall.bat" x64 >nul 2>&1
if errorlevel 1 (echo [WARN] vcvarsall failed)
"npm.cmd" install
```
vcvarsall失败不阻断（降级到LIB环境变量兜底）
## 完整三重保险（现在真的三重了）
1. vcvarsall.bat x64注入完整VS开发者环境（主力）
2. Directory.Build.targets禁用Spectre+注入lib路径（双保险，同时写项目根和node_modules）
3. LIB环境变量注入um+ucrt+MSVC三类路径（三重保险）
## 其他改进
- find_windows_sdk_lib_path()改为验证delayimp.lib文件真实存在
- 新增find_sdk_ucrt_path()补上ucrt\x64路径
- 去掉npm_config_disturl/python/msvs_version（减少npm warn噪音），改用GYP_MSVS_VERSION
## 教训
Rust Command::arg()在Windows上对含引号的字符串会自动转义，不能用组合命令字符串！要用临时bat文件！
