[14:10] 主人贴出一整串 Comfy Cloud 浏览器 cookie，询问“是不是这些”。本轮给出明确判断：
1. 真正像核心登录态的基本只有 `session=`，其内容是 Firebase session JWT，包含 user_id / sign_in_provider / iat / exp，属于正经认证票据。
2. `_ga`、`_gcl_au`、`_dd_s`、`IR_*`、`PostHog`、`Mixpanel` 等几乎全是统计/埋点/归因，不是 recon.js 真正关心的认证核心。
3. 但光靠手工 pasted cookie string 仍然不稳：它丢失 domain/path/httpOnly/sameSite/expires 元数据，而且 Comfy Cloud/Firebase 的完整登录态大概率还涉及 localStorage / IndexedDB / Firebase persistence。
4. 额外发现：当前 session 看起来是短时票据，约2小时有效，不适合长期稳定自动化。
结论：临时测试可先用整串，真正工程化应把核心模块从“cookie 注入”升级为“storage state / localStorage / IndexedDB 注入与验证”。
