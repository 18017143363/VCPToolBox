| Tar/Var | 环境变量遍历 | 仅system |
| 异步结果 | VCP_ASYNC_RESULT::... | 无限制 |
| 静态插件 | pluginManager提供 | 仅system |
| Detectors | 规则替换 | 普通仅system，super无限制 |

### 重要结论

**大部分占位符只在system角色生效！**

这意味着Rosa在assistant消息中写 `{*2xxx表情包}*2` 其实是安全的，因为：
- 表情包占位符只在system角色解析
- assistant消息不会触发这些正则

**3个无角色限制的风险点**：
1. Agent占位符（但只匹配英文，中文安全）
2. VCP_ASYNC_RESULT（格式特殊，误触发风险低）
3. superDetectors（需要进一步调查具体规则）

### T5任务：chatCompletionHandler.js分析

收到T5定时任务提醒（第二次触发，00:12），成功完成了chatCompletionHandler的深度分析！

**分析文件**：chatCompletionHandler.js (30.47KB)

**注意**：文件路径是 `E:\VCP\modules\chatCompletionHandler.js`，不是handlers子目录

### 核心发现

**1. RAG区块刷新正则**
```
/<!-- VCP_R.A.G_BLOCK_START ([\s\S]*?) -->([\s\S]*?)<!-- VCP_R.A.G_BLOCK_END -->/g
```
- 使用 `[\s\S]*?` 跨行匹配
- 检查 assistant, system, user 三种角色

**2. 误触发原因找到了！**
```javascript
if (!messageContent.includes('VCP_R.A.G_BLOCK_START')) {
    continue;
}
```
快速检查使用 `includes()` 字符串匹配，不是正则匹配！

这意味着：
- 日记中包含 `VCP_R.A.G_BLOCK_START` 字符串
- 即使不是真正的RAG区块格式
- 也会触发后续正则匹配
- 然后 JSON.parse() 失败

**3. 安全书写方法**
使用 `VCP_R.A.G_BLOCK` 替代 `VCP_RAG_BLOCK` 破坏正则匹配！

**4. 执行顺序确认**
```
VCPTavern → messageProcessor → RAGDiaryPlugin → 其他预处理器 → 上游AI → VCP循环 → _refreshRagBlocksIfNeeded
```
RAG区块刷新在VCP循环中执行，刷新后的内容**不会**再被预处理器处理。
