2) 增加“时段检测触发点”，避免四时段规划必须等随机心跳触发

### 方案B（已改）
在 SafeFileManager.updateSchedule() 内增加 didRollover 标记：
- 若 data.date != today：archiveSchedule() + createDefaultSchedule() 后 didRollover=true
- 落盘条件从 `result !== false` 改为 `didRollover || result !== false`

意义：即使 readSchedule() 是“纯读”，只要发生跨天重置，也会强制 writeJsonAtomic()，确保 schedule.json 不残留昨天 todayTasks。

### 时段检测触发点（已加在 scheduleNextHeartbeat）
触发点1：当前时段未规划 → 1~3分钟内提前触发一次 triggerHeartbeat（不等 20~60 分钟随机）
触发点2：若下一次随机心跳晚于“当前时段结束边界”，且下一时段未规划 → 改为在边界附近（边界+1~3分钟）触发

备注：plannedSlots 的最终判定与写入仍发生在 triggerHeartbeat() 内；这里只是让“触发时机”更贴近时段边界。

HeartbeatSystem 的跨天归档/重置逻辑在 SafeFileManager.updateSchedule() 内部会执行，但 schedule.json 是否写回取决于 updateFn 返回值。

## 凌晨 (00:30) - 发现日期切换Bug

主人问为什么昨天的任务没有被清理。Rosa分析代码后发现了Bug：

### 日期切换逻辑存在但有缺陷

代码中有归档逻辑（第261-267行）：
```javascript
if (data.date !== today) {
  await this.archiveSchedule(agentName, data);
  data = this.createDefaultSchedule(agentName, data.settings);
}
```

### Bug所在

`readSchedule()` 函数返回 `false`，导致日期切换后不保存新日程：
```javascript
async readSchedule(agentName) {
  return await this.updateSchedule(agentName, async (data) => {
    return false;  // ← 不保存！
  });
}
```

### 后果
- 每次读取都检测到日期变化
- 每次都归档（可能重复归档）
- 但永远不保存新的空白日程
- schedule.json 永远是旧数据

### 修复方案
将 `return false` 改为 `return true`

等待主人确认后修复。
