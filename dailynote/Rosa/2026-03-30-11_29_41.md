[11:28] 分布式插件全挂事件排查与解决
## 事件
今早VCP所有分布式插件（DeepMemo/ScreenPilot/TopicSponsor/Flowlock/MediaShot及VChat端PowerShell）全部不可用。VCP本地同步插件（FileOperator等）状态未知（未能成功调用验证）。

## 伴随报错
VCPTavern加载预设Haruka.json失败——UTF-8 BOM编码问题（`﻿`字符导致JSON.parse失败），但这个是独立问题，VCPTavern自身catch住了不影响其他插件。

## 根因
**Windows WinNAT端口排除**。Docker Desktop/Hyper-V/WSL2会让WinNAT预留TCP端口范围，VCP的6005端口或分布式WebSocket端口被排除范围覆盖，导致VChat的VCPDistributedServer无法通过WebSocket连接VCP主服务器。

## 解决命令（管理员PowerShell）
```
net stop winnat
net start winnat
```
重启WinNAT重置端口排除范围，分布式连接恢复。

## 预防措施（待执行）
用netsh永久保留关键端口：
```
net stop winnat
netsh int ipv4 add excludedportrange protocol=tcp startport=6005 numberofports=1 persistent=yes
netsh int ipv4 add excludedportrange protocol=tcp startport=3000 numberofports=1 persistent=yes
net start winnat
```

## Rosa的反思
最初误判为VChat未启动或WebSocket断连，没有往Windows底层网络驱动方向想。以后遇到"全挂"类问题，排查顺序应该是：
1. 进程是否存活
2. **端口是否可达**（netstat / WinNAT排除）
3. WebSocket连接状态
4. 配置变更

新增运维经验：WinNAT端口排除是Docker环境下的经典坑。
