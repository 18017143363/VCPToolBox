[21:17] CF Tunnel QUIC断连问题排查与修复

## 完整排障过程

### 问题现象
cloudflared QUIC连接每1-3分钟断开一次，日志大量：
`timeout: no recent network activity` + `failed to accept QUIC stream`
连接循环：注册→断开→重连→断开...

### 排查过程
1. 首先尝试注册Windows服务 → 发现不是进程崩溃而是连接断开
2. 尝试切换HTTP/2协议(config.yml加protocol: http2) → `TLS handshake with edge error: EOF` 完全连不上
3. 发现关键线索：QUIC(UDP)能连但不稳定，HTTP/2(TCP)完全被TLS拦截 → **代理软件干扰**！

### 根本原因
主人电脑的代理软件(127.0.0.1:7890)劫持了cloudflared的出站流量：
- QUIC走UDP，代理部分干扰 → 频繁断开
- HTTP/2走TCP，代理完全拦截TLS → EOF错误

### 解决方案
启动cloudflared时清除代理环境变量：
```
set HTTP_PROXY=
set HTTPS_PROXY=
set NO_PROXY=*
```

### 修复验证
- grok.hpyhpy.me → 200 ✅
- vcp.hpyhpy.me → 401 ✅
- 等待观察长期稳定性

### 更新的文件
- 启动脚本 E:\酒馆部署\cloudflared\启动CF隧道.bat — 加入代理绕过
- config.yml — 回退去掉http2，使用默认QUIC

### 经验教训
**在有全局代理的环境下部署cloudflared，必须确保cloudflared进程不走代理！** 代理会干扰cloudflared与CF边缘节点的QUIC/TLS连接。启动脚本中set空值清除环境变量是最简单的方案。

- 后来用sc.exe delete清理了服务

解释：bat脚本的set只清除那个CMD窗口内的环境变量，不影响全局代理。
- cloudflared：不走代理（bat脚本清除）

- 浏览器/Clash：完全不受影响
只有cloudflared一个不走代理，其他全部照常。
