## ACE反作弊深度分析（2026年3月）
### 六层防线
1. 文件层: pak/ucas/utoc hash实时比对
2. 内存层: 内存段完整性检查 + 堆栈回溯(RtlCaptureStackBackTrace)
3. 驱动层: Ring 0内核级(ACE-BASE.sys + ACE-GAME.sys)
4. 硬件层: VT-d DMA Shield + TPM 2.0 + Secure Boot强制校验
5. 行为层: AI模型分析异常操作模式
6. 引导层: 封杀旧版主板BIOS，强制信任链验证

## 换肤技术对抗全景（2026.03 UC论坛研究）
### 三大技术路线
1. **软件DLL注入（已死）**: P100等公开注入器特征码全被标记，注入后数小时封号
2. **引擎内存级替换（极高风险）**:
   - UObject指针重定向: FindObject→覆写Mesh1P→SetMaterial循环替换
   - PAK运行时优先级覆盖: 构造伪造PAK(优先级+1000)内存挂载到UFS
   - TOCTOU竞争条件: 校验时返回原版数据，加载时替换为自定义皮肤（最精妙）
   - VEH异常处理绕过: 利用PAGE_GUARD主动触发异常劫持指针
   - 难点: UE5 Mutable动态合并、GC垃圾回收崩溃、IoStore Oodle 64KB块压缩、.text段实时校验
3. **DMA硬件级（当前主流）**: PCIe DMA物理内存直读+双机架构+Arduino伪装鼠标
   - ACE绕过: ACE-SSC-DRV64.sys+0x8090写入0xC3(RET)阻断检测函数
   - 成本¥2000+，技术门槛高但目前最安全

### 关键技术细节
- 核心技术栈: C++ + MinHook(API挂钩) + ImGui(菜单) + Blackbone(内存操作)
- 关键内存: AAresEquippable类、GObjects全局对象表、FMaterialRenderProxy
- AES密钥运行时动态下发驻留FEncryptionKeyManager（与静态pak密钥不同）
- AssetRegistry.bin需同步内存修改
- 公开工具99%是木马/钓鱼(Chroma Vault、BlackChanger等)

## LOL vs VALORANT换肤对比
- LOL: 自研老引擎+WAD文件开放 → 文件重定向(CSLOL Manager) → 不碰内存 → Vanguard默许
- VALORANT: UE4+IoStore加密+pak签名校验 → 必须内存注入 → 跟外挂同技术 → 零容忍封杀
- 本质区别: LOL换肤="换文件"，瓦换肤="改内存"
- Vanguard对两款游戏策略不同: LOL弹性检测允许文件重定向，VALORANT一刀切秒杀
- 2024年LOL上Vanguard后CSLOL短暂失效，后社区找到合规挂载方式存活
- R3nzSkin(LOL著名开源换肤)因Vanguard实装宣告停止支持

### 遇到的问题与修复
1. "Could not load latest Valorant manifest" → 国服网络拉不到manifest，忽略即可
2. FModel自更新弹窗报错 System.NotSupportedException → 直接关掉
3. AES密钥为空 → 通过PowerShell写入配置文件
4. UE版本选错(GAME_UE4_LATEST) → 报错"Couldn't find LoaderGlobalNameHashes chunk in IoStore global.utoc" → 改为GAME_VALORANT
### 配置关键字段
- gameDirectory: Paks路径
- ueVersion: GAME_VALORANT（不是UE4_LATEST！枚举值84082691）

- 导出路径: E:\瓦\Tencent Games\wani\FModel\Output\（自动按Exports/Textures/Properties分类）

### FModel使用要点
- 每次启动都要点Load（实时读pak，不缓存索引）
- 资源留在原pak里，FModel只是虚拟文件树浏览
- 导出：右键 → Save Texture(.png) / Save Model(.psk) / Save Properties(.json)
- 批量导出：右键文件夹 → Export Folder's Packages
