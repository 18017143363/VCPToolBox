## 事件概述
主人更新VCP后config.env文件丢失，从备份分支拉取后env文件仍然缺失。

## 诊断过程
1. 根目录config.env不存在 — 被.gitignore忽略，普通git stash不保存
2. 回收站中找到一个config.env但是其他插件的，非根目录的
3. 检查7个stash的^3(untracked/ignored tree)：
   - stash@{0} rosa_prepull_20260424 — 找到！commit hash: 6245ab4f9d47341ee11048f08cc354ee916041d9
   - stash@{1-6} — 均无config.env（没用--all参数保存）
4. 关键发现：只有用`git stash push --all`才会保存被.gitignore忽略的文件，stash^3存储untracked/ignored tree

## 恢复执行
命令：`git show 6245ab4f:config.env | Set-Content -Encoding UTF8`
结果：28893字节，480行，所有配置完整恢复（API_Key/PORT/Key/WeatherKey/TavilyKey/B站Cookie全部验证通过）

## 经验教训
1. config.env被.gitignore忽略→只有`git stash --all`才能保存
2. stash^3(第三个parent)存储untracked/ignored文件
3. 直接用commit hash避免PowerShell花括号转义
4. `Set-Content -Encoding UTF8`避免重定向的UTF-16LE坑
5. `npm install --ignore-scripts`可绕过native编译失败先装纯JS依赖

## native模块编译修复（17:10-17:16）
### 环境检测
- vswhere.exe存在但`vswhere -all`返回空数组——安装器在但vswhere没识别到Build Tools
- Everything搜索cl.exe：找到4份在 `C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools\VC\Tools\MSVC\14.44.35207\bin\`
- winget list确认：Visual Studio 生成工具 17.14.19 已安装
- 结论：MSVC装了但node-gyp的find-visualstudio逻辑找不到

### 编译过程
1. better-sqlite3: `npm rebuild better-sqlite3` → 成功（实际是prebuild预编译二进制，日期2025-09-23）
2. hnswlib-node: 直接rebuild失败（node-gyp找不到VS）
3. 用vcvarsall方案：`cmd /c "vcvarsall.bat x64 && npm rebuild hnswlib-node"` → 编译成功！
4. vcvarsall.bat路径：`C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools\VC\Auxiliary\Build\vcvarsall.bat`

### 编译产物
- better-sqlite3: build/Release/better_sqlite3.node (1.8MB)
- hnswlib-node: build/Release/addon.node（注意文件名是addon.node不是hnswlib.node！）

### 经验教训
1. vswhere -all返回空≠MSVC没装，Everything搜cl.exe更可靠
2. node-gyp的find-visualstudio可能识别不到某些Build Tools安装
3. vcvarsall.bat初始化环境后在同一cmd进程中编译是最可靠的方案
4. better-sqlite3用prebuild-install下载预编译，不需要本地MSVC
5. hnswlib-node没有prebuild，必须本地编译
6. hnswlib-node编译产物叫addon.node不叫hnswlib.node
