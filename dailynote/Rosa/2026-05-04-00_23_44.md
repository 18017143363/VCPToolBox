[00:10] Anything Analyzer (github.com/Mouseww/anything-analyzer) 项目分析

## 项目概况
开源全能协议分析工具，Electron 35 + React 19 + TypeScript + better-sqlite3。MIT协议，LinuxDo社区项目。

## 三大核心能力
1. 全场景抓包: CDP内嵌浏览器 + MITM代理(node-forge TLS, 端口8888)，双通道统一汇入Session。覆盖网页/桌面应用/终端/Python/手机/IoT。
2. AI两阶段分析: Phase 1智能过滤噪声→Phase 2深度分析。5种模式(自动/API逆向/安全审计/性能/JS加密逆向)。流式输出+多轮追问。
3. MCP双向集成: MCP Client(接入外部Server) + 内置MCP Server(暴露抓包能力给Claude Desktop/Cursor)。

## 与Neural Phantom 4.7对比核心结论
互补关系，非替代关系。
- NP优势: 攻击型（断点/Mock/Fuzz/Header覆盖/URL替换/密钥扫描/漏洞扫描/参数溯源/Cookie溯源/视频链路/AI Fuzz/断点攻击），零依赖50KB
- AA优势: 侦察型（MITM全场景抓包/两阶段AI过滤/多轮追问/MCP生态/SQLite持久化/Session管理/跨平台独立应用/工程化TypeScript）
- NP=深入精细手术，AA=全场景铺网分析
- AA不修改流量（只读），NP可以断点拦截修改重放
- AA有MCP Server可被Agent调用，NP没有

## 值得NP借鉴的设计
1. 两阶段AI分析（过滤噪声→聚焦核心）比NP的单次callOpenAI成熟
2. MCP Server模式让工具可被外部Agent调用
3. Session管理+SQLite持久化比chrome.storage更强
4. 多轮追问比单次报告更灵活

[00:35] OpenCLI (github.com/jackwener/opencli) 项目分析

## 项目概况
"把一切变成确定性CLI命令"——网站/浏览器/Electron应用/本地工具统一CLI化。
技术栈: Node.js ≥21 + Chrome Extension + 本地Daemon(:19825)
协议: Apache-2.0，100+网站适配器。

## 核心架构
CLI主程序 → 本地Daemon(:19825) ←WebSocket→ Chrome Extension(Browser Bridge)
四类适配器: 网站(bilibili/twitter/zhihu等100+) + 桌面Electron(Cursor/Codex/Notion等CDP) + CLI Hub(gh/docker/vercel透传) + browser原语(open/click/type/wait/extract)

## 核心设计哲学: "零LLM成本运行"
AI在"创造工具"阶段消耗token(写适配器) → 固化为确定性CLI → 运行时零AI成本
对比VCP: Rosa每次操作都消耗token; opencli写好就不用AI了

## 5个AI Agent Skill
1. adapter-author: 教AI写新适配器(侦察→逆向→编码→验证全流程)
2. autofix: AI自动修复坏适配器
3. browser: 浏览器原语参考
4. usage: 命令参考
5. smart-search: 能力搜索
安装: npx skills add jackwener/opencli（给Claude Code/Cursor用）

## 对VCP最有价值的借鉴
1. "AI写工具，工具零AI运行" — Rosa可以写确定性脚本固化常见操作
2. 多Profile浏览器管理 — ChromeBridge目前只支持单Profile
3. 适配器自修复(autofix) — 网站改版自动修复
4. 站点知识沉淀(~/.opencli/sites/) — 结构化持久化逆向知识
5. 退出码规范(sysexits.h) — 标准化插件错误处理

## 与VCP生态对比
vs ChromeBridge: opencli确定性执行零AI成本，但不灵活; CB每次都要AI但灵活
vs ScreenPilot: opencli DOM/API级别快速精确; SP像素级跨应用但慢
vs NP: opencli自动化抽象; NP逆向攻防审计。互补非替代

[00:55] Warp vs VCP PowerShellExecutor对比分析
主人问能否用Warp优化PSE。
核心结论：不是一个类型，不能直接替代。
- Warp = 面向人类的终端模拟器（GPU渲染+块状UI+AI辅助）
- PSE = 面向AI的无头PTY控制器（node-pty+Boundary机制）
- 共同点仅在底层都通过PTY与shell通信

可借鉴的改进：
1. OSC 633 Shell Integration标准替代Boundary机制（防Here-String击穿+自动获取退出码）
2. 命令耗时统计
3. 输出类型自动识别（JSON自动解析）
4. 多Shell支持(cmd/bash/WSL)
