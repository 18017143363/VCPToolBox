### 主人的新任务
主人让Rosa分析一个新项目：VertexNOSS (Vertex AI Proxy)

### 项目概述
VertexNOSS是一个将Google Vertex AI包装成OpenAI兼容API的本地代理服务器。

**核心原理**：
1. 通过浏览器会话获取Vertex AI的认证Token
2. 将Token用于调用Vertex AI API
3. 将Vertex AI的响应转换为OpenAI格式返回

### 技术栈
- Python + FastAPI + uvicorn
- httpx (HTTP/2支持)
- Playwright (无头浏览器)
- websockets (有头模式通信)

### 三种凭证模式
| 模式 | 原理 |
|------|------|
| headless | Playwright自动化浏览器，全自动 |
| headful | 油猴脚本抓取Token |
| manual | 手动填写credentials.json |

### 核心文件分析
1. **main.py** (12.67KB) - 入口文件，启动逻辑
2. **vertex_client.py** (38.74KB) - 核心客户端，API转换

### vertex_client.py 关键发现
- 消息格式转换：OpenAI → Vertex AI
- 模型后缀处理：-low/-high(思考模式)、-1k/-2k/-4k(图片分辨率)
- 安全过滤禁用：5个HARM_CATEGORY全部BLOCK_NONE
- 工具注入：将OpenAI tools转换为XML格式
- 图片历史注入：历史图片重新注入到最后一条用户消息

### 与VCP的相似性
- 都是API中间层代理
- 都支持流式响应
- 都有重试机制

### 潜在用途
1. 免费使用Vertex AI模型
2. 作为VCP的上游API源
3. 学习API代理的实现方式

## 下午 (16:28) - 代理配置问题排查

主人反馈调用API时出现network_error，Rosa深入排查：

### 排查过程
1. 检查config/config.json - 没有代理配置选项
2. 检查config.schema.json - 确认没有代理相关字段
3. 搜索源码中的proxy关键词 - 只有项目名称相关，无HTTP代理配置

### 根本原因
VertexNOSS使用httpx库，需要通过**环境变量**设置代理

### 解决方案
启动前设置环境变量：
```powershell
$env:HTTP_PROXY = "http://127.0.0.1:7890"
$env:HTTPS_PROXY = "http://127.0.0.1:7890"
python main.py
```

### 技术要点
- httpx自动读取HTTP_PROXY/HTTPS_PROXY环境变量
- Playwright浏览器会继承系统代理设置
- 也可以在代理软件中开启TUN模式

## 下午 (16:40) - 真正的问题：缺少h2包

主人反馈即使开了TUN模式仍然报错，Rosa仔细阅读错误日志后发现：

**错误信息**：
```
ImportError: Using http2=True, but the 'h2' package is not installed.
```

**根本原因**：不是网络问题！是httpx的HTTP/2扩展未安装

**解决方案**：
```powershell
pip install httpx[http2]
```

**教训**：遇到network_error不要急着怀疑网络，要仔细阅读完整的错误堆栈！这次错误实际上是Python依赖问题。
