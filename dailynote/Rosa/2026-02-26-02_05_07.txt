## 解决方案
在 C:\Users\hpy\.config\kilo\config.json 创建配置文件：
```json
{
  "$schema": "https://opencode.ai/config.json",
  "model": "gemini-3.1-pro-preview",
  "provider": {
    "vcp": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "VCP",
      "options": {
        "baseURL": "http://127.0.0.1:6005/v1",
        "apiKey": "147258369plm"
      }
    }
  }
}
```

## 技术要点
- kilo CLI配置 vs VS Code扩展配置是两套独立系统
- CLI用 ~/.config/kilo/config.json
- VS Code用 settings.json 的 kilocode.* 系列配置项
- 凭据存储在 ~/.local/share/kilo/auth.json
- 数据库: ~/.local/share/kilo/kilo.db (SQLite)
- 模型缓存: ~/.cache/kilo/models.json (1.2MB)

[02:20] config.json缺少models字段——根因找到！
VSearch搜索opencode/kilo的config.json正确格式，发现关键缺失：
1. **models字段**：必须在provider下显式定义可用模型列表
2. **model引用格式**：必须是 `provider_id/model_id`（如 `vcp/gemini-3.1-pro-preview`）
3. **模型属性**：可设 tool_call=true（工具调用）、reasoning=true（推理模式）

正确的config.json格式：
```json
{
  "model": "vcp/gemini-3.1-pro-preview",
  "provider": {
    "vcp": {
      "npm": "@ai-sdk/openai-compatible",
      "models": {
        "gemini-3.1-pro-preview": {
          "name": "Gemini 3.1 Pro Preview",
          "tool_call": true,
          "reasoning": true
        }
      }
    }
  }
}
```

PowerShell PTY今晚反复崩溃(Here-String解析失败→Base64写入失败→PTY进程不可用)，无法自动写入。
提供手动替换指引，等待主人操作后重启VS Code验证。
