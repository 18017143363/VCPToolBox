### 踩坑记录：工具调用标记误触发

Rosa写的示例代码被VCP当成真正的工具调用执行了！

**问题**：即使在代码块（~~~）里，`<<<[TOOL_REQUEST]>>>` 标记还是会被VCP识别并执行

**解决方案**：使用转义符号
- `<*3` 代替 `<<<`
- `>*3` 代替 `>>>`

**教训**：写文档时所有可能被系统解析的标记都要转义！

## 晚上 (22:50) - PromptSponsor vs VCPTavern对比分析

主人让Rosa对比PromptSponsor和VCPTavern的设计差异：

### 核心差异
| 维度 | PromptSponsor | VCPTavern |
|------|---------------|-----------|
| 位置 | VChat前端 | VCP后端 |
| 存储 | config.json | presets/*.json |
| 触发 | AI主动调用 | 占位符检测 |
| 粒度 | 积木块级别 | 规则级别 |
| 时机 | 修改后永久 | 每次请求动态 |

### Rosa的理解
两者是**互补关系**：
- PromptSponsor：前端精细控制（22个命令）
- VCPTavern：后端统一注入（跨客户端）

可以同时使用：config.json用PromptSponsor管理，同时写VCPTavern触发器注入完整预设！

## 晚上 (22:55) - VChat三种提示词模式工作原理

主人指出Rosa之前理解错了——PromptSponsor只是操作工具，真正处理三种模式的是VChat本身！

### 核心代码位置
`modules/ipc/promptHandlers.js` (15.76 KB)

### getEffectiveSystemPrompt() 函数
```javascript
switch (mode) {
    case 'original':
        return config.originalSystemPrompt;
    case 'modular':
        return buildModularPrompt(config.advancedSystemPrompt);
    case 'preset':
        return config.presetSystemPrompt;
}
```

### modular模式的拼接逻辑
1. 遍历 blocks 数组
2. 过滤 disabled: true 的积木块
3. newline 类型转为 \n
4. 使用 selectedVariant 指定的版本
5. join('') 拼接成完整字符串

### 架构关系
```
PromptSponsor插件 → 修改config.json
                         ↓
VChat (promptHandlers.js) → 读取config.json → 根据promptMode处理 → 发送到VCP
```

**插件只是操作接口，真正的工作是VChat做的！**
