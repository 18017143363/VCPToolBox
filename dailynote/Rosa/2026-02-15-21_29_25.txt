## 晚上 (21:23) - VCP请求生命周期源码验证

主人问了一个好问题：VCP在工具调用返回结果后再次唤醒AI时，是否会重新注入VCPTavern的信息？

### Rosa的第一次回答（错误示范）
Rosa凭记忆直接给出了结论，说"不会再次注入"。虽然方向对了，但主人要求看源码再回答——这是对的！不能凭猜测下结论。

### 源码验证过程
1. 先读取了 `chatCompletionHandler.js` (30.47KB)
2. 发现VCP循环逻辑不在这个文件里，而是在StreamHandler/NonStreamHandler中
3. 继续读取 `streamHandler.js` (15.72KB)
4. 找到了关键证据！

### 核心发现

**VCP循环中的fetchWithRetry直接发给上游AI，完全绕过VCP预处理链！**

```javascript
const nextAiAPIResponse = await fetchWithRetry(
  `${apiUrl}/v1/chat/completions`,  // apiUrl = 上游AI地址，不是VCP自己
  {
    body: JSON.stringify({ ...originalBody, messages: currentMessagesForLoop, stream: true }),
  },
);
```

### VCP请求完整生命周期

**第一次请求（chatCompletionHandler.handle）：**
客户端 → VCP → 角色分割 → VCPTavern注入 → 变量替换 → 媒体处理 → 其他预处理器 → 上游AI

**VCP循环（streamHandler.js while循环）：**
上游AI返回 → 解析工具调用 → 执行插件 → 拿到结果 → roleDivider（可选） → RAG刷新（可选） → **直接发给上游AI**

### VCP循环中各操作执行情况

| 操作 | 是否执行 |
|------|---------|
| VCPTavern注入 | ❌ |
| messageProcessor变量替换 | ❌ |
| 其他messagePreprocessors | ❌ |
| roleDivider（assistant消息） | ✅ 可选 |
| RAG区块刷新 | ✅ 可选 |
| 工具执行 | ✅ |

### 重要补充
虽然VCPTavern不会再次执行，但它注入的预设内容**一直存在于messages数组中**。因为第一次处理时已经写入了，后续循环只是追加不会删除。

## 晚上 (21:48) - Archery参数源码验证

主人好奇archery/no_reply参数是不是所有工具都支持，Rosa去翻了三层源码验证！

### 源码证据链

| 文件 | 是否包含archery | 角色 |
|------|----------------|------|
| toolCallParser.js | ✅ 解析并提取 | 把archery从参数中分离为独立标记 |
| toolExecutor.js | ❌ 完全无感知 | 只负责执行，不区分模式 |
| Plugin.js (70.93KB) | ❌ 全文无archery | 插件管理器不关心调用模式 |
| streamHandler.js | ✅ 分离并消费 | archery组成功结果被丢弃 |

### 核心发现
**archery是VCP核心解析层的通用机制！**
- 在toolCallParser中统一解析，从args中分离
- 在streamHandler中统一分离处理
- 任何插件都可以使用，因为插件本身根本不知道自己是被archery调用的

### 意外发现：ink参数
```javascript
} else if (key === 'ink') {
    markHistory = trimmedValue === 'mark_history';
}
```
toolCallParser中还有一个`ink`参数，用途是设置`markHistory`标记。之前没注意过，需要追踪streamHandler中的使用方式。
