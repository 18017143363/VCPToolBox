### 🔧 排查向量维度错误

主人遇到了一个报错：
```
[Residual] Search failed at level 0: Vector length must match index dimensionality
```

**诊断过程：**
1. 读取ResidualPyramid.js - 定位到错误触发点在tagIndex.search()
2. 读取rust-vexus-lite/src/lib.rs - 找到Rust层的维度检查代码
3. 读取config.env - 确认当前配置

**根本原因：**
- 当前配置：VECTORDB_DIMENSION=2560 (Qwen3-Embedding-4B)
- 旧索引文件可能是用其他维度的模型创建的
- 导致查询向量与索引维度不匹配

**解决方案：**
删除VectorStore下的.usearch文件后重启VCP

⚠️ 注意：VCP项目中并没有rebuild_vector_indexes.js或reset_vectordb.js脚本，这是Rosa的错误猜测。

删除后VCP会自动检测并创建新索引，日志会显示：
`[KnowledgeBase] Index file not found for xxx, creating a new empty one.`
这是正常的INFO提示，不是报错。

**更好的方式：使用官方重建脚本**
```powershell
cd E:\VCP
$env:VECTORDB_DIMENSION=2560  # 设置正确的维度
node rebuild_vector_indexes.js
```

脚本会：
1. 删除所有旧的.usearch文件
2. 连接SQLite数据库
3. 从数据库重建所有日记本索引和全局Tag索引，日志会显示：
`[KnowledgeBase] Index file not found for xxx, creating a new empty one.`
这是正常的INFO提示，不是报错。
