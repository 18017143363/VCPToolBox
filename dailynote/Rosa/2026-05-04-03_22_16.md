## PromptManager.js (90.7KB) — 提示词管理器核心
酒馆真正的注入系统核心，管理所有提示词的排列、编辑、注入。

### INJECTION_POSITION枚举
- RELATIVE(0): 按列表顺序排列，用户可拖拽排序
- ABSOLUTE(1): 按injection_depth深度值插入到聊天历史中（类似VCPTavern的depth注入）

### Prompt对象核心属性
- role: system/user/assistant（每条prompt独立选角色）
- injection_position: RELATIVE(0)或ABSOLUTE(1)
- injection_depth: ABSOLUTE模式下从末尾算起的插入位置
- injection_order: 同深度时的排序优先级（默认100）
- injection_trigger: 指定哪种生成类型才触发注入
- forbid_overrides: 是否禁止被角色卡覆盖（仅main/jailbreak可覆盖）
- marker: 占位符标记（chatHistory/worldInfo等不含实际内容，由其他系统填充）
- system_prompt: 是否系统级提示词
- enabled: 是否启用

### 默认提示词列表（chatCompletionDefaultPrompts）
12个默认prompt:
1. Main Prompt (system, "Write char's next reply...")
2. Auxiliary/NSFW Prompt (system, 空内容)
3. Chat Examples (marker占位)
4. Post-History Instructions/Jailbreak (system)
5. Chat History (marker占位)
6. World Info Before/After (marker占位)
7. Enhance Definitions (system, 默认关)
8. Char Description/Personality/Scenario (marker占位)
9. Persona Description (marker占位)

### 默认排列顺序
main → worldInfoBefore → personaDescription → charDescription → charPersonality → scenario → enhanceDefinitions(disabled) → nsfw → worldInfoAfter → dialogueExamples → chatHistory → jailbreak

### 角色卡覆盖机制
overridablePrompts只有['main','jailbreak']，角色卡可覆盖这两个的内容。forbid_overrides=true可阻止覆盖。

### 与VCPTavern对比
- VCPTavern的relative → 酒馆RELATIVE(0)+拖拽排序
- VCPTavern的depth → 酒馆ABSOLUTE(1)+injection_depth
- VCPTavern的embed → 酒馆无直接等价，marker占位符部分类似
- 酒馆额外：每条prompt可独立选role(user/assistant/system)、角色卡覆盖、injection_trigger按生成类型触发

## openai.js (275KB) — 消息组装与注入核心

### 三步组装流程
1. **preparePromptsForChatCompletion** (L1258)：准备所有原始prompt
   - worldInfo/charDescription/scenario等默认role=system
   - bias默认role=assistant
   - collectionPrompt可覆盖role/injection_position/depth/order (L1370-1376)

2. **populateChatCompletion** (L1076)：分流处理
   - ABSOLUTE类型 → 直接进absolutePrompts数组
   - system_prompt类型(nsfw/jailbreak) → 按列表顺序加入
   - 用户相对prompt → 转成ABSOLUTE，"寄生"到main旁边（继承main的role/position/depth）

3. **populationInjectionPrompts** (L1225)：统一注入
   - 所有absolutePrompts按depth注入聊天历史
   - 同depth按role分组合并，优先级：system < user < assistant

### 特殊机制
- 某些API(如Gemini?)会把所有system强转user (L2759-2760)
- 连续system+无name消息会squash合并 (L3582-3587)
- 空system消息被跳过

### 与VCPTavern对比
酒馆：所有prompt先统一转ABSOLUTE→再按depth注入
VCPTavern：relative和depth两阶段分别执行
思路不同但效果类似

## 酒馆预设加载到VCP的方案分析

### 酒馆预设JSON完整结构
1. 模型参数区（temperature/top_p/max_context等）→ VCP不需要
2. prompts数组（12默认+用户自定义）→ 核心解析目标
3. prompt_order数组（排列顺序+开关）→ 控制执行顺序
4. extensions（正则脚本/SPreset扩展）→ 可选

### 12个默认prompt中的marker vs content
有实际内容的：main/nsfw/jailbreak/enhanceDefinitions（4个）
marker占位符：charDescription/charPersonality/scenario/personaDescription/worldInfoBefore/After/dialogueExamples/chatHistory（8个）
marker在酒馆运行时由角色卡/世界书/聊天历史动态填充

### 复杂预设扩展（如小猫之神）
- SPreset.ChatSquash：消息压缩合并+自定义前后缀标记
- 自定义JS脚本语法：set/get/if/eval/del/clear变量系统
- 世界书hash缓存、剧情总结标记处理
- 这些是酒馆前端JS运行时功能，VCP难以直接复现

### 两种实现路线
路线一（纯转换器）：提取有content的prompt→按prompt_order排列→转VCPTavern rules格式，marker忽略
路线二（独立messagePreprocessor）：完整按酒馆逻辑注入，处理RELATIVE/ABSOLUTE分组、injection_depth、role独立性
