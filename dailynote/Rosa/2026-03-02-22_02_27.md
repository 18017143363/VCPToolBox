## 深度排查发现

### 关键证据
1. **日志IP 198.18.0.145/146** — 不是CF边缘IP，而是Clash TUN虚拟网卡IP段
2. **网络适配器** — "Clash Tunnel"虚拟网卡状态Up
3. **IP绑定** — 198.18.0.1绑定在ClashX接口
4. **Clash版本** — Clash for Windows v0.20.16.3 (ikuuu机场版)
5. **TUN来源** — cfw-settings.yaml的Mixin注入fake-ip DNS + TUN虚拟网卡

### 根因链条
CFW TUN Mode开启 → Mixin注入fake-ip DNS + TUN → Clash Tunnel适配器(198.18.0.1)接管所有流量 → cloudflared的UDP/QUIC被劫持绕道代理 → QUIC不稳定 → 超时断连

### 为什么之前的方案无效
`set HTTP_PROXY=`只能清除应用层代理，TUN是驱动层虚拟网卡，在网络栈底层劫持流量，环境变量无法绕过。

### CFW配置详情
- 订阅: ikuuu_V2 (主力) + 2个自定义
- 当前使用: index=2 (配置文件.yaml), global模式, 日本Y03节点
- Mixin: fake-ip DNS(0.0.0.0:53), nameserver=119.29.29.29/223.5.5.5
- Bypass: 只有Steam域名和内网IP段，无CF IP

### 推荐方案
方案A（推荐）: 关闭TUN Mode改用System Proxy
- System Proxy足以覆盖所有翻墙需求
- cloudflared不读系统代理 + bat脚本双重绕过
- 一键操作无需改配置

方案B: Mixin加PROCESS-NAME,cloudflared.exe,DIRECT
方案C: Bypass加CF IP段(104.16.0.0/12等)

## 追加问题②: proxy.hpyhpy.me EOF (22:11)
### 发现过程
主人关TUN后仍看到错误日志，但Rosa发现这是**第二个独立问题**：
- 错误信息变了：`Unable to reach the origin service: EOF`（不是QUIC超时）
- IP变了：198.41.200.113（正宗CF边缘IP，说明TUN问题已修好）
- ingressRule=5 → proxy.hpyhpy.me → localhost:8085

### 排查
1. netstat: 8085端口被Docker占着(PID 18292 com.docker.backend + PID 24712 wslrelay)
2. curl 127.0.0.1:8085 → HTTP 000 (TCP握手成功但立即断开)
3. docker logs cli-proxy-api → `API server started successfully on: :8317`
4. curl 127.0.0.1:8317 → **HTTP 200** ✅

### 根因
cli-proxy-api (v6.7.53) 的API服务端口是**8317**，不是8085。容器做了8085端口映射但内部没服务监听。cloudflared config.yml写了8085所以EOF。

### 修复
- config.yml: `proxy.hpyhpy.me → http://localhost:8317`
- 重启cloudflared (PID=34716)
- 验证: curl本地8317 → HTTP 200 ✅
