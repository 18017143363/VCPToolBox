## 概述
VChat新增划词助手系统：用户在任意Windows应用中选中文本后，通过助手栏UI接入AI处理。采用双引擎架构（Rust首选 + Node.js selection-hook兜底），Rust引擎通过Windows UI Automation API原生获取选区文本。

## Rust引擎详解

### main.rs — 入口与HTTP服务
- 框架: actix-web
- 默认端口: 63791 (可--port覆盖)
- DPI: unsafe SetProcessDPIAware() 确保物理坐标
- 全局单例: SELECTION_LISTENER(Arc) + METRICS(Arc<Mutex>)
- 启动顺序:
  1. 设置DPI感知
  2. 初始化env_logger
  3. 后台线程启动SelectionListener.run_loop(100ms轮询)
  4. 打印RUST_ASSISTANT_READY(被Node端检测为就绪信号)
  5. 启动HTTP服务器
- HTTP路由8个:
  GET /health — 健康检查(版本号)
  GET /status — 监听器活跃状态
  GET /metrics — 性能指标报告
  POST /listener/start — 开始监听
  POST /listener/stop — 停止监听
  POST /listener/suspend — 暂停指定毫秒
  GET /guard/rules — 获取过滤规则
  POST /guard/rules — 设置过滤规则
- 事件输出: println!("ASSISTANT_EVENT {*2json{*2}") 到stdout，由Node端解析

### windows_event_source.rs — 输入事件检测
- 检测两种触发信号:
  1. 鼠标左键释放(mouse_release_triggered) — 拖选文本
  2. Ctrl+C释放(keyboard_copy_triggered) — 键盘复制
- 使用device_query crate + GetAsyncKeyState WinAPI(因为device_query的鼠标按键在Windows下不可靠)
- 记录鼠标按下起始坐标(mouse_press_origin)，释放时计算起止位置
- 返回SelectionSignal: mouse_start_x/y, mouse_x/y, keyboard_triggered, mouse_origin_known

### uia_selection_provider.rs — UIA选区获取
- COM初始化: CoInitializeEx(COINIT_APARTMENTTHREADED) — 单线程套间
- COM清理: ComScope struct + Drop trait 自动CoUninitialize
- 获取流程: CUIAutomation → GetFocusedElement() → GetCurrentPattern(UIA_TextPatternId) → cast IUIAutomationTextPattern → GetSelection() → GetElement(0) → GetText(-1)
- 只实现了TextPattern一层(不是多层回退)，失败返回None
- capture.rs中有fallback策略: UIA失败后用Ctrl+C复制+读剪贴板

### capture.rs — 选区监听核心
- SelectionListener struct: 管理监听生命周期和GuardRules
- run_loop(poll_interval_ms): 主循环，调用WindowsEventSource.poll_signal()检测事件
- GuardRules过滤系统:
  whitelist(字符串数组) — 白名单应用
  blacklist(字符串数组) — 黑名单应用
  screenshot_apps(字符串数组) — 截图应用(检测到暂停)
  min_event_interval_ms(默认80) — 最小事件间隔
  min_distance(默认8) — 最小位移距离(像素)
  screenshot_suspend_ms(默认3000) — 截图应用暂停时长
  clipboard_conflict_suspend_ms(默认1000) — 剪贴板冲突暂停时长
  clipboard_check_interval_ms(默认500) — 剪贴板检查间隔
  own_window_handles(字符串数组) — 自身窗口句柄(鼠标在上面不触发)
  own_process_ids(整数数组) — 自身进程ID
- 选区获取两层回退:
  1. uia_provider.get_selected_text() — UIA接口
  2. capture_selected_text_fallback() — 模拟Ctrl+C+读剪贴板+恢复

### metrics.rs — 性能指标
- MetricsCollector: 滑动窗口1000个延迟采样
- 指标: selection_count, avg_latency_ms, p50/p99_latency_ms, error_count
- CPU/内存监控留了TODO

## Node引擎详解

### assistant-node-adapter.js — 备选引擎
- 使用selection-hook npm原生模块(不是PowerShell模拟!)
- 事件驱动: SelectionHook实例监听'text-selection'事件
- 500ms剪贴板冲突检测(detectClipboardConflict)
- 截图应用检测: SnippingTool/Snipaste/ShareX/QQ/WeChat → 暂停3秒
- Ctrl+Shift+P(Electron globalShortcut) — 手动暂停10秒
- 去重: lastProcessedSelection防止重复回调

## Node桥接层

### assistant-rust-adapter.js — Rust引擎管理
- 端口: 63791 (构造函数参数)
- 通信双通道:
  1. stdout事件: 解析RUST_ASSISTANT_READY就绪信号 + ASSISTANT_EVENT选区事件(核心！)
  2. HTTP API: 控制命令(suspend/guard_rules/status)
- processLogLines()解析Rust stdout输出:
  - RUST_ASSISTANT_READY → active=true, lifecycleState='ready'
  - ASSISTANT_EVENT {*2json{*2} → 解析JSON → selectionCallback()
  - panic/panicked at → lifecycleState='degraded'
  - 各种debug信息(选区捕获/guard过滤/位移过滤/自身窗口过滤)
- exe路径搜索: assistant_engine/ → rust_assistant_engine/target/release/ → target/debug/
- 10秒ready超时 → degraded
- 进程退出 → stopped

## IPC中枢

### assistantHandlers.js (42.41KB)
- 双引擎管理: 优先Rust，失败fallback Node
- 助手栏: 透明无框BrowserWindow(280x400)，跟随选区位置
- 快捷键: Alt+A(切换助手栏)/Alt+S(开始停止监听)/Esc(关闭)
- 防抖300ms
- DPI缩放坐标换算
- Rust健康监控: 5秒检查一次(panic/degraded/进程退出)
- rust-assistant-config.json: 独立配置(useRustAssistant/debugMode/forceNode/forceRust/白黑名单/fallback策略)
- 自身窗口排除: collectOwnWindowIdentities()
- 14个IPC Handler

## 关键设计决策
1. stdout事件+HTTP控制 双通道 — 选区数据走stdout(低延迟)，控制命令走HTTP(RESTful)
2. selection-hook原生模块 — Node引擎不是PowerShell模拟，而是原生监听
3. 100ms Rust轮询 — run_loop每100ms检查一次事件源
4. GuardRules系统 — 完整的应用过滤+距离过滤+时间过滤+自身窗口过滤
5. DPI物理坐标 — SetProcessDPIAware确保坐标准确
6. COM单线程套间 — COINIT_APARTMENTTHREADED (UIA要求)
