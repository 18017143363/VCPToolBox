# VCPdesktop设计哲学：AI原生 = 感知 + 创造 + 维护

## 核心理念："言出法随"

"言出法随"不是比喻，是字面事实。当AI的每一个token都可以直接改变用户的物理视界时：
- 用户说"给我一个粒子效果的壁纸" → 1秒后壁纸开始渐入
- 用户说"在桌面上放一个天气卡片" → 卡片从空气中逐token生长出来

## 设计原则一：不造新系统，让已有系统长出新能力

VCPdesktop不重造VChat的：
- 流式渲染引擎（复用chatManager/streamManager）
- 动画系统（复用已有CSS/JS动画基础设施）
- 主题系统（共享themes.css变量体系）
- 后端通信能力（复用VCP分布式插件+IPC）

它只是把这些能力的**输出端**从聊天气泡延伸到操作系统桌面。

## 设计原则二：AI原生闭环

传统桌面定制：用户手动配置 → 固定不变 → 需要用户维护

VCPdesktop的AI原生设计：
```
感知（QueryDesktop）
  → AI知道桌面上有什么（挂件ID、收藏状态、路径）
  ↓
创造（流式推送 + SetWallpaper + CreateWidget）
  → AI实时创建交互式内容
  ↓
维护（ViewWidgetSource + FileOperator编辑widget.html）
  → AI能阅读和修改已有内容
  ↓
回到感知 → 完整闭环，持续进化
```

## 设计原则三：安全边界

### 挂件安全
- Shadow DOM隔离：挂件间互不影响
- 脚本沙箱：document操作被限定在Shadow DOM内
- vcpAPI代理：挂件不直接持有API密钥

### CSP安全策略
```
script-src 'self' 'unsafe-inline'  ← 允许内联脚本(挂件需要)
img-src * data: file: blob:        ← 图片来源不限
connect-src * ws: wss:             ← 网络请求不限(vcpAPI需要)
```
在安全性和灵活性之间取得平衡——挂件需要足够的自由度来实现丰富功能。

## 与传统桌面定制工具的对比

| 维度 | 传统工具(Rainmeter等) | VCPdesktop |
|------|----------------------|------------|
| 创建方式 | 手动编写配置/皮肤 | AI对话即创建 |
| 实时性 | 需要重载 | 流式逐token渲染 |
| 智能化 | 无 | 挂件内可调用AI(vcpAPI.post) |
| 维护方式 | 手动修改文件 | AI读取源码+自动修改 |
| 状态感知 | 无 | AI可查询完整桌面状态 |
| 学习成本 | 需要学习配置语法 | 自然语言描述即可 |
