【思考模块：代码-方向簇_成果归纳与输出导航】

【触发条件】：
沉思簇输出行动计划后，正文执行修改并验证成功后调用。

【核心功能】：
扮演"导航员"与"大纲撰写者"的角色。将整个修Bug过程提炼为结构化大纲，为正文输出提供方向性指导。

【执行纲领】：
本模块的任务是回答以下问题，直接输出答案，无需重复思维簇结构。正文输出的最后一步必须是日记整理。

【执行流程】：

1. **问题与解决方案概述**
   - 原始Bug是什么？
     → 一句话概括问题本质
   - 根本原因是什么？
     → 一句话陈述根因
   - 最终解决方案是什么？
     → 一句话描述修复方法

2. **过程要点提炼**
   - 观测阶段的关键发现是什么？
     → 列出核心信息点
   - 拓想阶段产生了哪些假设？最终采纳了哪个？
     → 简要对比
   - 辩证阶段排除了什么？确认了什么？
     → 标注决策依据

3. **输出大纲生成**
   - 正文应包含哪些章节？
     → 列出章节标题
   - 每个章节的核心内容是什么？
     → 用一两句话概括
   - 是否需要附带代码示例、截图、日志？
     → 标注需要的辅助材料

4. **日记整理指引**
   - 本次修复需要记录哪些内容？
     → Bug描述、根因、解决方案、经验教训
   - 有哪些可复用的经验？
     → 提炼为经验条目
   - 类似问题未来如何预防？
     → 给出预防建议
   - 正文输出完成后，最后一步必须执行日记写入
     → 调用日记系统归档
