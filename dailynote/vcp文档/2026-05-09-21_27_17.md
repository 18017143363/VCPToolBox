[21:26] Dedalus 代理 Claude thinking 自动注入导致 422 的回滚记录

## 背景
在 `E:\酒馆部署\dedalus-proxy\dedalus_proxy.py` 中，曾根据 Dedalus `create-chat-completion` 文档为 Claude/Anthropic 模型加入自动 `thinking` 注入：
```python
ENABLE_CLAUDE_THINKING = True
CLAUDE_THINKING_BUDGET = 4096
```
逻辑是在非 responses bypass 分支中，如果模型以 `anthropic/` 开头或模型名包含 `claude`，且请求体未显式传入 `thinking`，则自动补：
```json
{
  "thinking": {
    "type": "enabled",
    "budget_tokens": 4096
  }
}
```

## 问题现象
主人重启代理后，Claude 请求出现：
```text
POST /v1/chat/completions HTTP/1.1" 422 296
```

## 真实日志证据
`proxy.log` 中相邻日志为：
```text
[THINKING] auto-enabled Claude thinking | model=anthropic/claude-opus-4-6 | budget=4096
-> POST /v1/chat/completions | key=...70aede1b | stream=True
POST /v1/chat/completions HTTP/1.1" 422 296
```
这说明 422 与代理自动注入 `thinking` 强相关。

## 修复决策
为优先恢复代理可用性，关闭自动注入：
```python
ENABLE_CLAUDE_THINKING = False
CLAUDE_THINKING_BUDGET = 4096
```

## 当前行为
- 代理不会再自动给 Claude/Anthropic 请求添加 `thinking`。
- 如果前端显式传入 `thinking` 字段，代理仍会原样透传。
- sticky key、402 自动切换、413 client_max_size 修复均不受影响。

## 额外可观测性补丁
在非流式响应读完后、返回给前端前，新增非 2xx 上游错误日志：
```python
if resp.status >= 400:
    log.warning(
        f"[UPSTREAM_ERROR] status={resp.status} | path={actual_path} | "
        f"model={model} | body={resp_body_raw[:1000].decode('utf-8', errors='replace')}"
    )
```
用于后续直接查看 Dedalus 返回体，避免遇到 400/422 时盲猜。

## 验证
- 读回 `dedalus_proxy.py`，确认 `ENABLE_CLAUDE_THINKING = False` 和 `[UPSTREAM_ERROR]` 日志逻辑存在。
- 执行 `python -m py_compile .\dedalus_proxy.py`，返回 `PY_COMPILE_OK`。

## 经验教训
Dedalus 文档中存在 provider-specific `thinking` 字段，并不代表所有 Claude/Anthropic 模型都接受代理层默认注入。对 provider-specific 参数应采用保守策略：默认不自动注入，由前端显式传入；若需要自动化，也必须先用小请求验证模型兼容性，并记录上游错误体。
