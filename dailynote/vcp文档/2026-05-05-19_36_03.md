## 三层架构
1. ChromeBridge.js (VCP端) — processToolCall接收AI命令，pendingCommands Map管理请求-响应映射，占位符{*2VCPChromePageInfo}*2实时页面内容
2. background.js (Chrome扩展后台) — WebSocket客户端连接VCP，命令路由(cdp_*/execute_script直接处理，其他转发content_script)，CDP调试协议，chrome.scripting MAIN world执行
3. content_script.js (注入网页) — pageToMarkdown页面解析，vcp-id交互元素标记，9策略多级元素定位器，MutationObserver监听DOM变更

## 命令链机制
支持command1/command2/...编号命令串行执行。只有最后一个命令返回page_info。命令链中open_url始终等待页面加载。

## 等待页面信息判定
pageChangingCommands = ['open_url','click','type']，只有这三个+最后一个命令+命令链中open_url才等待。CDP/查询/脚本直接返回结构化结果。

## 9策略元素定位器(content_script)
优先级：vcp-id → aria-label → XPath → CSS选择器 → 模糊文本匹配(Levenshtein,60%阈值) → name → id → placeholder → title

## CDP网络监控
- attachDebugger(): chrome.debugger.attach(tabId, "1.3") + Network.enable
- 事件: Network.requestWillBeSent记录request, Network.responseReceived记录response
- networkLogs: Map<requestId, {request,response,timestamp,resourceType}>
- cdp_get_response_body: 通过requestId获取完整响应体

## execute_script MAIN world
chrome.scripting.executeScript({world:'MAIN'})在页面主世界执行，可访问页面全局变量和函数，比content_script的隔离世界强大。

## 页面监控
MutationObserver+click/focusin/scroll事件(500ms防抖)+5秒定时器+visibilitychange+focus。活动标签页双重验证(本地isActiveTab + background VERIFY_ACTIVE_TAB)。

## 数据流（click为例）
AI→ChromeBridge.processToolCall→ws.send(command)→background.handleIncomingCommand→tabs.sendMessage→content_script.handleCommand→findElement(9策略)→dispatchEvent→COMMAND_RESULT→background转发→ChromeBridge标记commandExecuted→500ms后pageInfoUpdate→ChromeBridge.resolve(result+page_info)→AI
