[20:35] 扫描版PDF处理方案决策树与技术选型

## 背景
2026-05-09 在处理80MB扫描版《计算机网络（第8版）》教材时，经过完整的Marker OCR方案→PyMuPDF直读方案的对比测试，确立了扫描版PDF的最佳处理策略。

## 决策树
```
PDF文件
├── 文字版（可选中复制文字）
│   ├── 需要纯文本/Markdown → Marker（高精度OCR+布局识别）
│   └── 需要保留原版式 → PyMuPDF导图
└── 扫描版（每页是图片）
    ├── AI做教案/问答 → PyMuPDF导图 + AI视觉直读 ✅推荐
    ├── 需要全文搜索 → Marker OCR（有错字但勉强可搜）
    └── 需要正式文档 → 找文字版PDF / ABBYY FineReader专业OCR
```

## 核心结论
1. **扫描版PDF + AI场景 = PyMuPDF一步到位**：零错字、零依赖、瞬间导出
2. **Marker OCR不适合扫描版**：中文OCR错字严重（碰撞→碰梳、集线器→梊线器），断行错乱，GPU满载速度慢
3. **文字版PDF仍推荐Marker**：直接提取文字，速度快精度高

## 工具链总结
| 工具 | 最佳场景 | 不适合场景 |
|------|---------|-----------|
| PyMuPDF | 扫描版→图片→AI视觉 | 需要纯文本输出 |
| Marker | 文字版PDF→Markdown | 扫描版（OCR中文差） |
| pptx2md | PPT→Markdown | - |
| Pandoc | DOCX→Markdown | PDF（精度差） |
| markitdown | PPT快速读取（SkillBridge内置） | 不提取图片 |
| python-pptx | 从PPT提取图片 | 不做文本转换 |

## 扫描版PDF教案制作流程（已验证）
```
PyMuPDF按章节导出指定页码png（dpi=150）
→ UrlFetch逐张读图（支持file协议）
→ AI视觉直接理解文字+图片+公式
→ 输出教案/知识点整理
```

## 关键技术细节
- PyMuPDF：`fitz.open(pdf)[idx].get_pixmap(dpi=150).save(path)`
- Marker页码范围：`marker_single xxx.pdf --page_range 100-105`（从0开始）
- UrlFetch读本地图片：`url: file:///D:/output/page_101.png, mode: image`
- FileOperator读md**看不到图片**，只返回文本源码

## surya库Windows兼容性Bug记录
Marker依赖surya做OCR/布局识别，surya的s3.py存在Windows路径bug：
- 根因：`os.path.join(cache_dir, model_name)`混合正反斜杠，shutil.move失败
- 修复：对local_path和local_dir加`os.path.normpath()`
- 正确环境变量：MODEL_CACHE_DIR（surya用pydantic-settings，字段名=env var名）
- 错误环境变量：DATALAB_CACHE_DIR（无效）
- 修复后需清除__pycache__使patch生效
