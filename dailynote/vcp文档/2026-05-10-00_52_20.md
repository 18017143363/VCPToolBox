## 真实结论
Claude thinking 在 Dedalus `/v1/chat/completions` 端口可用。此前失败根因不是端口不支持，而是参数约束：
```text
max_tokens > thinking.budget_tokens
```

## 安全注入逻辑
位于 `do_proxy()` 的非 bypass 分支，即 Claude/Anthropic 普通 chat/completions 转发前。

逻辑概要：
1. 若模型名以 `anthropic/` 开头或包含 `claude`，且 `ENABLE_CLAUDE_THINKING=True`，进入处理。
2. 若前端未传 `thinking`，注入：
```json
{
  "thinking": {
    "type": "enabled",
    "budget_tokens": 1024
  }
}
```
3. 若前端已传 `thinking`，不覆盖其内容。
4. 读取 `thinking.budget_tokens`，若非法则回退到默认 1024。
5. 读取 `max_tokens` 或 `max_completion_tokens`。
6. 若未设置或 `current_max <= budget`，自动设置：
```python
body_json["max_tokens"] = budget + CLAUDE_THINKING_MIN_VISIBLE_TOKENS
```
默认即：
```text
1024 + 1024 = 2048
```
7. 重新序列化 `actual_body` 并转发。

## 踩坑记录
第一次 ApplyDiff 后，安全注入逻辑已落盘，但配置块没有改成功，仍是：
```python

```
而新逻辑引用了：

由于 `ENABLE_CLAUDE_THINKING=False` 时分支不会运行，`py_compile` 仍返回 OK，但一旦启用就会运行期 `NameError`。读回文件后发现该问题，随后修正 searchString 中 `/v1messages` 少斜杠的 typo，再次 ApplyDiff 成功替换配置块。

## 经验教训
1. provider-specific 参数失败时，必须读取真实错误体；本次关键错误是 `max_tokens must be greater than thinking.budget_tokens`。
2. `py_compile` 不能检查运行期常量引用是否存在；补丁后必须读回确认配置与调用点同步。
3. 对自动注入类代理逻辑，必须同时注入相关约束字段，否则一个合法字段也会因配套预算不合法而炸。
