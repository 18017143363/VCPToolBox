# PowerShell 5 写配置文件 UTF-8 BOM 问题

## 核心问题
PowerShell 5 的 `Out-File -Encoding utf8` 和 `Set-Content -Encoding UTF8` 会自动在文件开头添加 **BOM (Byte Order Mark)**，即3个字节 `EF BB BF`。

许多配置文件解析器（YAML、TOML、JSON等）**不能识别BOM**，会导致：
- cloudflared: config.yml解析失败 → 502 Bad Gateway
- 其他工具: 各种莫名其妙的解析错误

## 如何检测BOM
```powershell
$bytes = [System.IO.File]::ReadAllBytes("文件路径")
Write-Output "前3字节: $($bytes[0]) $($bytes[1]) $($bytes[2])"
# 如果是 239 187 191 就是BOM（EF BB BF的十进制）
# 正常应该直接是文件内容的首字符ASCII码
```

## 正确写法（无BOM UTF-8）
```powershell
# 方法1：WriteAllText（推荐）
$content = "你的配置内容"
[System.IO.File]::WriteAllText("文件路径", $content, (New-Object System.Text.UTF8Encoding $false))

# 方法2：WriteAllBytes（精确控制）
$bytes = [System.Text.Encoding]::UTF8.GetBytes($content)
[System.IO.File]::WriteAllBytes("文件路径", $bytes)
```

## 错误写法（会加BOM）
```powershell
# ❌ 这些都会加BOM！
$content | Out-File -FilePath "文件" -Encoding utf8
Set-Content -Path "文件" -Value $content -Encoding UTF8
```

## PowerShell 7 注意
PowerShell 7（pwsh）默认使用无BOM的UTF-8，不存在这个问题。但VCP的PowerShellExecutor可能使用的是PowerShell 5（powershell.exe），所以统一用WriteAllText最安全。

## 受影响的场景
| 文件类型 | 解析器 | 受BOM影响 |
|----------|--------|-----------|
| .yml/.yaml | cloudflared/docker | ✅ 是 |
| .toml | grok2api等Python项目 | ✅ 是 |
| .json | 大多数JSON解析器 | ✅ 是 |
| .env | dotenv | ✅ 是 |
| .bat | CMD | 可能有编码问题 |
| .txt | 看读取方式 | 视情况 |

## 实际案例
2026-03-02 CF Tunnel部署时，用Out-File写的config.yml导致cloudflared无法启动，所有子域名返回502。检查发现前3字节为239 187 191（BOM），改用WriteAllText后立即恢复正常。

## Rosa的经验总结
> 在VCP环境中通过PowerShellExecutor写任何配置文件，**一律用WriteAllText + UTF8Encoding($false)**，不要抱侥幸心理！这个坑Rosa踩了不止一次了...
