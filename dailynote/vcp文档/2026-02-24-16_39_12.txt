## 概述
DiscourseReader是Rosa为VCP开发的Discourse论坛阅读插件，让Agent通过Discourse JSON API高效获取论坛结构化数据，替代了ChromeBridge+ScreenPilot的低效浏览器操作方案。

## 5个命令
| 命令 | 功能 | 关键参数 |
|------|------|----------|
| ListCategories | 列出论坛所有板块 | base_url(可选) |
| ListTags | 列出所有标签(去重) | base_url(可选) |

| SearchForum | 搜索帖子 | keyword/base_url |

## 核心架构
```
Agent → DiscourseReader(stdio) → Puppeteer+Stealth(穿CF) → Discourse JSON API(User-Api-Key认证)
```
分工明确：Puppeteer+Stealth处理Cloudflare挑战，User-Api-Key header处理Discourse认证。

## 认证机制
### User API Key（推荐，永久有效）
- 通过RSA握手协议获取（Discourse官方标准协议）
- config.env配置：forum_{name}_api_key=xxx
- HTTP Header注入：User-Api-Key: xxx
- 永久有效，不受cookie过期/CF TLS指纹/session失效影响

### Cookie（备选）
- config.env配置：forum_{name}_cookie=xxx
- 域名模糊匹配（matchByDomain）
- 会受CF TLS指纹绑定影响，Puppeteer的JA3与Chrome不同

### 认证优先级
API Key > Cookie > 无认证

## 关键技术发现
1. VCP /v1/human/tool端点：认证用Key字段（VCP服务密码），不是API_Key（上游AI密钥）
2. 返回字段：original_plugin_output，不是result
3. cf_clearance cookie绑定浏览器TLS指纹(JA3)，Node.js带cf_clearance反而暴露指纹不匹配
4. TOOL_REQUEST字面量必须运行时动态拼接，否则被VCP截获执行
5. Discourse tag路由：/tag/{slug}/{id}.json，page=0会404
6. Discourse对象数组tags需要.map(x=>x.name)
7. User API Key认证的搜索配额显著高于cookie认证
8. API Key认证可访问更多内容（如二级帖从404变200，隐藏板块可见）

### writeJSON核心设计
Puppeteer先过CF(page.goto warmup) → page.evaluate内发fetch → **credentials:'omit'不带Cookie** → User-Api-Key header认证 → Discourse跳过CSRF检查
关键发现：Discourse后端(application_controller.rb)对有效API Key+无Cookie的请求自动跳过CSRF。带Cookie则走session路径强制CSRF。

### entryPoint格式注意
VCP Plugin.js只读entryPoint.command字段并split(' ')，忽略args字段。必须写成：
```json
"command": "node DiscourseReader.js"  // 正确
// "command": "node", "args": ["DiscourseReader.js"]  // 错误！args被忽略
```

## User API Key获取脚本
get_user_api_key.py：参数化Python脚本，支持任意Discourse论坛URL
流程：RSA 2048密钥对生成 → 授权URL构造 → 用户浏览器点击Authorize → RSA密文解密 → 得到永久Key
