## 核心定位
对正文中**远距离、低相关性**的AI输出进行摘要折叠，减少Token消耗同时保留上下文连贯性。

## 激活方式
在Agent的System Prompt中写入激活占位符：
- `[[ContextFoldingV2]]` — 使用默认阈值
- `[[ContextFoldingV2:0.6]]` — 覆盖阈值基准为0.6
- `{ {ContextFoldingV2} }` — 双花括号格式（可能被messageProcessor替换）
未写入占位符则完全不激活（零性能开销）。

## 工作流程（7步）
1. 检测System中的激活占位符（正则匹配，支持尾缀数字）
2. 识别所有assistant块并计算深度（depth=0最新，向前递增）
3. 过滤候选: depth >= FOLDING_MIN_DEPTH (默认3)，即最近3轮永不折叠
4. 构建上下文参考向量 = 最新user向量 × contextWeights[0] + 最新assistant向量 × contextWeights[1]
   默认权重: user 0.7, assistant 0.3（与RAGDiaryPlugin.mainSearchWeights对齐）
   跳过系统邀请指令（以"[系统邀请指令:]"开头的user消息）
5. 计算动态阈值: threshold = base + lWeight×L - sWeight×S
   - L = computeLogicDepth(contextVector)：逻辑深度，L高→阈值↑→更激进折叠
   - S = computeSemanticWidth(contextVector)：语义宽度，S高→阈值↓→保守保留
   - 阈值硬限: thresholdRange [0.40, 0.60]
6. 逐候选块处理:
   a. 净化内容(bridge.sanitize) → SHA-256哈希
   b. 获取向量: FoldingStore缓存 → bridge嵌入缓存 → embedding API
   c. 计算与上下文向量的余弦相似度
   d. similarity >= threshold → 保留原文
   e. similarity < threshold → 按摘要状态处理:
      - ready → 替换为 [VCP上下文语义折叠-本层摘要:xxx]
      - none/failed(retry<maxRetries) → 异步触发摘要生成
      - pending → 等待下一轮
7. 返回处理后的messages数组

## 异步摘要生成（非阻塞）
- 不阻塞当前POST请求，用setTimeout延迟执行
- 指数退避延迟: 1s → 3s → 9s (delay = 1000 × 3^retryCount)
- pendingHashes Set防止并发重复触发
- 状态机: none → pending → ready/failed
- 调用LLM API生成摘要（OpenAI兼容接口）

### 摘要Prompt设计
System: "上下文压缩器。输出单行格式：[VCP上下文语义折叠-本层摘要:摘要内容]"
规则：提取核心动作/关键实体/结论决策/工具调用结果，剥离寒暄/表情/语气词/格式/冗余解释
User: 用[等待摘要的原始文本:]和[原始文本结束]包裹原文（防注入+防幻觉）
输入截断: 最大4000字符
摘要限制: ≤100字

### 三级安全验证
1. **结构验证**: 正则匹配 /\[VCP上下文语义折叠-本层摘要:[\s\S]+?\]/
2. **内容验证**:
   - 长度: 2~1000字
   - 拒绝关键词检测: error/无法/抱歉/sorry/cannot/unable
   - 外部文本(标记外): includes严格检测
   - 内部摘要(标记内): 仅startsWith检测（避免误杀"分析了error处理"等合法内容）
3. **写入验证**: 通过前两级才返回有效摘要

## FoldingStore 迷你数据库
- 引擎: better-sqlite3
- WAL模式 + synchronous=NORMAL（高性能）
- 预编译语句缓存
- Schema:
  | 字段 | 类型 | 说明 |
  |------|------|------|
  | content_hash | TEXT PK | SHA-256 |
  | text_preview | TEXT | 前80字 |
  | vector | BLOB | Float32Array↔Buffer |
  | summary | TEXT | 摘要文本 |
  | summary_status | TEXT | none/pending/ready/failed |
  | retry_count | INTEGER | 重试次数 |
  | created_at | INTEGER | 创建时间 |
  | updated_at | INTEGER | 更新时间(LRU) |
- 容量: maxEntries=200, evictCount=20
- LRU淘汰: 超过200条删除最旧20条
- getEntry时自动touchUpdated维持LRU
- 数据库损坏自动删除重建
- 由RAGDiaryPlugin初始化管理，通过ContextBridge暴露

## 热参数调控（rag_params.json）
| 参数 | 默认值 | 说明 |
|------|--------|------|
| thresholdBase | 0.50 | 阈值基准 |
| thresholdRange | [0.40, 0.60] | 阈值硬限范围 |
| lWeight | 0.05 | 逻辑深度权重 |
