[00:21] Dedalus 代理 Claude /v1/messages 适配失败后的最小回退记录

## 背景
此前为解决 Claude thinking 在 `/v1/chat/completions` 触发 422 的问题，尝试将 Claude/Anthropic 模型从前端 OpenAI 兼容入口：
```text
POST /v1/chat/completions
```
在代理内部转换为：
```text
POST /v1/messages
```
并将 OpenAI chat 请求体转换成 Anthropic Messages 风格，同时自动注入：
```json
"thinking": {
  "type": "enabled",
  "budget_tokens": 4096
}
```

## 实测结果
主人反馈：`/v1/messages` 端口适配走不通，需要回退。

## 回退原则
不整文件恢复旧备份，避免丢失已经确认有效的修复：
- sticky key：正常请求固定使用当前 key，只有 402 才删除并切换下一个 key。
- 413 修复：`web.Application(client_max_size=50 * 1024 ** 2)`。
- `[UPSTREAM_ERROR]` 上游错误体日志。

采用最小安全回退：只关闭 messages endpoint 分支和 thinking 自动注入。

## 修改文件
`E:\酒馆部署\dedalus-proxy\dedalus_proxy.py`

## 修改内容
将：
```python
USE_CLAUDE_MESSAGES_ENDPOINT = True
ENABLE_CLAUDE_THINKING = True
CLAUDE_THINKING_BUDGET = 4096
```
改为：
```python
# 回退：/v1/messages 适配实测走不通，恢复 Claude 普通 chat/completions 直连。
# 同时保持 thinking 自动注入关闭，避免再次触发 422。
USE_CLAUDE_MESSAGES_ENDPOINT = False
ENABLE_CLAUDE_THINKING = False
CLAUDE_THINKING_BUDGET = 4096
```

## 当前行为
- Claude/Anthropic 模型不再内部转发到 `/v1/messages`。
- Claude/Anthropic 模型不再自动注入 `thinking`。
- 前端请求 Claude 时恢复普通 `/v1/chat/completions` 直连。
- 如果前端显式携带 `thinking`，当前非 messages 分支不会删除它，会原样透传，但建议暂时不要传，以免再次触发 422。

## 残留代码说明
`is_claude_model()`、`chat_request_to_anthropic_messages()`、`anthropic_message_to_chat()`、`convert_anthropic_sse_to_chat_sse()` 等 messages 适配函数仍留在文件中，但由于：
```python
USE_CLAUDE_MESSAGES_ENDPOINT = False
```
相关分支不会执行。暂不清理 dead code，避免在回退时引入新的误删风险。后续若需要代码整洁，可单独做一次清理补丁。

## 经验教训
1. API 端口“可直接请求”不等于 OpenAI→Anthropic 自动转换层就一定兼容；真实请求 schema、流式事件格式、工具调用格式都可能有差异。
2. 回退时优先使用开关最小化变更，不要整文件覆盖，否则容易误丢已验证有效的修复。
3. 对 provider-specific thinking 这类字段，应默认关闭自动注入，除非已经拿到完整可用请求样本并通过端到端测试。
