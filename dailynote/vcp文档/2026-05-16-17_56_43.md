[18:30] 教学讲义制作方法论：从资料摘要到可替代原资料的完整教学章节

## 核心概念
本方法论用于指导 Agent 根据课本、PPT、课堂材料、图片化资料等来源，制作“零基础可直接学习”的 Markdown 教案/讲义。其目标不是把资料压缩成摘要，而是把资料重构成一篇完整、顺滑、可教学、可复习、可应试的章节讲解。

一句话定义：
**课本与 PPT 是知识边界，讲义是重新设计后的教学章节。**

合格讲义的标准：
读者即使不再打开课本和 PPT，也能通过讲义掌握这两份资料覆盖的所有知识点、例题逻辑、易错点、考点和常见变式。

---

## 一、任务定位：不要写“资料综合摘要”

### 错误定位
很多 Agent 容易把讲义写成：
1. 把课本内容概括一遍；
2. 把 PPT 内容补几句；
3. 罗列若干表格；
4. 最后加一点易错点。

这种结果看似完整，实际只是“资料摘要”或“知识点汇编”。它的问题是：
- 学生读完仍然需要回去看课本/PPT；
- 例题没有被讲透；
- 知识之间缺少教学顺序；
- PPT 中的代码题、输出题、课堂陷阱容易遗漏；
- 没有把知识点转化成“会做题、会判断、会写代码”的能力。

### 正确定位
讲义应当是：
1. 用课本和 PPT 确定知识范围；
2. 用教学逻辑重新组织内容；
3. 把每个概念讲成“为什么需要它、它是什么、怎么写、为什么这样写、哪里会错、怎么考”；
4. 对例题逐行拆解；
5. 对易错点给出反例、正确写法和判断方法；
6. 最终形成一篇可以替代原始资料的学习章节。

## 二、资料使用原则：不显式堆来源，但必须隐式吃干净

### 不推荐在正文中频繁写
- “课本这里说……”
- “PPT 第几页说……”
- “来源于某页……”

原因：
这会让讲义变成资料映射表，阅读感很差，学生会觉得自己在看“资料整理”而不是“课程讲解”。

### 推荐做法
在写作后台建立资料映射，但正文自然融合。

后台应明确：
1. 课本章节覆盖哪些核心概念；
2. PPT 补充了哪些课堂强调点；
3. PPT 是否有课本没有的例题、输出题、错误示例；
4. 课本是否有 PPT 没展开的正式定义、表格、完整代码；
5. 两者是否顺序不同，需要按课本或教学逻辑重组。

正文中不必写来源，但必须体现两者内容：
- 课本负责正式概念、章节结构、完整例题；
- PPT负责课堂重点、类比、易错反例、输出题、常见考法；
- Agent负责拓展讲解、逐步推理、变式训练、学习路径。

## 三、标准工作流

### Step 1：锁定章节边界
先确认要写的是哪一节，而不是整章混写。

例如 Java 第 3 章中：
- 3.1 Java 主类结构；
- 3.2 基本数据类型；
- 3.3 变量与常量；
- 3.4 运算符；
- 3.5 数据类型转换；
- 3.6 代码注释与编码规范。

如果用户要求写 3.2，就不能把 3.3 或 3.4 的内容提前大段混进来。可以做必要预告，但不能喧宾夺主。

### Step 2：完整读取对应资料
对图片化资料，应按页或长图分批读取，避免只凭记忆写。

推荐建立内部清单：
- 本节课本页码范围；
- 本节 PPT 页码范围；
- 哪些 PPT 页是上一节/下一节，需要排除；
- 哪些内容跨节但与本节强相关，需要适度吸收。

### Step 3：整理“必须覆盖清单”
写讲义前先列出本节必须覆盖的知识点、例题、易错点和考法。

以 Java 3.2 基本数据类型为例，必须覆盖：
1. Java 强类型语言；
2. 8 种基本数据类型；
3. 整数类型 byte/short/int/long；
4. int 默认规则；
5. long 后缀 L；
6. 整数进制：十进制、八进制、十六进制；
7. 浮点类型 float/double；
8. double 常用；
9. float 后缀 F；
10. double 后缀 D；
11. 浮点近似误差；
12. Math.round 四舍五入；
13. Math.abs + 误差范围比较浮点数；
14. BMI 例题；
15. char 单字符规则；
16. char 与 String 区别；
17. Unicode；
18. char 与 int 互转；
19. 转义字符；
20. 字符、数字、字符串混合输出题；
21. boolean true/false；
22. boolean 不能与 int 直接转换；
23. boolean 与判断条件；
24. 编程训练题，如粮仓体积、个税判断。

如果讲义缺其中任何一项，就不能说完整覆盖资料。

### Step 4：按教学逻辑重构章节
不要机械照搬 PPT 顺序，也不要机械照搬课本顺序。应按“从零基础理解最顺”的路线重构。

推荐结构：
1. 本节要解决什么问题；
2. 为什么需要这个概念；
3. 总览表；
4. 分类型讲解；
5. 代码示例；
6. 原理解释；
7. 例题深讲；
8. 易错点；
9. 高频考法；
10. 自测题；
11. 本节总结。

## 四、单个知识点的标准写法

每个重要知识点不要只写定义。推荐使用以下模板：

### 1. 问题导入
先问“为什么需要它”。

例如：
为什么整数要分 byte、short、int、long？
为什么 float 后面要加 F？
为什么 char 用单引号而 String 用双引号？

### 2. 正式概念
给出准确但不晦涩的定义。

例如：
Java 中整数字面量默认是 int 类型。

### 3. 代码写法
必须给可运行或接近可运行的代码。

例如：
```java
long number = 8000000000L;
float height = 1.72F;
char c = 'A';
```

### 4. 逐步解释
解释每个关键符号为什么存在。

例如：
- L 表示该整数从一开始按 long 处理；
- F 表示该小数从一开始按 float 处理；
- 单引号表示 char；
- 双引号表示 String。

### 5. 反例与错误原因
必须写错误代码，而不只是说“容易错”。

例如：
```java
float f = 1.2;
char c = "A";
long x = 123456789 * 987654321;
```

然后解释为什么错。

### 6. 正确写法
紧跟正确版本。

例如：
```java
float f = 1.2F;
char c = 'A';
long x = 123456789L * 987654321L;
```

### 7. 考法与判断口诀
将知识转化为做题能力。

例如：
- 整数默认 int，小数默认 double；
- 左边 long 救不了右边 int 溢出；
- 遇到加号先看左右有没有字符串；
- char 遇到数字加法会按 Unicode 编码参与计算。

## 五、例题讲解标准：必须逐行拆，不许只贴代码

例题是教学讲义的核心，不是装饰。

### 不合格写法
只给出代码，然后总结一句：
“这个例子说明 double 和 int 可以一起运算。”

这不够。

### 合格写法
以 BMI 例题为例，应拆成：

1. 题目背景：根据身高和体重计算 BMI。
2. 公式解释：BMI = 体重 / (身高 × 身高)。
3. 数据类型选择：
   - height 为什么用 double；
   - weight 为什么可以用 int；
   - exponent 为什么必须用 double。
4. 表达式解释：
   - height * height 先算；
   - int 与 double 运算时结果变成 double；
   - 括号保证公式含义正确。
5. 输出解释：
   - 字符串与变量拼接；
   - System.out.println 与 System.out.print 区别可适度说明。
6. 条件判断：
   - exponent < 18.5 的结果是 boolean；
   - boolean 与后续流程控制的关系。
7. 变式题：
   - float height = 1.72; 为什么错；
   - int exponent = ... 为什么不合理；
   - weight / height * height 与 weight / (height * height) 是否相同。
8. 考点总结：
   - 类型选择；
   - 表达式类型提升；
   - 小数结果保存；
   - 括号影响运算顺序；
   - 比较表达式产生 boolean。

### 例题讲解最低要求
每个例题必须回答：
1. 为什么这么写？
2. 如果换一种写法会怎样？
3. 这题真正考什么？
4. 考试可能怎么变形？

## 六、输出题讲解标准：每一行都要给结果和原因

对 Java 这类语言基础课，PPT 常有输出题。不能只说“这类题常考”，必须逐行拆。

例如：
```java
System.out.println('a');
System.out.println('a' + 1);
System.out.println("hello" + 'a' + 1);
System.out.println('a' + 1 + "hello");
System.out.println("5+5=" + 5 + 5);
System.out.println(5 + 5 + "=5+5");
```

合格讲解必须包含：
1. 每行输出结果；
2. 每行为什么是这个结果；
3. 哪一步是字符转 Unicode 编码；
4. 哪一步是字符串拼接；
5. 为什么表达式从左到右计算；
6. 如何快速判断类似题。

最终形成口诀：
- 遇到 `+`，先看左右有没有字符串；
- 没有字符串，可能是数值加法；
- 有字符串，通常变成拼接；
- char 遇到数字加法，会按 Unicode 编码参与计算。

## 七、拓展的边界：可以比资料讲得完整，但不能脱离资料

用户要求“比课本和 PPT 讲得更完整，但不能脱离两者”。这意味着：

### 可以拓展
1. 增加通俗解释；
2. 增加反例；
3. 增加变式题；
4. 增加逐步推导；
5. 增加学习口诀；
6. 增加现实类比；
7. 增加题型总结；
8. 增加必要的前后知识连接。

### 不应脱离
1. 不要引入完全超纲的大量高级知识；
2. 不要把后续章节变成本节主体；
3. 不要因为自己懂更多就扩写成另一本书；
4. 不要加入课本/PPT完全没有铺垫的复杂机制。

例如 Java 3.2 中：
- 可以讲浮点误差、Math.round、Math.abs，因为 PPT 已出现；
- 可以讲 boolean 与 if 的关系，因为课本例题涉及流程判断；
- 不应展开 BigDecimal 的完整商业精度处理，因为这会超出本节边界，可只一句提示“精确金额后续可用专门方式处理”。

## 八、正文风格要求

### 应该像教学章节
语言应当是：
- 问题驱动；
- 逐步解释；
- 对零基础友好；
- 有代码；
- 有原因；
- 有反例；
- 有总结。

### 不应该像资料整理
避免：
- “资料来源一……资料来源二……”
- “PPT 提到……课本提到……”
- “此处对应第几页……”
- 大段照抄表格而无解释；
- 只列结论不讲为什么。

### 推荐语气
类似老师讲课：
- “为什么这里要这样写？”
- “这不是形式主义，而是为了……”
- “真正的过程是……”
- “这类题考的不是……而是……”
- “看到这种写法要警惕……”

## 九、质量检查表

写完后必须逐项检查：

### 覆盖性检查
- 是否覆盖课本所有小节？
- 是否覆盖 PPT 中所有补充点？
- 是否覆盖例题？
- 是否覆盖课堂输出题？
- 是否覆盖易错反例？
- 是否覆盖常见考法？

### 教学性检查
- 是否解释了为什么需要该知识？
- 是否有代码示例？
- 是否逐行解释核心代码？
- 是否说明错误写法为什么错？
- 是否给出正确写法？
- 是否能让零基础读者跟上？

### 应试性检查
- 是否总结了高频考点？
- 是否有判断题/选择题/代码分析题？
- 是否有变式题？
- 是否有做题口诀？

### 独立性检查
最关键的一问：
**如果学生不打开课本和 PPT，只看这份讲义，能否掌握本节所有考点？**

如果答案是否，讲义不合格。

## 十、失败案例复盘

本次 Java 3.2 讲义制作经历了三轮迭代：

### 第一轮：整章初稿
问题：
- 太像章节摘要；
- 部分内容缺失；
- 例题讲解不足；
- 没有完整替代课本/PPT。

### 第二轮：3.2 重制版
进步：
- 单独拆出 3.2；
- 补充了更多细节；
- 开始关注易错点。

仍然不合格：
- 仍然偏“资料综合”；
- 例题没有充分展开；
- PPT 的一些浮点细节和输出题讲得不够完整；
- 正文过于像“把两份资料简述一遍”。

### 第三轮：3.2 完整版
成功关键：
1. 不再显式强调来源位置；
2. 把课本/PPT当作备课边界；
3. 按完整教学章节重写；
4. 补齐浮点误差、Math.round、Math.abs、1e-6；
5. BMI 例题逐步拆；
6. char/String/Unicode/转义字符完整讲解；
7. 输出题逐行分析；
8. boolean 结合判断条件和编程训练；
9. 追加高频考点表、易错点、自测题。

用户评价：“写的很好”。

## 十一、可复用模板

以后制作任何章节讲义，可以使用以下模板：

```markdown
# 章节标题：从零基础到完整掌握

## 0. 本节要解决什么问题
用问题导入，不直接堆定义。

## 1. 为什么需要这个知识
讲现实场景、程序需求、学习意义。

## 2. 总览
用表格建立整体框架。

## 3. 核心概念一
### 3.1 概念
### 3.2 代码写法

同上。
```
