[19:36] Dedalus代理Vercel版 — NewAPI/ChatBox模型手动配置说明

## 背景
主人询问：Vercel版代理是否需要手动填写模型，以及哪些模型可用。

## 结论
当前Vercel代理只实现：
```text
POST /v1/chat/completions
```
并在内部转换到：
```text
Dedalus /v1/responses
```

它没有实现：
```text
GET /v1/models
```

因此 NewAPI/ChatBox 无法自动拉取模型列表，必须手动添加模型名。

## Base URL
推荐使用稳定别名：
```text
https://tempproxy111.vercel.app
```

完整接口：
```text
https://tempproxy111.vercel.app/v1/chat/completions
```

## 模型名语法
```text
[provider/]model[-search][(effort)]
```

### 解析规则
1. 先剥离括号里的 effort：
```text
gpt-5.4-search(xhigh) -> effort=xhigh
```
2. 再剥离 `-search`：
```text
gpt-5.4-search -> search=true
```
3. 最终上游模型：
```text
gpt-5.4
```

### 语义
- `-search`：自动注入 `tools=[{type:"web_search_preview"}]`
- `(high)/(xhigh)`：自动注入 `reasoning={effort:"...", summary:"auto"}`

## 推荐手动模型列表

### 基础模型
```text
gpt-5.4
gpt-5.4(high)
gpt-5.4(xhigh)
```

### 联网模型
```text
gpt-5.4-search(high)
gpt-5.4-search(xhigh)
```

其中 `gpt-5.4-search(high)` 已在 Vercel 线上环境实测成功。

### Pro模型
```text
gpt-5.4-pro(high)
gpt-5.4-pro(xhigh)
gpt-5.4-pro-search(high)
gpt-5.4-pro-search(xhigh)
```

Pro模型可能响应更慢，Vercel serverless环境更容易遇到超时，应谨慎作为默认模型。

## 建议默认模型
推荐先用：
```text
gpt-5.4-search(high)
```

理由：
- 已线上实测成功
- 支持联网
- high档比xhigh更稳
- 响应速度与能力较均衡

## 不建议添加的模型

### Realtime模型
```text
gpt-realtime-2
gpt-realtime-1.5
openai/gpt-realtime-2
openai/gpt-realtime-1.5
```

原因：之前已验证Dedalus未部署realtime协议栈，`/v1/realtime`与WebSocket均不可用。

### Audio模型
```text
openai/tts-1
openai/whisper-1
```

原因：这些模型虽然在Dedalus `/v1/audio/*` 端点可用，但Vercel代理只处理 chat/responses 路径，不处理文件上传与音频端点。

## 注意事项
1. 如果客户端/平台要求模型名不能含括号，应改造代理增加别名映射；当前版本未实现。
2. 如果要支持自动模型列表，需要新增 `GET /v1/models` handler。
3. PowerShell测试时不要直接 `--data-raw $json`，建议使用无BOM文件 + `--data-binary "@file"`，避免JSON转义问题。
