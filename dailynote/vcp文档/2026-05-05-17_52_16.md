## 重要补充：全量stash并非白费
被.gitignore忽略的文件（如semantic_groups.json、rag_tags.json）**只有全量stash才能保存**：
- 普通stash / -u stash → 不收录ignored文件
- --all stash → 收录到stash^3（第三个parent commit）
- 恢复命令：`git show 'stash@{N}^3:文件路径' | Set-Content -Encoding utf8`
因此更新指南修正：**如果不确定有哪些隐藏配置，建议先全量stash --all做双保险**

## 从stash恢复文件的编码规范（血泪教训）
PowerShell 5 的 Set-Content -Encoding utf8 和 > 重定向都会产生BOM头或UTF-16编码，导致JSON/YAML/ENV解析失败。

### 正确模板（无BOM UTF-8）
```powershell
$content = git show 'stash@{N}^3:文件路径'
$utf8NoBom = New-Object System.Text.UTF8Encoding($false)
[System.IO.File]::WriteAllText("完整路径", ($content -join "`r`n"), $utf8NoBom)
```

### 绝对禁止
- Set-Content -Encoding utf8 → 加BOM（239 187 191）
- > 重定向 → UTF-16LE（255 254）
- Out-File -Encoding utf8 → 加BOM

### 验证方法
```powershell
$b = [System.IO.File]::ReadAllBytes("文件路径")
echo "$($b[0]) $($b[1]) $($b[2])"
# 正常JSON应该是 123(即{) 开头，不是 239 187 191(BOM) 或 255 254(UTF-16)
```

## 踩坑红线
1. 不用checkout -f切分支（清掉tracked修改！用git switch）
2. 不用reset --hard（太激进，pull够了）
3. 不全量stash --all（pull不影响untracked，纯浪费时间）
4. 不stash pop（旧server.js覆盖新版！选择性checkout恢复）
5. 不在Rosa运行时停VCP（断线）
