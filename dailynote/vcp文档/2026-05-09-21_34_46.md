## 背景
此前为 `E:\酒馆部署\dedalus-proxy\dedalus_proxy.py` 在 `/v1/chat/completions` 直连分支中自动注入 Claude/Anthropic `thinking`：
```json
{
  "thinking": {

    "budget_tokens": 4096
```

但主人重启后，`anthropic/claude-opus-4-6` 请求返回 `422 296`。日志证据显示 `[THINKING] auto-enabled Claude thinking` 后紧接 `/v1/chat/completions` 422，说明 Chat Completions 兼容层不接受该 thinking 参数。

主人指出：可能不是 `thinking` 字段本身错，而是端口错了。Claude thinking 应该走 Anthropic Messages 风格的 `/v1/messages` 端口；主人表示该端口可以正常请求。

## 本次修改目标
保持前端/NewAPI 仍然使用 OpenAI 兼容入口：
```text

```
但代理内部对 Claude/Anthropic 模型单独转发：
```text
POST /v1/messages
```
同时在 messages 分支自动加入：
```json
"thinking": {
  "type": "enabled",
  "budget_tokens": 4096
}
```

## 新增函数
### 1. `is_claude_model(model: str) -> bool`
识别 Claude/Anthropic 模型：
- `model.lower().startswith("anthropic/")`
- 或模型名包含 `"claude"`

### 2. `chat_request_to_anthropic_messages(body: dict) -> dict`
将 OpenAI Chat Completions 请求体转换为 Anthropic Messages 风格：
- `messages` 中 `system/developer` 拆到顶层 `system`
- `user/assistant` 保留为 messages
- `tool` 暂降级为 `user`
- `max_tokens/max_completion_tokens` 映射为 `max_tokens`
- `stop` 映射为 `stop_sequences`
- 透传 `stream/temperature/top_p`
- 若前端显式传 `thinking` 则优先使用，否则按配置自动补 `thinking`

### 3. `anthropic_message_to_chat(resp_data, model)`
将非流式 Anthropic Messages JSON 响应转换为 OpenAI Chat Completions 响应：
- `content[].text` 拼接为 assistant message content
- `usage.input_tokens/output_tokens` 转为 `prompt_tokens/completion_tokens/total_tokens`
- `stop_reason` 转为 `finish_reason`

### 4. `convert_anthropic_sse_to_chat_sse(event_data, model, resp_id)`
将 Anthropic Messages SSE 事件转为 OpenAI chat.completion.chunk：
- `message_start` → role chunk
- `content_block_delta.delta.text` → content delta chunk
- `message_delta/message_stop` → finish chunk
- `message_stop` 附加 `data: [DONE]`

## 经验教训
`py_compile` 只能证明语法通过，不能证明运行期引用存在。批量补丁后必须读回检查关键函数和调用点是否同时存在，否则会出现“编译通过但一运行就 NameError”的假成功。
