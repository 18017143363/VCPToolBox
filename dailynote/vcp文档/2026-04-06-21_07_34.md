## 二、新增模块详解

### 2.1 auditor.js — 去偏见审计器 (12.79KB，v0.4最大新模块)
**核心使命**: 对抗Context Momentum Bias（上下文惯性偏见）。审计时**不携带Rolling Context**，独立比对原文vs摘要。

**三种抽样策略selectAuditSamples()**:
1. 矛盾信号(contradiction): 检测chunk中的转折词（however/but/although/但是/然而/局限/矛盾等，共22个关键词），命中越多score越高(×2)
2. 高压缩率(high_compression): 原文token÷摘要token>15x视为异常，可能遗漏重要内容
3. Triage边界(triage_boundary): 被Triage标记为skim但实际token>800的chunk，Triage可能误判

**审核流程auditChunk()**: LLM独立审核，三档判定:
- faithful: 摘要准确反映原文
- minor_gap: 有小遗漏不影响理解
- significant_bias: 存在重大偏差需修正

**findings类型**: omission(遗漏)/downplay(淡化)/misinterpret(误解)，每个含severity(high/medium/low)

**整体偏差评估**: high≥2或high≥1+medium≥3→significant; high≥1或medium≥2→mild; 其他→none

**patchContext()**: 将高严重度findings的correction注入Chunk_Summaries.json，标记audited:true并在key_facts中追加[AUDIT CORRECTION]前缀

**输出工件**: reading_notes/audit_report.json

### 2.2 triage.js — 分诊注意力分配 (10.17KB)
**核心使命**: 为每个章节分配deep/skim/skip阅读策略，避免全量精读浪费资源。

**核心设计原则**: Skim ≠ 跳过，Skim = 不写入Rolling Context

**依赖**: 需要tree_index.json（skeleton生成的树索引），没有则报错

**runTriage()流程**:
1. 读取tree_index.json → flattenTree()扁平化为节点列表
2. 过滤有chunk_range的actionable节点
3. 加载已读记录readLog，已深读的节点强制skip
4. LLM规划每个节点的read_mode(deep/skim/skip) + depends_on依赖关系
5. LLM失败时全部defaulting to deep（优雅降级）
6. 补全未被LLM标注的节点（默认deep）
7. 持久化attention_map.json

**topoSortReadOrder()**: Kahn算法拓扑排序
- 尊重depends_on约束（如Results依赖Methods先读）
- 同层级内deep优先于skim
- 处理循环依赖（追加剩余节点）

**expandToChunkPlan()**: 将节点级attentionMap展开为chunk级阅读计划
- [{chunkIndex, readMode, nodeId, section}]
- 先排topo顺序的deep+skim，再排skip

**输出工件**: reading_notes/attention_map.json

### 2.3 catalog.js — 全局文档索引 (4.77KB)
维护workspace/index/catalog.json。
四重反向索引Map: _byDocId / _byFingerprint / _bySlug / _byLegacyId
findAny()通用查找: doc_id → legacy_paperId → slug 三级fallback
upsertEntry(): 新增或更新条目，自动rebuildIndices
metaToCatalogEntry(): 从meta.json构建catalog条目

### 2.4 doc-id.js — xray.v1文档身份体系 (6.67KB)
**新ID格式**: xray-{YYYYMMDDTHHMMSS}-{slug8}（替代旧的paper-{sha1前10位}）
**slug生成**: 标题→小写→去标点→空格转连字符→截断48字→sha1取前8位
**source_fingerprint**: DOI > URL hash > 文件内容hash > 文件路径hash
**buildMeta()**: 构建xray.v1标准化meta.json（schema_version, source, parser等完整字段）
**generateFrontMatter()**: 生成YAML front matter注入到full_text.md头部
**classifyId()**: 判断ID类型 xray/legacy/custom

## 三、v0.4 Read命令完整流程
```
handleRead(paperId, goal)
  → generateSkeleton(骨架+树索引)
  → handleReadDeep(Rolling Context深度阅读)
  → runAudit(去偏见审计)
    ├─ selectAuditSamples(三策略抽样3-8个chunk)
    ├─ 逐chunk auditChunk(无Rolling Context！独立审核)
    ├─ 评估overallBias
    └─ 提取high severity corrections
  → patchContext(修正注入Chunk_Summaries)
  → 返回 {mode:'unified-read', content, audit, patch}
```

## 四、v0.4关键设计亮点
1. **Context Momentum Bias对抗**: Auditor故意不看Rolling Context，独立审核
2. **Triage智能分诊**: 不再全量精读，LLM决策deep/skim/skip
3. **拓扑排序阅读顺序**: 章节间依赖关系自动排列
4. **统一ID体系**: xray.v1替代旧的paper-*格式
5. **全局文档索引**: catalog.json多维查找+去重
6. **审计→修正闭环**: 发现偏差自动patch到摘要
