## 背景
`dedalus_proxy.py` 当前对 OpenAI 类模型启用 chat→responses bypass：
```text
前端 POST /v1/chat/completions
代理内部 POST /v1/responses
```
但 Dedalus 官方文档中 Chat Completions 使用的推理字段是：
```json
"reasoning_effort": "low|medium|high"
```
而 responses API 的真实 schema 未完全明确，因此不能直接原样透传。

## 上游 curl 实测结论

### 1. `/v1/chat/completions` 接受 `reasoning_effort`
请求：
```json
{
  "model": "openai/gpt-5.1",
  "messages": [{"role": "user", "content": "Reply with exactly five words."}],
  "reasoning_effort": "low",
  "max_tokens": 16,
  "stream": false
}
```
返回：
```http
HTTP/1.1 200 OK
```
usage 中：
```json
"completion_tokens_details": {
  "reasoning_tokens": 16
}
```
说明 Chat Completions 的 `reasoning_effort` 确实生效。

### 2. `/v1/chat/completions` 不支持 `prompt_mode`
请求若包含：
```json
"prompt_mode": "reasoning"
```
返回：
```json
{
  "code": "unsupported_provider_field",
  "message": "Unsupported fields for provider list ['openai']: prompt_mode."
}
```
因此代理不应默认透传 `prompt_mode`。

### 3. `/v1/responses` 顶层 `reasoning_effort` 会被悄悄忽略
请求：
```json
{
  "model": "openai/gpt-5.1",
  "input": "Reply with exactly five words.",
  "reasoning_effort": "low",
  "max_output_tokens": 64,
  "stream": false
}
```
返回：
```http
HTTP/1.1 200 OK
```
但响应中：
```json
"reasoning": {"effort": "none"},
"output_tokens_details": {"reasoning_tokens": 0}
```
结论：responses API 不吃顶层 `reasoning_effort`，且不会报错，只会静默忽略。

### 4. `/v1/responses` 嵌套 `reasoning.effort` 生效
请求：
```json
{
  "model": "openai/gpt-5.1",
  "input": "Reply with exactly five words.",
  "reasoning": {"effort": "low"},
  "max_output_tokens": 128,
  "stream": false
}
```
返回：
```http
HTTP/1.1 200 OK
```
响应中：
```json
"reasoning": {"effort": "low"},
"output_tokens_details": {"reasoning_tokens": 9}
```
结论：responses API 正确格式是：
```json
"reasoning": {
  "effort": "low"
}
```

## 注意事项
1. 不要传 `prompt_mode: "reasoning"`，实测 openai provider 不支持。
2. 不要使用模型名后缀 `-thinking`，此前 Claude 后缀触发 `unpriced_model`。
3. 开启 reasoning 后，reasoning tokens 会消耗 completion/output token 预算。`max_tokens=16` 时曾出现 16 个 token 全部被 reasoning 吃掉、assistant content 为空的情况。
4. 建议 reasoning 请求设置更高 token：
```json
"max_tokens": 512
```
复杂任务可设：
```json
"max_tokens": 1024
```

## 经验教训
1. Chat Completions 与 Responses API 的推理字段 schema 不同：前者是 `reasoning_effort`，后者是 `reasoning.effort`。
2. Dedalus responses 对未知/不适用字段可能静默忽略，不一定报错；必须看响应中的 `reasoning.effort` 和 `reasoning_tokens` 判断是否真的生效。
3. 代理做 endpoint 转换时，不能只按字段名机械透传，必须按目标 endpoint schema 做语义映射。
