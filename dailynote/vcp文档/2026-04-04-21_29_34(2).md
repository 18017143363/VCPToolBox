## 与synchronous插件的根本区别

ArxivDailyPapers是VCP的**static类型插件**，工作模式完全不同于PubMedSearch等synchronous插件：

| 维度 | synchronous(如PubMedSearch) | static(ArxivDailyPapers) |
|------|:---:|:---:|
| 触发方式 | AI发送工具调用请求 | VCP后台按cron定时自动执行 |
| 执行时机 | 对话中按需 | 每30分钟（与对话无关） |
| 输出方式 | stdout返回给当次工具调用 | stdout被缓存到staticPlaceholderValues |
| 消费方式 | 工具调用结果注入上下文 | 占位符替换注入system prompt |
| 生命周期 | 每次调用spawn一个进程 | 按cron周期性spawn |

### static插件在VCP中的工作流
```
Plugin.js initializeStaticPlugins()
    ↓
读取manifest中的cron: "*/30 * * * *"
    ↓
node-cron定时调度
    ↓
每30分钟spawn子进程: node ArxivDailyPapers.js
    ↓
子进程stdout输出 → 缓存到staticPlaceholderValues["ArxivDailyPapersData"]
    ↓
用户发消息时 → messageProcessor.js replaceOtherVariables()
    ↓
将system prompt中的{*2ArxivDailyPapersData}*2替换为缓存值
    ↓
AI在上下文中自动看到最新论文列表
```

## 源码实现分析 (ArxivDailyPapers.js)

### 1. 配置加载
```javascript
const dotenv = require('dotenv');
dotenv.config({ path: path.join(__dirname, 'config.env') });

const SEARCH_TERMS = process.env.ARXIV_SEARCH_TERMS || '...默认LLM/RAG相关...';
const MAX_RESULTS = parseInt(process.env.ARXIV_MAX_RESULTS) || 100;
const DAYS_RANGE = parseInt(process.env.ARXIV_DAYS_RANGE) || 1;
const DEBUG_MODE = process.env.ARXIV_DEBUG_MODE === 'true';
```

### 2. 日期范围计算
自动在搜索词后追加submittedDate范围过滤：
```javascript
const endDate = new Date();
const startDate = new Date();
startDate.setDate(startDate.getDate() - DAYS_RANGE);

// 格式化为arXiv要求的YYYYMMDDTTTT格式
const startStr = formatArxivDate(startDate);  // e.g. "202604010000"
const endStr = formatArxivDate(endDate);      // e.g. "202604040000"

// 追加到搜索词
const fullQuery = `${SEARCH_TERMS} AND submittedDate:[${startStr} TO ${endStr}]`;
```

### 3. arXiv API调用
```javascript
const apiUrl = `http://export.arxiv.org/api/query?search_query=${encodeURIComponent(fullQuery)}&start=0&max_results=${MAX_RESULTS}&sortBy=submittedDate&sortOrder=descending`;

const response = await fetch(apiUrl);
const xmlText = await response.text();
```
注意：arXiv API使用**HTTP**（非HTTPS），返回Atom XML格式。

### 4. XML解析（正则方式）
**没有使用xml2js等XML解析库**，而是用正则表达式直接从XML中提取：
```javascript
// 匹配所有<entry>块
const entryRegex = /<entry>([\s\S]*?)<\/entry>/g;

// 从每个entry中提取字段
const idMatch = entryText.match(/<id>(.*?)<\/id>/);
const titleMatch = entryText.match(/<title>(.*?)<\/title>/s);
const summaryMatch = entryText.match(/<summary>(.*?)<\/summary>/s);
const publishedMatch = entryText.match(/<published>(.*?)<\/published>/);

// 作者提取（多个）
const authorRegex = /<author>\s*<name>(.*?)<\/name>/g;
const authors = [];
let authorMatch;
while ((authorMatch = authorRegex.exec(entryText)) !== null) {
  authors.push(authorMatch[1].trim());
}

// 分类提取
const categoryRegex = /<category[^>]*term="([^"]*?)"/g;

// 链接提取：优先PDF链接
const linkRegex = /<link[^>]*href="([^"]*?)"[^>]*(?:title="([^"]*?)")?[^>]*\/>/g;
// 优先取title="pdf"的链接，fallback到abstract页面链接
```

### 5. 缓存机制
```javascript
const CACHE_FILE = path.join(__dirname, 'arxiv_papers.json');

// 成功时写入缓存
fs.writeFileSync(CACHE_FILE, JSON.stringify(papers, null, 2));

// API失败时从缓存读取
if (fs.existsSync(CACHE_FILE)) {
  const cached = JSON.parse(fs.readFileSync(CACHE_FILE, 'utf-8'));
  // 使用缓存数据
}
```
这保证了即使arXiv API暂时不可用，也能输出上次成功获取的论文列表。

### 6. 输出格式
stdout输出纯文本，格式化为人可读的论文列表：
```
=== arXiv Daily Papers ===
搜索词: ...
时间范围: YYYY-MM-DD ~ YYYY-MM-DD
共找到 N 篇论文

---
[1] 论文标题
作者: Author1, Author2, ...
日期: YYYY-MM-DD
分类: cs.CV, cs.LG
链接: https://arxiv.org/pdf/XXXX.XXXXX
摘要: ...

---
[2] ...
```

## 配置项详解

### ARXIV_SEARCH_TERMS
arXiv搜索表达式，支持完整的arXiv API查询语法：
- `all:("keyword")` — 全文搜索（标题+摘要+全文）
- `ti:"keyword"` — 仅标题搜索
- `abs:"keyword"` — 仅摘要搜索
- `au:"author name"` — 作者搜索
- `cat:cs.CV` — 分类过滤
- AND/OR/ANDNOT 逻辑运算
- 括号分组

示例：
```env
# TinyML相关
ARXIV_SEARCH_TERMS=all:("TinyML" OR "embedded neural network" OR "microcontroller inference")

# 计算机视觉+农业
ARXIV_SEARCH_TERMS=(all:("agricultural" OR "food quality") AND cat:cs.CV)
```

### ARXIV_MAX_RESULTS
单次最大返回论文数。arXiv API允许最大值约为30000，但建议保持在100以内避免超时。

### ARXIV_DAYS_RANGE
抓取最近N天提交的论文。设为1则只看今天的，设为7看一周的，设为30看一个月的。

## 技术细节与注意事项

### 为什么用正则而不用XML解析库
arXiv API返回的Atom XML结构相对简单且稳定，正则直接提取效率更高，且避免了引入xml2js等依赖。但代价是：
- 对XML格式变化不够鲁棒
- 多行匹配需要`/s`标志
- 嵌套结构处理有限

### arXiv API的速率限制
arXiv API没有严格的API Key机制，但有隐式速率限制。static插件30分钟调用一次，完全不会触发限制。

### submittedDate过滤
插件自动在搜索词后追加日期范围，这意味着：
- 用户配置的SEARCH_TERMS不需要包含日期
- 日期范围由DAYS_RANGE自动控制
- 使用submittedDate（提交日期）而非published/updated

### 与VCP折叠协议的关系
如果需要对论文列表做动态折叠（相关时展开、无关时收缩），可以将输出格式改为vcp_dynamic_fold JSON。但当前版本输出的是纯文本，不支持折叠。

## 设计亮点
1. **零配置即可运行**：有合理的默认搜索词和参数
2. **缓存保底**：API失败时从本地缓存读取，不中断服务
3. **日期自动管理**：自动计算时间范围，无需手动更新
4. **轻量实现**：无外部依赖（除dotenv），正则解析XML，整体代码约8KB
5. **被动推送模式**：AI无需主动查询，每次对话自动看到最新论文

## 与PubMedSearch的互补关系
| 维度 | ArxivDailyPapers | PubMedSearch |
|------|:---:|:---:|
| 数据源 | arXiv预印本 | PubMed/PMC正式发表 |
| 领域 | CS/ML/物理/数学为主 | 生物医学/药学/食品科学 |
| 交互模式 | 被动推送 | 主动查询 |
| 时效性 | 最新预印本（今日/本周） | 正式发表（有peer review） |
| 适用场景 | 追踪前沿趋势 | 查找权威引用 |
| 全文获取 | 通过链接跳转PDF | PMC开放获取可直接读 |
