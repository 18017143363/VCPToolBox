## 问题1: `/v1/chat/completions` 返回 Vercel 404

### 现象
初次测试：
```text
POST https://tempproxy111.vercel.app/v1/chat/completions
HTTP=404
The page could not be found
NOT_FOUND
```

### 根因
Vercel Serverless Function 文件路径为：
```text
api/v1/chat/completions.js
```
默认公网函数路径实际是：
```text
/api/v1/chat/completions
```
项目原始 `vercel.json` 没有配置 rewrite，因此 OpenAI兼容客户端常用的 `/v1/chat/completions` 无法命中函数。

### 修复
在 `vercel.json` 增加：
```json
"rewrites": [
  {
    "source": "/v1/(.*)",
    "destination": "/api/v1/$1"
  }
]
```

重新部署后：
```text
POST /v1/chat/completions 无key
HTTP=401
{"error":{"message":"Missing Authorization header","type":"missing_auth"}}
```
这证明 `/v1/*` rewrite 已经命中函数。

## 问题2: 有key请求返回 `Invalid JSON`

### 现象
初测有key请求返回：
```json
{"error":{"message":"Invalid JSON","type":"invalid_body"}}
```

### 排查
最初怀疑：
1. PowerShell `Out-File -Encoding utf8` 产生BOM；
2. Vercel req.body形态与 handler 不兼容；
3. Windows PowerShell 调用 curl.exe 时JSON字符串引号被破坏。

### handler修复
增强 `readJsonBody(req)`，兼容：
- `req.body` 为 object
- `req.body` 为 string
- `req.body` 为 Buffer
- 原始 request stream
- UTF-8 BOM

关键逻辑：
```js
const parseRaw = (raw) => {
  if (raw === undefined || raw === null || raw === '') return {};
  if (Buffer.isBuffer(raw)) raw = raw.toString('utf8');
  if (typeof raw !== 'string') return raw;
  if (raw.charCodeAt(0) === 0xFEFF) raw = raw.slice(1);
  if (!raw.trim()) return {};
  return JSON.parse(raw);
};
```

### 最终真实根因
使用 PowerShell 直接通过 `--data-raw $json` 传参仍容易触发 `Invalid JSON`；改用：
```powershell
[System.IO.File]::WriteAllText($req, $json, [System.Text.UTF8Encoding]::new($false))
curl.exe ... --data-binary "@$req"
```
后请求成功。  
结论：线上代理正常，PowerShell/curl 直接字符串传JSON存在转义/编码坑；建议测试统一使用无BOM文件 + `--data-binary @file`。
