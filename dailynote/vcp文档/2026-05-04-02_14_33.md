## VCPChrome对照结论
读取了 `E:\VCP\VCPChrome\background.js/content_script.js/manifest.json/popup.js`。
VCPChrome 范式：
1. background 作为 WebSocket 客户端连接 VCP。
2. 默认地址 `ws://localhost:8088/vcp-chrome-observer/VCP_Key=...`。
3. 服务器下发 `type:"command"`。
4. background 将指令转发给 content_script。
5. content_script 执行 click/type/open_url 这类页面语义控制。
6. 30秒心跳。

Neural Phantom 采用相同“浏览器端主动连接VCP”的方向，但未复用 VCPChrome 协议，因为NP能力域是逆向抓包、请求操控、安全审计、加密链路，不是普通页面交互。因此使用独立 `np-bridge` 协议和41指令体系。

## NP端Connector三层实现
1. 查询类命令：
   - 直接访问 background 全局状态：
     `globalLogs`, `contentCache`, `wsLogs`, `paramTraceStore`, `funcTraceStore`, `MediaChainEngine`, `SecurityHeaders`, `VulnScanner`, `EndpointExtractor`, `ParamMiner`。
2. 控制类命令：
   - 使用 `chrome.scripting.executeScript({world:"MAIN"})` 在页面 MAIN world 执行 `window.postMessage`。
   - page-script 已确认接收：
     - `UPDATE_MOCK_RULES`
     - `UPDATE_LOCAL_FILE_RULES`
     - `UPDATE_WS_RULES`
     - `DUMP_STORAGE`
     - `ABORT_REQUEST`
     - `UPDATE_DYNAMIC_SCRIPT`
     - `TOGGLE_BREAKPOINT`
     - `RESUME_REQUEST`
     - `ADD_REDIRECT_RULE`
     - `REPLAY_REQUEST`
     - `TRACE_FUNCTION`
     - `WS_FRAME_RESUME`
     - `WS_FRAME_ABORT`
3. 主动推送：
   - hook `updateLogs` 推送 `REQUEST_CAPTURED`。
   - hook `contentCache.set` 推送 body-ready enriched request，并扫描 KeyHunter。
   - hook `chrome.runtime.sendMessage` 观察 `KEY_FOUND/SENSITIVE_FIELD_FOUND/WS_FRAME/CHAIN_PUSH_EVENT`，转为 VCP 事件。

## 真实字段结构
- Mock规则：`{ urlKeyword, responseBody, enabled }`
- 本地文件替换：`{ urlKeyword, content, fileName, enabled }`
- WS改写规则：`{ urlKeyword, direction, rewriteBody, enabled }`
- 请求断点：`{ type:'TOGGLE_BREAKPOINT', enabled, filter }`
- 恢复请求：`{ type:'RESUME_REQUEST', requestId, modifiedData:{ url, body, headers } }`
- URL替换：`{ type:'ADD_REDIRECT_RULE', original, clean }`

## 重要经验
1. FileOperator SearchFiles 对 `E:\VCP\VCPChrome` 曾返回0结果，但 ListDirectory/PowerShell 证明目录实际有文件。遇到本地搜索异常要用多工具交叉验证。
2. ChromeBridge 的 `registerRoutes` 第二参数是真实 config，不是 admin router；新插件不能凭空假设参数签名。
3. NP page-script 控制字段必须从真实源码确认，不能只靠分析报告，否则会出现“命令返回成功但页面无效果”的半残状态。
4. config.env 最好使用纯 ASCII，尤其是插件配置 key/value 附近不要写中文注释，避免编码/换行污染。
