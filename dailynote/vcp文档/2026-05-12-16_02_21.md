## 背景
主人要求测试“思维链/推理预算”的正确传参方式。此前 Dedalus `gpt-5.4-pro` MCP 全网深搜任务在约 420 秒时 curl 56 / HTTP 000 / peer reset，无法判断是否为 `xhigh` 参数错误。因此本次拆成最小探针，只测试 reasoning 参数，不混入 web search、大 prompt 或高输出。

## 结论
Dedalus `/v1/responses` 中，`openai/gpt-5.4-pro` 的正确 reasoning 参数是 Responses API 风格的嵌套对象：

```json
"reasoning": {
  "effort": "xhigh"
}
```

顶层字段：

```json
"reasoning_effort": "xhigh"
```

在 `/v1/responses` 中不会报错，但会被静默忽略，实际返回仍是默认：

```json
"reasoning": {
  "effort": "medium"
}
```

此外，`openai/gpt-5.4-pro` 不是 Chat Completions 模型，不能走 `/v1/chat/completions`。

## 推荐 payload
用于 Dedalus `gpt-5.4-pro` 高推理任务：

```json

  "model": "openai/gpt-5.4-pro",
  "input": "任务内容",
```

## 重要工程注意
1. `/v1/responses` 使用 `reasoning.effort`，不是顶层 `reasoning_effort`。
2. 顶层 `reasoning_effort` 在 Responses 中会被静默忽略，必须检查响应里的 `reasoning.effort`。
3. 判断 reasoning 是否实际生效，应检查：
```json
usage.output_tokens_details.reasoning_tokens
```
以及响应：
```json
reasoning.effort
```
4. `gpt-5.4-pro` 不能走 `/v1/chat/completions`，应使用 `/v1/responses`。
5. 此结论说明此前 MCP 深搜任务的失败不是 `xhigh` 参数错误，更可能是 `xhigh + web_search high + 超大 prompt + 12000 输出` 导致长时间无首包后被连接层 reset。
