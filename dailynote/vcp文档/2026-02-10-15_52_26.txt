# VCP 语义组(semantic_groups) 配置与重构指南

（说明：本文档中 {*2 = {{，}*2 = }}）

## 概述

语义组(semantic_groups)是VCP RAG系统的核心配置之一，用于提升记忆检索的精准度。通过将语义相近的词汇聚类为"组"，RAG在检索时可以理解同义词和相关概念，从而召回更精准的记忆片段。

## 文件位置

```
E:\VCP\semantic_groups.json
```

## 数据结构

```json
[
  {
    "name": "组名",
    "terms": ["词汇1", "词汇2", "词汇3", ...],
    "vector": [0.123, -0.456, ...]  // 自动计算，无需手动填写
  }
]
```

### 字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| name | string | 语义组名称，描述这组词汇的共同主题 |
| terms | string[] | 语义相近的词汇列表 |
| vector | number[] | 由Embedding API自动计算的向量表示（重启VCP时自动生成） |

## 语义组设计原则

### 1. 词汇要具体，不要抽象
- ❌ "技术" → 太宽泛，什么都能匹配
- ✅ "RAG, 向量检索, embedding, 语义搜索" → 精准聚焦RAG领域

### 2. 同一组内词汇要语义相近
- ✅ ["插件", "plugin", "manifest", "entryPoint", "capabilities"] → 都是插件系统概念
- ❌ ["插件", "日记", "论坛"] → 三个不同领域混在一起

### 3. 组的数量要适中
- 太少：覆盖不足，很多查询无法匹配到语义组
- 太多：组间重叠严重，降低区分度
- 建议：20-35个组为宜

### 4. 中英文混合
VCP系统中很多概念有中英文两种表达，建议同时包含：
- ["消息处理", "messageProcessor", "message pipeline", "消息管道"]

## 向量计算注意事项

### 限流问题
重启VCP后，新增的语义组会自动调用Embedding API计算向量。如果一次新增太多组（>10个），可能触发API限流（403错误）。

### 解决方案
- 已有向量的组会跳过计算
- 多次重启VCP，每次只计算剩余的组
- 通常2-3次重启即可全部完成

### 验证方法
检查 `semantic_groups.json` 中每个组的 `vector` 字段是否已填充（非空数组）。

## 维护建议

1. **定期审查**：每月检查一次，删除不再相关的组
2. **新增时机**：当发现某类查询总是检索不到相关记忆时，考虑新增语义组
3. **编辑方式**：直接编辑 `semantic_groups.json`（或创建 `.edit.json` 由系统合并），重启VCP生效
4. **备份**：修改前备份原文件
