[20:01] Dedalus代理Vercel版 — 新增 GET /v1/models 硬编码模型列表接口

## 背景
此前Vercel代理只实现 `POST /v1/chat/completions`，未实现 `GET /v1/models`，NewAPI/ChatBox无法自动拉取模型列表。主人要求新增models列表，硬编码即可，普通版和pro版都全加。

## 本地改动
新增文件：
```text
E:\酒馆部署\dedalus-proxy-vercel\api\v1\models.js
```

已有 `vercel.json` rewrite：
```json
{
  "source": "/v1/(.*)",
  "destination": "/api/v1/$1"
}
```
因此新增的 `/api/v1/models` 会以 OpenAI 标准路径 `/v1/models` 暴露。

同时把 CORS methods 从：
```json
POST, OPTIONS
```
改为：
```json
GET, POST, OPTIONS
```

## models.js 行为
- `GET`：返回OpenAI兼容模型列表
- `OPTIONS`：返回204用于CORS
- 其他方法：返回405 method_not_allowed

响应格式：
```json
{
  "object": "list",
  "data": [
    {
      "id": "gpt-5.4-search(high)",
      "object": "model",
      "created": 1779000000,
      "owned_by": "dedalus-proxy"
    }
  ]
}
```

## 注意事项
1. 模型列表按主人要求“全加上”，但上游不一定支持所有effort组合。
2. 之前实测 `gpt-5.4-pro(none)`、`gpt-5.4-pro(low)` 这类低档位可能被上游拒绝；列表显示不等于上游一定可调用。
3. 如果NewAPI仍不能自动拉模型，需要检查NewAPI是否请求 `/v1/models` 以及是否要求更多字段。
4. 当前 `/v1/models` 不需要Authorization，符合多数OpenAI兼容客户端的模型发现习惯。
