## 权限验证结论
通过 WPS 页面内 `window.__WPSENV__.request` 正门调用：
`/api/v3/office/file/{fileId}/download`
结果连续返回：
- HTTP 403
- body.errno=10000
- msg=`no download permission`
- result=`permissionDenied`

当前 ACL：
- read=true
- share=true
- identify=true
- 缺少 download/saveas/copy
配置：
- isShowDownloadBtn=false
- isShowHistoryDownload=false

源码验证：
WPS 前端 canDownload/canSaveAs 判断并非只看按钮显示，而是依赖 session 权限与 `window.fileInfo.user_acl.download/saveas` 双重满足。
因此原始 PPTX 正常下载不可行；继续猜 URL 或裸 fetch 没意义。

## 尝试过的路径
1. 直接下载 NPBridge 抓到的 preview URL：
   - 得到 11.57KB HTML 预览壳。
2. 下载 WebOffice office URL：
   - 得到 63.05KB WPS 协作文档 HTML 壳。
3. 使用裸 fetch 访问 `/weboffice/api/...`：
   - 因未走 WPS request/httpencrypt 封装，容易得到 DriverNetError/InvalidArgument/404。
4. 使用 WPS 自身 request 层：
   - 可读取文件信息；
   - 下载接口被后端 ACL 明确拒绝。

## 降级策略
当原始文件下载被 ACL 拒绝，但页面可正常显示时：
1. 不绕过权限，不伪造下载；
2. 改为提取页面已合法显示的可见内容；
3. 对 WPS PPT，可提取 `.thumbnail_slide .thumbnail_view svg` 生成离线 SVG 预览 HTML；
4. 如 SVG 懒加载不足，需要先滚动预热；
5. 最终文件必须落盘验证，避免空壳。

## 经验教训
- 下载任务不能只看“脚本执行成功”或“浏览器触发下载”，必须 FileInfo 验证大小。
- 同名浏览器下载会自动编号，需 Everything 通配搜索。
- 对权限问题以后端真实接口响应为准，不能把前端隐藏按钮当成唯一证据。
- 对复杂对象结果必须 JSON.stringify 后返回，避免 VCP 汇总丢失细节。
