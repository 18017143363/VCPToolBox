[23:59] VCP Code 2.0 CLI后端启动机制与配置持久化

## 架构发现
VCP Code 2.0的配置不是存在VS Code的globalState里，而是通过一个独立的CLI后端进程管理。

## 完整配置链路
```
Webview UI (ProvidersTab.tsx) 
  → postMessage("updateConfig") 
  → KiloProvider.handleUpdateConfig() 
  → httpClient.updateConfig() 
  → HTTP POST到CLI后端 
  → CLI写入磁盘 config.json
```

## CLI后端启动流程
文件: `packages/kilo-vscode/src/services/cli-backend/server-manager.ts`

1. `getCliPath()` → `{extensionPath}/bin/VCP.exe`（Windows）
2. `spawn(cliPath, ["serve", "--port", "0"])` 启动进程
3. 每次启动生成随机密码(32字节hex)
4. 通过stdout解析端口号
5. 30秒超时保护
6. 创建HttpClient连接到 `http://127.0.0.1:{port}`

## 配置存储路径
文件: `packages/opencode/src/global/index.ts`
```
const app = "kilo"
const config = path.join(xdgConfig, app)  // Windows: %APPDATA%/kilo/
```
配置文件: `%APPDATA%/kilo/config.json`（通过xdg-basedir库）

## 关键Bug记录
实际安装的扩展bin目录下文件名是`kilo.exe`，但源码期望`VCP.exe`。
文件名不匹配导致CLI后端从未启动，配置无法持久化。
修复：重命名 kilo.exe → VCP.exe
