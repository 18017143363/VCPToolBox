# Cloudflare Tunnel 内网穿透部署教程

## 概述
CF Tunnel是Cloudflare提供的免费内网穿透方案，通过在本地运行cloudflared客户端，将本地服务安全地暴露到公网。

**核心优势**:
| 对比项 | 传统端口映射(frp) | CF Tunnel |
|--------|-------------------|-----------|
| 暴露真实IP | 是 | 否，完全隐藏 |
| DDoS防护 | 无 | CF自带 |
| SSL证书 | 需自配 | 自动提供 |
| 端口扫描风险 | 有 | 无开放端口 |
| WAF防火墙 | 无 | 免费基础WAF |
| 费用 | 看方案 | 免费 |

## 前置条件
1. 一个域名（任意注册商）
2. Cloudflare账号
3. 本地运行的服务

## 步骤一：域名接入Cloudflare
1. 登录 dash.cloudflare.com
2. 点击 **"+ Onboard a domain"**（注意：不是搜索框，不是Buy a domain！）
3. 输入域名 → 选Quick scan → Continue
4. 选 **Free** 计划 → Select plan
5. CF扫描DNS记录 → Continue to activation
6. CF给出两个NS记录，例如：
   - barbara.ns.cloudflare.com
   - dante.ns.cloudflare.com
7. 去域名注册商修改NS服务器为CF给的这两个
8. 回CF点"I updated my nameservers"
9. 等待NS传播（几分钟到几小时）

**踩坑**：域名输入时如果报"Invalid domain"，检查是不是在错误的输入框里输入了（搜索框 vs Onboard按钮）

## 步骤二：安装cloudflared
**建议不要装C盘！** 可以放在统一的部署目录。

### 方法：直接下载exe
```powershell
# 创建目录
New-Item -ItemType Directory -Path "E:\你的部署目录\cloudflared" -Force
# 下载（从GitHub Releases）
Invoke-WebRequest -Uri "https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-windows-amd64.exe" -OutFile "E:\你的部署目录\cloudflared\cloudflared.exe"
# 验证
& "E:\你的部署目录\cloudflared\cloudflared.exe" --version
```

## 步骤三：登录CF账户
```powershell
& "路径\cloudflared.exe" tunnel login
```
- 自动弹出浏览器 → 选择域名 → 授权
- 证书保存到 `C:\Users\用户名\.cloudflared\cert.pem`

## 步骤四：创建Tunnel
```powershell
& "路径\cloudflared.exe" tunnel create 隧道名
```
- 生成Tunnel ID（UUID格式）
- 凭证保存到 `C:\Users\用户名\.cloudflared\<Tunnel-ID>.json`

## 步骤五：添加DNS路由
```powershell
# 每个子域名执行一次
& "路径\cloudflared.exe" tunnel route dns 隧道名 子域名.你的域名
```
会自动在CF创建CNAME记录。

## 步骤六：编写config.yml
**位置**：`C:\Users\用户名\.cloudflared\config.yml`

**⚠️ 极其重要：不能用PowerShell 5的Out-File写！会加BOM头导致cloudflared解析失败！**

正确写法：
```powershell
$config = "tunnel: <Tunnel-ID>`ncredentials-file: C:\Users\用户名\.cloudflared\<Tunnel-ID>.json`n`ningress:`n  - hostname: xxx.域名`n    service: http://localhost:端口`n  - service: http_status:404`n"
[System.IO.File]::WriteAllText("C:\Users\用户名\.cloudflared\config.yml", $config, (New-Object System.Text.UTF8Encoding $false))
```

**config.yml格式**：
```yaml
tunnel: <Tunnel-ID>
credentials-file: <凭证文件完整路径>

ingress:
  - hostname: vcp.example.com
    service: http://localhost:6005
  - hostname: api.example.com
    service: http://localhost:3000
  - service: http_status:404    # 兜底规则，必须有！
```

## 步骤七：启动Tunnel
```powershell
& "路径\cloudflared.exe" tunnel run 隧道名
```
看到 `Registered tunnel connection` 就成功了！

## 启动脚本模板
```batch
@echo off
title CF Tunnel
"E:\部署目录\cloudflared\cloudflared.exe" tunnel run 隧道名
pause
```

## 常见问题
| 问题 | 原因 | 解决 |
|------|------|------|
| 502 Bad Gateway | config.yml有BOM头或格式错误 | 用WriteAllText无BOM写入 |
| 502 Bad Gateway | credentials-file路径被截断换行 | 确保路径在一行内 |
| Invalid domain | 在搜索框而非Onboard按钮输入 | 点蓝色Onboard a domain按钮 |
| NS未生效 | 传播需要时间 | 等几分钟，不影响创建Tunnel |
| 连接数警告 | 免费版限2个HA连接 | 无影响，正常使用 |
| root certificate pool警告 | Windows特性 | 忽略，不影响功能 |
| QUIC频繁断开 | 代理软件干扰UDP流量 | 启动时清除代理环境变量 |
| TLS handshake EOF | 代理拦截HTTP/2的TCP连接 | 同上，清除代理后用QUIC |

## ⚠️ 代理环境重要提醒
如果电脑上运行了代理软件（Clash/V2Ray/SSR等），**必须确保cloudflared不走代理**！
代理会干扰cloudflared与CF边缘节点的连接：
- QUIC(UDP)：被部分干扰，表现为频繁断开重连
- HTTP/2(TCP)：被完全拦截，TLS握手EOF

启动脚本中加入：
```batch
set HTTP_PROXY=
set HTTPS_PROXY=
set NO_PROXY=*
```

## 安全建议
1. 穿透后的服务务必有认证机制（密码/API Key）
2. 高危服务（API反代等）考虑加CF Zero Trust Access
3. 不需要公网访问的服务不要穿透（最小暴露原则）
