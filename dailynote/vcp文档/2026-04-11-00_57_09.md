## 设计模式：synchronous + static 配对
这两个插件展示了VCP插件系统的经典配对范式：
- ScheduleManager(synchronous): AI主动调用→CRUD操作→写入共享数据文件
- ScheduleBriefing(static): 定时自动执行→读取共享数据→清理+提取→占位符注入System Prompt

## 共享数据
数据文件: ScheduleManager/schedules.json
ScheduleBriefing通过 `path.join(__dirname, '..', 'ScheduleManager', 'schedules.json')` 跨目录引用。
数据结构:
```json
[
  { "id": "1735564800000", "time": "2026-04-15 14:00", "content": "开会" }
]
```
ID为Date.now()毫秒时间戳字符串。

## ScheduleManager 命令
### AddSchedule
参数: time(字符串,必需,YYYY-MM-DD HH:mm), content(字符串,必需)
功能: 添加日程→自动按时间升序排序→写入schedules.json
校验: 正则 /^\d{4}-\d{1,2}-\d{1,2}/ 简单检测年月日开头

### DeleteSchedule
参数: id(字符串,必需,时间戳)
功能: filter过滤删除→写回

### ListSchedules
无参数
返回: 格式化列表 `[id] time: content`

## ScheduleBriefing 机制
Cron: `0 * * * *`（每整点）
占位符: {*2VCPNextSchedule}*2

每次执行:
1. 读取schedules.json
2. 过期清理: `scheduleTime > now` 过滤，无效时间戳的日程保留防误删
3. 若有清理则写回文件
4. 提取第一条（最近的）日程→stdout输出纯文本→VCP存入占位符

## 局限性
- 无Agent隔离: 全局共用一份schedules.json
- 无并发保护: 读-改-写无锁，多Agent同时操作可能数据丢失
- 无主动唤醒: 只注入占位符，不会在日程时间到达时唤醒Agent
- 跨目录引用: 硬编码相对路径，不够健壮

## 与HeartbeatSystem对比
ScheduleManager系列定位为"用户日程表"（被动展示），HeartbeatSystem定位为"Agent生物钟"（主动调度+唤醒）。
HeartbeatSystem相比额外具备: Agent数据隔离/FileLockManager并发锁/timed-contact唤醒/四时段规划/心跳记录。
