## 四路探测结果

- HTTP 404
- Body: `{"detail":"Not Found"}`
- 来源: Dedalus FastAPI业务层（JSON格式响应）

### Probe B: POST /v1/realtime（带model+voice+modalities）
- HTTP 404

- 来源: Dedalus业务层

### Probe C: GET /v1/realtime?model={encoded}（OpenAI官方WebSocket升级URL格式）
- HTTP 404
- Body: `{"detail":"Not Found"}`
- 来源: Dedalus业务层

### Probe D: WebSocket Upgrade（含Connection:Upgrade + Upgrade:websocket + Sec-WebSocket-*头）
- HTTP **403 Forbidden** 🔥
- Body: 空（Content-Length: 0）
- 来源: **Cloudflare边缘层**（text/plain响应类型 + 无JSON body + 无Dedalus业务标识）

## 🔍 微妙关键发现：ABC返回404但D返回403

不同状态码来自不同层级：

| 状态码 | 响应特征 | 拦截层级 | 含义 |
|--------|---------|---------|------|
| 404 + `{"detail":"Not Found"}` | application/json + FastAPI格式 | Dedalus业务层 | 路由表未注册 |
| 403 + Content-Length: 0 | text/plain + 无JSON | Cloudflare边缘层 | WebSocket升级被边缘拒绝 |

**解读**: 
- ABC请求穿过了CF边缘 → 进入Dedalus业务层 → FastAPI路由表里没有/v1/realtime → 业务层返回JSON 404
- D请求带了Upgrade:websocket头 → **CF边缘检测到WebSocket升级请求 → 直接拒绝（403）→ 请求根本没有进入Dedalus业务层**

**底层原理**: Cloudflare Workers默认不允许WebSocket穿透到后端Worker除非业务侧明确配置WebSocket binding。Dedalus用的是CF Worker代理架构（之前推断），从403行为可证实Dedalus没有为/v1/realtime开启CF WebSocket binding。

## 最终结论

**Dedalus的realtime协议栈完全未部署**：
1. FastAPI业务层未注册任何/v1/realtime系列路由
2. CF边缘层未开启WebSocket binding
3. 即使绕过两者，pricing table也未录入这两个模型的价格

这两个模型`openai/gpt-realtime-2`和`openai/gpt-realtime-1.5`在Dedalus上**就是挂名占位符**，任何方式都无法使用其realtime能力。
