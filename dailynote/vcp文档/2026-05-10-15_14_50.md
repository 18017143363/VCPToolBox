## 背景
文件：`E:\酒馆部署\dedalus-proxy\dedalus_proxy.py`
此前为规避 Claude thinking 在 Dedalus chat/completions 流式路径可能出现的 `json_invalid`/不稳定问题，代理在 Claude thinking 分支中将前端 `stream=true` 改写为上游 `stream=false`，再由代理合成 OpenAI 风格 SSE。这解决了兼容性，但导致用户体验变成“假流式”：必须等待上游完整 non-stream 响应后才一次性吐出内容。

## 目标
恢复真实上游流式输出，同时保留旧假流式逻辑作为可回退兜底。

## 根因定位
原逻辑位于 Claude thinking 安全注入分支：
```python
if body_json.get("stream"):
    body_json["stream"] = False
    body_json.pop("stream_options", None)
    force_claude_nonstream_sse = True
    log.info(f"[THINKING] force Claude thinking upstream non-stream, synthesize SSE | model={model_prefix}")
```
该逻辑会主动关闭上游流式，因此不是 aiohttp 不能流式，而是代理代码主动禁止了上游 stream。

## 最终补丁
新增配置开关：
```python
# False = Claude thinking 请求保持上游真实 stream；True = 上游 non-stream 后由代理合成 SSE（旧兜底）。
FORCE_CLAUDE_THINKING_NONSTREAM_SSE = False
```

替换流式强制分支为：
```python
# Claude thinking 默认保持上游真实 stream，避免代理“假流式”。
# 如果 Dedalus 上游流式路径再次出现 json_invalid/不稳定，可将
# FORCE_CLAUDE_THINKING_NONSTREAM_SSE 改为 True 回退到旧兜底：
# 上游 non-stream，代理合成 SSE。
if body_json.get("stream") and FORCE_CLAUDE_THINKING_NONSTREAM_SSE:
    body_json["stream"] = False
    body_json.pop("stream_options", None)
    force_claude_nonstream_sse = True
    log.info(f"[THINKING] force Claude thinking upstream non-stream, synthesize SSE | model={model_prefix}")
elif body_json.get("stream"):
    log.info(f"[THINKING] keep Claude thinking upstream true stream | model={model_prefix}")
```

## 回退方式
若 Dedalus 上游 Claude thinking 流式再次触发 `json_invalid` 或其他不稳定问题，将：
```python
FORCE_CLAUDE_THINKING_NONSTREAM_SSE = False
```
改为：
```python
FORCE_CLAUDE_THINKING_NONSTREAM_SSE = True
```
即可恢复旧兜底：上游 non-stream，代理合成 SSE。
