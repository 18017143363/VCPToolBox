[13:37] Dedalus `openai/gpt-5.4` Responses API 内置 `image_generation` 4K 实测

## 背景
主人询问：既然 `openai/gpt-5.4` 在 Dedalus `/v1/responses` 中可以调用内置 `image_generation` 工具，是否能通过该工具直接生成 4K 图片。

测试路径：
```text
POST https://api.dedaluslabs.ai/v1/responses
```

模型：
```text
openai/gpt-5.4
```

## 测试 1：显式传入 4K size
请求体核心：
```json
{
  "model": "openai/gpt-5.4",
  "input": "Generate a native 4K 3840x2160 image: a minimal blue circle centered on a white background. Do not add text.",
  "tools": [
    {
      "type": "image_generation",
      "size": "3840x2160"
    }
  ],
  "tool_choice": "auto",
  "max_output_tokens": 512,
  "stream": false
}
```

真实结果：
```text
HTTP_STATUS=400
TOTAL_TIME=2.611356
```

错误体：
```json
{
  "detail": {
    "error": {
      "message": "Error code: 400 - {'error': {'message': \"Invalid size '3840x2160'. Supported sizes are 1024x1024, 1024x1536, 1536x1024, and auto.\", 'type': 'image_generation_user_error', 'param': 'tools', 'code': 'invalid_value'}}",
      "type": "provider_error"
    }
  }
}
```

结论：
Responses 内置 `image_generation` 工具在 Dedalus/OpenAI provider 下不接受 `3840x2160`。该工具支持的尺寸枚举仅为：
```text
1024x1024
1024x1536
1536x1024
auto
```

## 测试 2：不传 size，仅在 prompt 中要求 4K
请求体核心：
```json
{
  "model": "openai/gpt-5.4",
  "input": "Use the image generation tool to create a native 4K 3840x2160 PNG image: a minimal blue circle centered on a white background. Do not add text. The final image should be exactly 3840 by 2160 pixels if possible.",
  "tools": [
    {
      "type": "image_generation"
    }
  ],
  "tool_choice": "auto",
  "max_output_tokens": 512,
  "stream": false
}
```

真实结果：
```text
HTTP_STATUS=200
TOTAL_TIME=24.806849
```

响应信息：
```text
model = gpt-5.4-2026-03-05
outputTypes = image_generation_call,message
image_generation_call.result = base64 PNG
```

解码结果：
```text
decoded image path:
E:\\VCP\\temp\\dedalus_gpt54_response_image_4k_probe\\decoded_prompt_only_4k_no_size.png

actual size:
1536x1024
```

summary 关键字段：
```json
{
  "width": 1536,
  "height": 1024,
  "model": "gpt-5.4-2026-03-05",
  "outputTypes": [
    "image_generation_call",
    "message"
  ],
  "usage": {
    "input_tokens": 2343,
    "output_tokens": 91,
    "total_tokens": 2434
  }
}
```

结论：
仅在 prompt 中要求 “native 4K / 3840x2160” 不会突破底层工具限制。工具会成功调用，但实际输出被降到合法尺寸，本次为 `1536x1024`。

## 与 `/v1/images/generations` 的对比
此前实测 `/v1/images/generations + openai/gpt-image-2` 的 size 枚举为：
```text
256x256
512x512
1024x1024
1536x1024
1024x1536
1792x1024
1024x1792
auto
```

而 `/v1/responses + openai/gpt-5.4 + image_generation` 的 size 枚举为：
```text
1024x1024
1024x1536
1536x1024
auto
```

因此如果目标是尽可能大底图，`/v1/images/generations` 路径反而比 Responses 内置生图工具尺寸上限更高。

## 工程建议
1. 不要在 Responses `image_generation` 工具中传 `3840x2160`，会直接 400。
2. 横图推荐显式传：
```json
{"type": "image_generation", "size": "1536x1024"}
```
3. 竖图推荐：
```json
{"type": "image_generation", "size": "1024x1536"}
```
4. 若需要接近 4K，应采用“两段式”：
   - 先用 `/v1/images/generations` 生成 `1792x1024` 或用 Responses 生成 `1536x1024`
   - 再使用 ComfyUI / Real-ESRGAN / SD upscale / Topaz 等工具超分到 `3840x2160`

## 关键洞察
模型文本层理解“4K”不等于图像工具真实输出 4K。必须以解码后的图片宽高为准。Dedalus `/v1/responses` 的 `image_generation` 工具可用，但原生分辨率被工具 schema/provider 枚举限制，prompt 无法绕过。
