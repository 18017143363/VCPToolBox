## 项目背景
主人要求基于现有本地代理（22832→28626字节版本）打造Vercel部署版，作为社区可分发的轻量代理。

## 需求拆解
- **去掉**：402自动轮询/多key池、Claude thinking注入、流式重试机制
- **保留**：chat→responses bypass、模型后缀路由、思维链回传
- **新增**：联网功能（web_search_preview工具自动注入）
- **设计原则**：完全无状态、客户端key透传、中性技术注释（不提billing）

## 设计决策
| 项 | 选择 |
|----|------|
| Runtime | Node.js（Vercel原生，无Python依赖） |
| 路由 | POST /v1/chat/completions（单端点） |
| 模型名语法 | `gpt-5.4-search(xhigh)` 两段后缀 |
| 解析顺序 | 先剥`(effort)`再剥`-search` |
| Key策略 | 透传`Authorization` header |
| 流式 | 通过Vercel Node Function fetch + body.getReader() |
| maxDuration | 300s（Vercel Pro） |

## lib/converter.js 关键函数
1. `parseModelSuffixes(modelStr)` — 解析 `model[-search][(effort)]` 语法，返回 `{cleanModel, effort, search}`
2. `convertContentForResponses(content)` — 单条content的Chat→Responses格式转换（text→input_text, image_url对象→input_image字符串）
3. `convertMessagesForResponses(messages)` — 遍历messages应用上述转换
4. `chatRequestToResponses(body)` — 主转换函数，自动注入 reasoning.summary=auto 和 tools=[web_search_preview]
5. `responsesResultToChat(respData, model)` — 非流式响应转换，reasoning包`...`前置到content
6. `convertResponsesSseEventToChatSse(eventData, model, respId, state)` — 流式SSE事件转换，state跨事件维持think_open状态

## api/v1/chat/completions.js 入口逻辑
1. CORS preflight处理（OPTIONS返回204）
2. Method校验（仅POST）
3. 提取Authorization/x-api-key header（缺失返回401）
4. 解析JSON body
5. chatRequestToResponses 转换
6. fetch上游 `${UPSTREAM}/v1/responses`
7. 流式分支：res.flushHeaders() → 流式读取上游SSE → 逐event转换 → res.write
8. 非流式分支：read text → JSON.parse → responsesResultToChat → res.end
