# VCP向量数据库维度配置指南

## 配置位置
`config.env` 文件中的 `VECTORDB_DIMENSION` 参数

## 常见嵌入模型维度对照

| 模型 | 维度 |
|------|------|
| Qwen/Qwen3-Embedding-4B | 2560 |
| google/gemini-embedding-001 | 3072 |
| text-embedding-3-small | 1536 |
| text-embedding-3-large | 3072 |

## 维度不匹配错误

**错误信息：**
```
[Residual] Search failed at level 0: Search failed: Exception { what: "Vector length must match index dimensionality" }
```

**触发位置：**
- `ResidualPyramid.js:54` - `this.tagIndex.search()`
- `rust-vexus-lite/src/lib.rs:213-220` - Rust层维度检查

**Rust检查代码：**
```rust
if query_slice.len() != self.dimensions as usize {
    return Err(Error::from_reason(format!(
        "Search dimension mismatch: expected {}, got {}",
        self.dimensions, query_slice.len()
    )));
}
```

## 解决方案

### 方案一：重建索引（推荐）
```bash
node rebuild_vector_indexes.js
# 或
node reset_vectordb.js
```

### 方案二：手动清理
删除 `VectorStore/` 目录下所有 `.usearch` 文件，重启VCP

## 重建脚本详解

### rebuild_vector_indexes.js
**位置**: `E:\VCP\rebuild_vector_indexes.js`

**执行方式**:
```powershell
cd E:\VCP
$env:VECTORDB_DIMENSION=2560  # 必须与config.env一致！
node rebuild_vector_indexes.js
```

**执行流程**:
1. Step 1/3: 删除所有旧的 .usearch 文件
2. Step 2/3: 连接 SQLite 数据库 (knowledge_base.sqlite)
3. Step 3/3: 从数据库重建索引
   - 遍历所有日记本 → 重建各自的向量索引
   - 重建全局 Tag 索引

**⚠️ 重要**: 脚本默认维度是3072，必须通过环境变量覆盖！

### rebuild_tag_index_custom.js
**位置**: `E:\VCP\rebuild_tag_index_custom.js`
**用途**: 仅重建Tag索引（待验证）

## 注意事项
- 更换嵌入模型后必须重建索引
- VECTORDB_DIMENSION必须与WhitelistEmbeddingModel的实际输出维度严格匹配
- 索引重建会触发所有日记的重新向量化
