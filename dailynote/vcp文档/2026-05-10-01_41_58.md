## 背景
在 Dedalus 代理中，Claude thinking 经 `/v1/chat/completions` 返回时，会把可见思考混入 `message.content`：
```text
[Thinking: ...] 正文
```
主人希望将方括号格式转换为 XML 标签格式，便于前端/酒馆按标签识别：
```xml

正文
```

## 最终转换函数
```python
def convert_claude_thinking_brackets_to_xml(content: str) -> str:
    """Convert Claude visible thinking prefix from bracket format to XML-like tags."""
    if not isinstance(content, str) or not content.startswith("[Thinking:"):
        return content

    match = re.match(r"^\[Thinking:\s*(.*?)\]\s*(.*)$", content, re.S)
    if not match:
        return content

    thinking_text = match.group(1).strip()
    visible_text = match.group(2).lstrip()

    if thinking_text and visible_text:
        return f"\n{visible_text}"
    if thinking_text:
        return f""
    return visible_text
```

## 调用位置
在 Claude thinking 的 non-stream → SSE 合成分支中：
```python
content = message.get("content") or ""
content = convert_claude_thinking_brackets_to_xml(content)
```
之后再将 `content` 放入 OpenAI Chat Completions SSE chunk：
```json
{"delta": {"content": content}}
```

## 生产整理开关
新增：
```python
ENABLE_JSON_REPAIR = True
DEBUG_UPSTREAM_BODY = False
```

含义：
- `ENABLE_JSON_REPAIR=True`：保留对脏 JSON/非法反斜杠转义的兼容修复。
- `DEBUG_UPSTREAM_BODY=False`：默认关闭 `[UPSTREAM_BAD_JSON_BODY]` 的 actual_body 片段日志，避免日志泄漏 prompt 或隐私内容。

## 必须保留的 Claude thinking 承重墙
1. 非 bypass 分支使用干净 headers，避免复用前端旧 `Content-Length`：
```python
headers = {
    "Content-Type": "application/json",
    "Authorization": f"Bearer {key}",
    "x-api-key": key,
}
```
这是此前 422 JSON 截断的根因修复。

2. `max_tokens > thinking.budget_tokens` 自动补足：
```python
required_max = budget + CLAUDE_THINKING_MIN_VISIBLE_TOKENS
```

3. thinking 启用时强制 `temperature = 1`：
```python
body_json["temperature"] = 1
```

4. 前端 `stream=true` 时，上游改为 `stream=false`，代理合成 SSE：
```python
body_json["stream"] = False
body_json.pop("stream_options", None)
force_claude_nonstream_sse = True
```

## 工具使用经验
- FileOperator `ApplyDiff` 有时返回“文件编辑已经提交等待用户确认”，但实际读回未变；不能把“提交”当成“落盘”。
- PowerShellExecutor PTY 偶发不可用，可先用 `newSession=true` + `Write-Host PS_READY` 恢复。
- `python -m py_compile` 只能证明语法正确，不能证明函数逻辑符合目标；必须读回文件确认关键代码片段。
