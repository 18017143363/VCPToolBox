## 核心理念
解决插件数量增长后将所有插件描述全部注入System Prompt导致token爆炸的问题。根据用户消息内容智能选择展开哪些插件的详细描述，其他插件只显示一行简介。

## 占位符
{*2VCPDynamicTools}*2 — 在System Prompt中使用，messageProcessor.js中调用buildInjection()替换

## 三级分类系统
| 级别 | 方法 | 优先级 |
|------|------|--------|
| SmallModel | 调用小模型做JSON分类 | 最高 |
| RAG Embedding | 用RAGDiaryPlugin的embedding做余弦相似度 | 中 |
| Keyword Fallback | 基于关键词规则匹配7个预定义类别 | 兜底 |

7个预定义类别：search/file_code/image_media/memory_knowledge/agent_task/communication/data

## 注入构建流程 (buildInjection)
1. 提取可用工具列表（enabled + online + 不在excludedOriginKeys中）
2. 解析用户消息中的指令：
   - [[VCPDynamicTools:tool=xxx]] — 强制展开指定工具
   - [[VCPDynamicTools:category=xxx:all]] — 强制展开指定类别
3. 对每个工具评分（关键词匹配+分类匹配+指令强制）
4. 输出Brief list（所有工具一行简介）+ Expanded usage（得分最高的工具详细描述）

## 配置
存储在 ToolConfigs/dynamic_tool_bridge.config.json：
| 参数 | 默认值 | 说明 |
|------|--------|------|
| maxBriefListItems | 120 | Brief list最大条目数 |
| maxExpandedPlugins | 4 | 自动展开的最大插件数 |
| maxForcedCategoryPlugins | 12 | 类别强制展开最大数 |
| maxInjectionChars | 16000 | 注入总字符上限 |
| classificationDebounceMs | 1000 | 分类去抖动 |
| classifierTimeoutMs | 30000 | 分类超时 |
| useRagEmbeddings | true | 是否使用RAG embedding分类 |

SmallModel配置在 Plugin/DynamicToolBridge/config.env
