[16:19] CF Tunnel 协议切换指南 — QUIC vs HTTP/2

## 背景
cloudflared默认使用QUIC协议（UDP 443），在某些网络环境（校园网、企业网、部分运营商）下UDP流量被限速或丢包，导致QUIC连接反复超时。

## 切换方法
在 C:\Users\hpy\.cloudflared\config.yml 中添加：
```yaml
tunnel: xxx
credentials-file: xxx
protocol: http2    # ← 加这一行

ingress:
  ...
```

## 协议对比
| 特性 | QUIC | HTTP/2 |
|------|------|--------|
| 传输层 | UDP 443 | TCP 443 |
| 多路复用 | 原生支持 | 支持 |
| 连接迁移 | 支持（IP切换无感） | 不支持 |
| 校园网兼容性 | 差（UDP常被限制） | 好（TCP几乎不被限制） |
| 性能 | 略高 | 略低 |
| 建议场景 | 家庭宽带/稳定网络 | 校园网/企业网/受限网络 |

## 实测数据（2026-03-05 校园网环境 10.134.30.13）
- QUIC模式：connIndex=3反复超时4次（198.41.200.x段），2分钟才建立第4条连接
- HTTP/2模式：4条连接0.15-0.45秒内全部注册成功，零超时

## 切换回QUIC
回到家庭宽带环境后可以删掉protocol行或改为`protocol: quic`恢复高性能模式。

## 注意事项
- 修改config.yml后必须重启cloudflared才能生效
- 写入config.yml避免BOM头（PowerShell用[System.IO.File]::WriteAllText + UTF8Encoding($false)）
