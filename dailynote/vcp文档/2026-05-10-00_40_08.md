## 背景
主人要求使用测试 key 直接 curl Dedalus 官方上游，验证“包含思维链参数”的请求实际返回什么。测试绕过本地 `dedalus_proxy.py`，直接请求：
```text
POST https://api.dedaluslabs.ai/v1/chat/completions
```
使用模型：
```text
openai/gpt-5.1
```

## 测试 Key
由主人提供测试 key，本记录不完整复写 key，只记录其用途：Dedalus test key，用于直接 curl 上游验证 reasoning 参数兼容性。

## 测试 1：`reasoning_effort + prompt_mode`
请求体包含：
```json
{
  "model": "openai/gpt-5.1",
  "messages": [
    {"role": "user", "content": "Reply with exactly five words."}
  ],
  "reasoning_effort": "low",
  "prompt_mode": "reasoning",
  "max_tokens": 16,
  "stream": false
}
```

真实返回：
```http
HTTP/1.1 400 Bad Request
```

错误体核心：
```json
{
  "detail": {
    "error": {
      "message": "Unsupported fields for provider list ['openai']: prompt_mode. These fields are not supported by any provider in the model list.",
      "type": "api_error",
      "code": "unsupported_provider_field"
    }
  }
}
```

### 结论
对 `openai/gpt-5.1` 的 Dedalus `/v1/chat/completions` 请求，`prompt_mode: "reasoning"` 不被当前 openai provider adapter 支持。官方文档中出现 `prompt_mode`，但真实服务对 OpenAI provider 会拒绝该字段。

## 测试 2：仅 `reasoning_effort`
去掉 `prompt_mode`，请求体包含：
```json
{
  "model": "openai/gpt-5.1",
  "messages": [
    {"role": "user", "content": "Reply with exactly five words."}
  ],
  "reasoning_effort": "low",
  "max_tokens": 16,
  "stream": false
}
```

真实返回：
```http
HTTP/1.1 200 OK
```

响应体关键信息：
```json
{
  "model": "openai/gpt-5.1",
  "choices": [
    {
      "message": {
        "role": "assistant",
        "content": ""
      },
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "completion_tokens": 16,
    "prompt_tokens": 23,
    "total_tokens": 39,
    "completion_tokens_details": {
      "reasoning_tokens": 16
    }
  }
}
```

### 结论
`reasoning_effort` 对 `openai/gpt-5.1` 生效。证据是：
```json
"reasoning_tokens": 16
```
说明 Dedalus/OpenAI provider 实际产生了 reasoning tokens。

## 重要坑点：max_tokens 会被 reasoning token 消耗
本次 `max_tokens=16`，响应中：
```json
"completion_tokens": 16,
"reasoning_tokens": 16
```
即全部 completion token 都被内部 reasoning 消耗，导致可见输出：
```json
"content": ""
```

因此开启 reasoning 时，`max_tokens` 或 `max_completion_tokens` 必须显著提高，例如 256/512，否则模型可能只思考不输出。

## 最终可用写法
推荐：
```json
{
  "model": "openai/gpt-5.1",
  "messages": [
    {"role": "user", "content": "Analyze this bug briefly."}
  ],
  "reasoning_effort": "low",
  "max_tokens": 256,
  "stream": true
}
```

复杂任务可用：
```json
{
  "model": "openai/gpt-5.1",
  "messages": [
    {"role": "user", "content": "Deeply analyze the root cause."}
  ],
  "reasoning_effort": "medium",
  "max_tokens": 512,
  "stream": true
}
```

## 不推荐/会失败
不要对 OpenAI provider 传：
```json
"prompt_mode": "reasoning"
```
真实返回 `unsupported_provider_field`。

不要使用模型名后缀：
```text
-thinking
```
此前 `claude-opus-4-6-thinking` 已触发 `unpriced_model`。

## 对 dedalus_proxy.py 的后续建议
在 `chat_request_to_responses()` 或其他 bypass 转换中，若要支持 OpenAI reasoning，应优先透传：
```python
"reasoning_effort"
```
可考虑透传：
```python
"verbosity"
```
但默认不要透传：
```python
"prompt_mode"
```
至少对 OpenAI provider 应屏蔽或仅在显式配置允许时透传。

## 经验教训
1. 官方文档字段必须用真实 curl 校验，provider adapter 可能不支持所有 schema 字段。
2. `reasoning_tokens` 是判断 reasoning 是否实际生效的关键证据。
3. 推理 token 与可见输出共享 completion token 预算，开启 reasoning 必须增大 max_tokens。
