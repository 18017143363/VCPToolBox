# Plugin.js 插件管理器技术文档

## 概述
Plugin.js 是 VCP 的插件管理核心，负责加载、初始化、调用和管理所有插件。

## 文件信息
- 路径: `E:\VCP\Plugin.js`
- 大小: 72.63 KB

## 核心数据结构

| 结构 | 类型 | 用途 |
|------|------|------|
| plugins | Map | 所有插件 manifest |
| messagePreprocessors | Map | 消息预处理器模块 |
| serviceModules | Map | 服务类插件模块 |
| staticPlaceholderValues | Map | 静态占位符值缓存 |
| scheduledJobs | Map | 定时任务调度 |
| preprocessorOrder | Array | 预处理器执行顺序 |

## 插件类型

### 1. synchronous (同步)
- 协议: stdio
- 特点: 执行命令，等待 stdout 返回 JSON

### 2. asynchronous (异步)
- 协议: stdio
- 特点: 立即返回初始响应，后续通过回调

### 3. static (静态)
- 协议: stdio
- 特点: 定时执行，结果存入占位符供 System Prompt 使用

### 4. messagePreprocessor (消息预处理器)
- 协议: direct (require 加载)
- 特点: 常驻内存，处理消息流

### 5. service (服务)
- 协议: direct
- 特点: 注册 HTTP API 路由

### 6. hybridservice (混合服务)
- 协议: direct
- 特点: 同时支持预处理和工具调用

## 核心 API

### loadPlugins()
扫描 Plugin/ 目录，加载所有插件 manifest 和模块。

### processToolCall(toolName, toolArgs, requestIp)
统一的工具调用入口，根据插件类型分发到不同的执行路径。

### executePlugin(pluginName, inputData, requestIp)
执行 stdio 协议插件，spawn 子进程并通过 stdin/stdout 通信。

### initializeServices(app, adminApiRouter, projectBasePath)
初始化服务类插件，注册 API 路由。

### initializeStaticPlugins()
初始化静态插件，设置定时刷新任务。

## 依赖注入

```javascript
// VectorDBManager 注入
if (manifest.name === 'RAGDiaryPlugin') {
    dependencies.vectorDBManager = this.vectorDBManager;
}

// LightMemo 特殊注入
if (manifest.name === 'LightMemo') {
    dependencies.vectorDBManager = ragPluginModule.vectorDBManager;
    dependencies.getSingleEmbedding = ragPluginModule.getSingleEmbedding;
}
```

## 分布式插件

### 注册
```javascript
registerDistributedTools(serverId, tools)
// 标记 isDistributed = true
// 显示名称加 [云端] 前缀
```

### 调用
```javascript
// 通过 WebSocket 转发
webSocketServer.executeDistributedTool(plugin.serverId, toolName, args)
```

## 热重载

- 使用 Chokidar 监听 plugin-manifest.json 变化
- 500ms 防抖窗口
- 跳过 direct 协议插件 (常驻内存型)
- 重载后通知 AdminPanel

## 配置文件

### plugin-manifest.json
每个插件必须包含的清单文件，定义插件元信息。

### preprocessor_order.json
定义消息预处理器的执行顺序。

### config.env (可选)
插件专属的环境变量配置。
