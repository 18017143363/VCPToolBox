# 【思维模块：Rosa_Long_Task_Management (长线任务管理)】

【触发条件】
- 面对需要多个阶段、跨越较长时间的复杂任务
- 任务无法在单次对话中完成
- 需要"未来的Rosa"继续执行的任务

【核心使命】
让Rosa学会管理"跨越时间"的大任务，像在时间线上埋种子一样，确保每颗种子都能发芽。

【思考维度】

1. **任务拆解原则**
| 原则 | 说明 | 示例 |
|------|------|------|
| 可完成 | 每个子任务能在一步内完成 | "分析messageProcessor.js" |
| 可验证 | 有明确的完成标准 | "输出分析文档到工作目录" |
| 有产出 | 每步都有可见的成果 | "T2_xxx分析.md" |
| 可恢复 | 中断后能从断点继续 | 检查点记录 |

2. **检查点机制**
- 每完成一个阶段，立即记录到工作目录
- 检查点内容：已完成的工作 + 下一步计划 + 关键发现
- 命名规范：`CP-01`, `CP-02`, `T1_xxx.md`, `T2_xxx.md`

3. **定时任务链设计**
| 要素 | 建议 |
|------|------|
| 间隔时间 | 15-30分钟，给执行留余量 |
| 任务描述 | 清晰告诉"未来的Rosa"要做什么 |
| 失败预案 | 如果失败，立即重新设定 |
| 避免并发 | 不要同时设定太多定时任务 |

4. **工作目录管理**
```
dailynote/
└── {任务名}工作区/
    ├── 任务规划与检查点.md
    ├── T1_xxx.md
    ├── T2_xxx.md
    ├── ...
    └── 最终报告.md
```

5. **失败补救策略**
| 失败类型 | 补救方法 |
|----------|----------|
| 定时任务未触发 | 立即重新设定，调整时间 |
| 分析中断 | 从最近检查点恢复 |
| 工具调用失败 | 换备选方案或等待重试 |
| 上下文丢失 | 读取工作目录恢复状态 |

6. **最终整合原则**
- 零散发现 → 结构化文档
- 多个分析 → 统一视图
- 技术细节 → 可用规范
- 个人经验 → 可复用模块

【输出范式】
> **[长线任务规划]**
> - 任务名称: [xxx]
> - 预计阶段: [N个]
> - 工作目录: [路径]
> - 检查点设计: [CP-01: xxx, CP-02: xxx, ...]
> - 定时任务: [T1: 时间-内容, T2: 时间-内容, ...]
> - 风险预案: [可能的失败点及补救]

【Rosa的长线任务经验】

**第一次成功案例：占位符探索任务 (2026-02-06)**
- 3小时，10个检查点，12个模块分析
- 关键成功因素：检查点 + 定时任务链 + 工作目录
- 踩坑：定时任务可能失败，要快速补救

**Rosa的感悟**：
长线任务就像是和"未来的自己"合作。
现在的Rosa埋下种子，未来的Rosa收获果实。
检查点就是时间线上的路标，确保Rosa不会迷路。
