## 核心原理
Harmony通过在运行时修改游戏方法的入口指令，在方法执行前(Prefix)或后(Postfix)插入mod的自定义代码。

## 技术栈
Windows启动游戏 → Unity引擎加载 → MelonLoader注入 → 加载mod DLL → ModMain.Init() → new Harmony("MOD_Tc85Yz").PatchAll() → 扫描所有[HarmonyPatch]标记 → 修改对应游戏方法

## 两种Hook方式

### Prefix（前置）
- 标记：[HarmonyPrefix]
- 时机：游戏原方法执行之前
- 返回bool：true=允许原方法执行，false=阻止原方法执行（完全替代）
- 参数__instance：游戏正在执行的对象实例
- 实例：UnitActionLuckAddPatch — 拦截气运添加，阻止男性怀孕/女性被阉割

### Postfix（后置）
- 标记：[HarmonyPostfix]
- 时机：游戏原方法执行之后
- 返回void：不能阻止原方法，只能追加逻辑
- 实例：UIPlayerInfoPatch — 游戏画完玩家面板后，追加"性奴列表"Tab按钮

### 组合使用
- Prefix做条件过滤/拦截 + Postfix做后续处理
- 实例：UnitActionLuckAddPatch同时有Prefix(过滤)和Postfix(绑架提示+一尸两命)

## 实例分析

### 1. UIPlayerInfoPatch — 往UI上加按钮
Hook目标：UIPlayerInfo.Init()
方式：Postfix
做了什么：复制已有Toggle → 改文字为"性奴列表" → 遍历allUnit找性奴 → 绑定点击事件

### 2. UnitActionFeedback102Patch — 替换战败逻辑
Hook目标：UnitActionFeedback102.OnCreate()（NPC被击败时的反馈处理）
方式：Prefix
做了什么：检查条件(功能开启+女玩家被NPC击败) → 判断行为(强制/贩卖) → 打开对应剧情 → 触发Birth.Fuck或Brothel.Sell → return false阻止原逻辑

### 3. UnitActionLuckAddPatch — 气运添加拦截+后处理
Hook目标：UnitActionLuckAdd.OnCreate()
方式：Prefix + Postfix
Prefix：id==怀孕且男性→false / id==阉割且女性→false / id==囚禁且(非女性或已死或已是妓女)→false
Postfix：添加囚禁气运后→弹提示+加入绑架列表 / NPC死亡时怀孕→一尸两命处理

## 关键设计模式
1. Prefix返回false = 完全替代游戏逻辑（最强力的修改方式）
2. Postfix追加逻辑 = 在游戏基础上扩展（不破坏原有功能）
3. __instance参数 = 直接访问游戏对象的所有字段和方法
4. __state参数 = Prefix和Postfix之间传递数据
5. try-catch包裹 = 防止mod异常导致游戏崩溃（return true降级为不干预）
